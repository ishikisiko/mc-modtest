## Why

Choosing permanent innate fates inside the H character panel disconnects them from spiritual-root awakening and overloads a result-viewing page. The owner selected a testing-stele interaction that reveals the root first and then completes fate selection in the same independent awakening screen.

## What Changes

- Right-clicking `myvillage:spirit_testing_stele` uses the existing server awakening rules, then opens a dedicated awakening screen with the synchronized root result followed by six fate candidates and a three-choice confirmation.
- Existing roots, candidates, locks and confirmed choices survive reopening; only an empty unconfirmed pool receives an initial roll. The inheritance stele remains an independent facility.
- Gate ordinary fate roll/lock/confirm operations behind a live server-validated testing-stele interaction session, including command entry points.
- Make H → Fates a read-only result page. Keep candidate controls fixed and compact across the three supported GUI sizes and both languages.
- Update documentation, validators, evidence tooling and the release artifact; distinguish scripted evidence from the owner's visual/gameplay verdict.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `innate-fates`: relocate selection to the awakening screen, preserve legacy choices and enforce the live interaction gate.
- `cultivation-initiation-ritual`: open the root-first awakening screen from the testing stele while retaining independent inheritance and server-owned root generation.
- `cultivation-state-synchronization`: authorize awakening-screen opening through a bounded clientbound notification and retain intent-only fate requests.
- `cultivation-core-validation`: validate the stele session, independent screen, read-only H results and lifecycle/visual evidence boundaries.

## Impact

Testing-stele block routing; cultivation networking; fate runtime, service and command handlers; client awakening and H Fates UI; bilingual language resources; initiation/fate validators and tests; capture tooling; README/KB/specs. No root-generation algorithm, fate balance, save-format migration, new item/block or third-party dependency is required.
