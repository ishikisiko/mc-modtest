# 八州主城第一批交付与后续边界

日期：2026-10-29。用户已确定八州齐全、魔域也有主城，七州采用 D1 量级的地域差分，中州保留完整云山山水格局。

用户要求三个 Sol max 分工，本批不测试，今后测试由 Terra xhigh 负责。三个实现代理均已返回；父代理完成接口和展示层整理。本批不是八座城市的游戏版本，未切换生成器、未改旧世界、未打包安装。

## 已交付

- [多城基础](province-capitals-foundation.md)：八州目录、预览交换模型、有界候选/地形端口、cityId 生活绑定键、旧单城只读适配；尚未生产接入。
- [东海与灵岳样板](province-capitals-regional-preview.md)：两座真实三维布局，各有 70 个住宅外壳和代表性细化街区；NPC、碰撞、正式方块资源尚未接入。
- [中州完整白模](province-capitals-central-preview.md)：实际原作 plan 派生的 1200×1440 场景与 662 个建筑/桥占位，原高度与适配高度独立，D1 范围可对照。

这些数量来自正常交付生成统计，不是测试结果。原作最高采样地表约 427.6；适配后的建筑包络最高约 286.2。当前高度提案使飞云瀑落差从 102 缩到约 51.067，城南出水落差也明显收缩；其视觉代价必须交用户确认。

## 父代理整合内容

1. 确定 `capital_<region_id>`、几何闭包络、+X→+Z 正旋转、manifest 相对资源路径。原作旋转保留来源并转换，Three.js 使用负角度。
2. 分离目录布局族与具体方案身份。预览生成器读取共享 catalog，具体 `layout_id/layout_sha256` 与候选精确对应；中州两种高度各自保留身份，不借用另一份摘要。
3. 中州大型派生交换清单只写入忽略的预览目录，入口明确为 layout-original/adapted.json；资源相对其清单目录。blueprints 仅保留 authored 输入，profile manifest 和顶层索引不冒充 exchange 入口。
4. 两份 HTML 的显示模板使用 T3 主题变量、固定画布高度，由原生成器重新生成；没有手改生成模型或 NBT。
5. 通过 HTML 展示工具交付交互预览。首次截图处于异步载入阶段，后续中州截图已显示整城；父代理据此调低白模曝光并区分山体与建筑材质。此项仅为展示整理，不据此宣称几何、交互或外观验收通过。

## 测试状态和后续执行者

本批 tests/compile/validator/lint/Gradle/Minecraft/cloud 全部 `not_run`。没有启动 Terra 测试代理。玩家外观、手感、FPS、多人仍为 `not_verified`。阅读源码、整理数据接口及正常生成预览不计入测试通过。

后续 Terra xhigh 的第一轮应针对本批实际差异：

- Java API 编译、Python/Java exchange 一致性、八州唯一性与候选耗尽失败。
- 三套预览及两种中州高度的布局族/具体 ID/摘要组合、负坐标、四向旋转、文件路径和来源身份。
- 展示初始加载及切城、切高度、关键机位；几何包络、入口支撑与明显相交。
- 正式 worldgen/NPC 尚未实现，不能提前声明相关玩法、兼容、性能通过；实现后另定最小范围。

需要重生成预览时使用对应 owning generator。所有 out/preview 产物保持忽略，不提交；设计输入、生成源、Java 基础和本说明留在功能分支，正式资源化等待视觉方向确认。
