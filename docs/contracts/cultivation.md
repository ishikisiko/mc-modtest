## 档案、权威和生命周期

- `CultivationService` 是完整不可变 profile 的唯一替换入口；失败不半写、不发变更快照。ResourceLocation 持久化不依赖当前定义存在，不存 enum ordinal、registry 数字 ID 或解析对象。
- 当前字段与版本以 `CultivationProfile` CODEC 为准（本次基线为 v4）；保留支持的旧版本显式迁移、未知合法 ID 和已有字段。旧规范中的 v2/v3 默认、固定 stability≤100 等描述不再作为现行约束；稳定度上限取当前 stage。
- 根属性为不可变整数 basis-point map，合计精确 10000；学习进度、灵力、修为等非负值在构造/codec/替换处同样验证，运算不溢出为负。
- Attachment 的 copyOnDeath 是唯一档案拷贝机制；不另写培养档案 Clone 复制。登录/重生/跨维度只在权威状态就绪后同步；退出清客户端缓存。暂态修炼/施法计数不塞进持久化 profile。
- 时间以原始 ticks 存储：共享日历在有玩家在线时前进，个人寿命只计在线存活的生存/冒险状态。时间尺度变化重解释原始值而非重写存档；寿命批量和生命周期 flush 仍经服务提交，失败保留待写值。

## 定义、入门与交互

- realm/element/technique 使用同步 datapack registry；当前注册访问来自 RegistryAccess，不能用 id 前缀/Java 枚举猜定义。类别效果是声明，不是脚本执行器。
- 灵根按世界种子、玩家 UUID、固定 salt/version 和排序后的可选元素权重确定性生成；不依赖当前位置、系统时间、JDK 随机实现或 registry 迭代顺序，不泄露世界种子。
- 选元素无放回，整数分配精确守恒；既有灵根不因配置或生成器更新自动重抽。觉醒与基础功法传承是两个独立服务、两块石碑，各一次原子替换。
- 普通入门遵守当前定义要求；重复操作无副作用。管理员直接 setroot/learn 等诊断入口与普通仪式分开。所有 cultivation/xiulian 的英文/拼音别名结构、参数、权限和处理器等价。
- 共用注册器保持网络方向与物理 side 安全。客户端只发送有界动作、必要 ID 或服务端会话 token，绝不携带修为、成本、时长、目标境界或结果。换线格式必须调整兼容版本并检查两端 codec。

## 修炼、突破和功法

- 每玩家一个服务器暂态会话，修炼、准备、研读、突破互斥；按当前规则验证地面、状态、受伤间隔等资格。移动/攻击/使用/生命周期中断幂等，视角旋转可允许；管理性关闭不冒充玩家失误罚稳定度。
- 普通修为按灵性结算；灵石模式按 stage 定价完整支付。缺款整批不扣并降为普通修炼；提交失败归还成本，提交成功后网络发送失败不能退款或重放收益。
- 聚灵阵只在原批次还能获得额外修为时提供一份加成；一次结算最多选择一阵，逐玩家扣阵心余能。各档只接受显式允许的燃料品级；余能绑定产生它的品级，换槽不重估、耗尽才切换。旧阵 ID 与旧下品余能存档兼容。燃料预留与 CultivationService 档案提交配对，失败回滚；固本、研读、突破与满修为不扣阵能。结构及唯一阵枢归属必须加载且实时有效，无离线补算。规则来源、搭建和验证见 [KB62](../ai-kb/62_spirit_gathering_array.md)。
- 达到当前修为 cap 的这一批不同时涨稳定度；后续满修为结算才固本，固本不扣灵石。法诀熟练度是独立时钟，灵力与旧 meditation reserve 也互不替代。
- 突破从当前数据读取唯一下一阶段，结束再验证，一次意图只走一级；成功修为归零、实际稳定度向下取整减半，不再另扣兼容 cost 字段。保留其他档案字段，扩容不补满灵力、寿命上限增加不重置已耗寿命。
- 筑基后期到金丹初期由独立正式雷劫执行；普通静坐不能绕过，既有金丹不补劫。尝试身份、规则、伤害基准、余雷落点与在线时钟保存在同一玩家 NBT；重登续原劫，未知/损坏记录保留并拒绝重新起劫。主雷仅通过专用标签绕过身法，仍经护甲/抗性/护盾一次；失败与成功只结算一次，所有境界/稳定度替换经 CultivationService。管理员指令和普通 N 入口共用执行器。见[金丹雷劫](../features/tribulation.md)。
- 当前玩家链截止金丹后期；缺少 cap/transition 的终点不推算元婴。原有 stage IDs 和四个早期过渡由回归基线保护，后续数值只写 realm JSON。
- 功法、流派和传承目录由 `tools/technique_catalogue/` authored 数据生成；除明确手写基础条目外不改输出。核心切换只走 CultivationService；grade/元素倍率与损失来自 world_sim rules。
- 秘籍以 category/grade 物品加 technique/comprehension 组件区分，不每门功法注册一个物品。研读仍经会话与服务提交，提交后才更新秘籍；有效手册客户端 use 返回 consume，避免挥手中断。
- 功法成长当前仅四门样例，规则与新增秘籍配方由 `tools/technique_growth/sample.json` 及专用生成器拥有。闭关复用唯一修炼会话，完整批次扣费和增长同事务；剑气仅有效直接命中每次施放计一次。参悟方向互斥、按服务端版本拒绝过期请求，未主修心法不叠加收益。旧法只沿显式关系提供一个最佳学习帮助，传承承接只在真实学成时执行；境界、亲和、秘籍和研读门槛不被加速绕过。档案新增可选参悟字段保持旧熟练度，超过当前上限不回写截断。见 [KB69](../ai-kb/69_technique_growth_sample.md)。
- 灵力花费原子、恢复服务器计时且有上限，无离线收益。剑气通过已学功法和武器族验证，充能/释放/取消只发空意图；服务器负责方向、耗费、碰撞、去重命中和伤害，视觉不能越墙替代命中。

## H 面板与天命

- H 是 hub + PanelPage，系统页通过 PanelContext 读取缓存/同步定义，使用共享主题；每页交互走 page hooks，不把专用逻辑塞进 hub。四个修炼动作只在 MeditationPage 绑定一次。
- H 字体必须保持测宽、换行和绘制一致，且不替换全局字体；功法图标与品阶色分别由客户端资源声明，六个明确绝技覆盖图案，其余按同步大类共用。分类、图标和选中状态不赋予客户端学习、主修或施放权限。
- 经脉图只显示服务器已同步的会话/进度，不捏造穴位数量；批次绘制自持 buffer。只修改某页/语言时检查受影响页面，不能把全尺寸截图变成所有改动的默认义务。
- 分境界水墨内景同样只读服务器状态；静态底形和流动层分开绘制，收功停止动画时钟。完整 registry ID 只选择表现，不能据样式推算进阶规则；预留元婴图层不等于开放元婴玩法。原画由 `tools/cultivation_ink/source/` 经专用发布器生成。
- 四门功法活卷使用 `tools/technique_scroll/` authored 原画与体积配置，经 `tools/gen_technique_scroll_assets.py` 导出；原画与预览不进入 jar。动效只观察服务器状态，首次打开／切换／隐藏不得补发增长或参悟反馈，装饰行气不能伪称批次倒计时。
- 天命为独立不可变持久化状态，服务替换并 copyOnDeath；六选三、一个锁、点数预算与互斥由服务器验证，无额外高品数量上限。已确认不可普通重置。
- 普通天命变更需要真实测灵碑建立的存活、同维度、近距离 session 与新鲜 token/revision；旧 close token 不关掉新会话。H 只读结果；重开觉醒页不重抽已有候选。管理员显式目标诊断不等于普通流程证据。
- 实现的天命进入普通池；快速开发占位例外须明确标记且 effects 为空，其余未实现设计留在 catalogue；救急/击杀恢复由服务与持久化冷却约束，死亡不刷新冷却。

## 技艺、丹炉与丹药

- 炼丹/炼器/制符资质独立、一次初始化，使用独立确定性来源，不消耗灵根 RNG；旧已觉醒存档仅补缺失值，制符缺省不能重抽前两项。炼器生产见下方炼器雏形约束。
- 制符案只有真实近距菜单所有者能续发有界注灵心跳；每个已接受脉冲才付灵力，首次付费冻结符式/所有者/资质/品质并消费原料。松手、关界面、卸载和断线暂停，不补离线产量；已付批次保存，成符仅一次，满输出不继续扣费。引雷/镇步/护身符消费与效果由服务器提交，复用公共命中、控制及护盾，不能同源无限叠加。数值/资产由专属制符生成器拥有，见[制符](../features/talismans.md)。
- 资质限制同一配方成品品质，不是黄玄地天配方品阶；原单方块丹炉每炉手动开始，服务器检查有效近距菜单、觉醒与材料、空输出，冻结炼制者 UUID/资质/上限/结果。
- 丹方学入玩家持久知识，死亡保留；原单方块丹炉同步各自已学列表，服务器复查知识后选择并从本人背包补齐一炉。换方退料与补料先完整规划再一次提交，空间不足不改库存。保留原五槽存档索引与旧丹方取回槽，追加第 5 槽作为第三药材槽；旧双药配方次序可交换；活动输入锁定，产物与扣料一次完成；堵输出暂停不耗材不重抽，损坏旧批次保留物品待重开，完成不自动连炉。区块卸载不暗中计时生产。
- 独立多方块丹炉阵由已学丹方且已觉醒的玩家在有效近距菜单明确授权连续生产；保存操作者、丹方和当时资质上限，每批单独冻结结果，不要求操作者持续在线。停止只禁止续批，拆坏／未加载／堵口暂停原批次；修复不重抽。控制器唯一持有库存和批次，专口仅暴露限定方向和槽位的能力，模拟无副作用，每次调用复查结构与唯一归属；控制器拆除只掉落现存物品。结构与界面蓝图同源，旧单炉语义及 registry ID 保留。
- 下中上极品组件有界持久化/同步；旧无组件及新下品保持旧堆叠身份和强度。高品质默认改变强度；野外丹药可在配置中明确采用持续时间品质倍率（清瘴丹），此时清毒强度不变。共享间隔、资格与中断规则不变；持续药效保存原品质，读取上限由该品质的实际时长决定。
- 筑基丹只接受配置指定的源阶段，普通突破不能绕过服丹；尝试接受时消耗并冻结结果，完成再验证。失败不增根基或掉境界，稳定度损失取 foundation rules。补基丹只单调补全，不重复叠加，无最高境界限制；所有根基档案替换仍只经 CultivationService。
- `foundation_quality` 是 v4 可选有界字段，旧档缺省零，不凭空补发属性。根基提升基础生命、攻击及灵力容量，稳定标识替换且不直接治疗；既有伤害减免仍仅一次。新丹限定合法品级，原三丹四品与旧堆叠保持兼容。
- 回灵不超容量、养元受伤中断、凝神仅影响满修为固本；拒绝使用不耗物品，不叠加活动效果。所有修炼数值变更仍走 CultivationService。

## 炼器与锻造工坊

- 炼器数值、配方、消耗、可用专长与品质权重唯一来源为 `data/myvillage/forging/rules.json`；资质品质上限仍由 crafting rules 决定。器谱使用后独立持久保存，copyOnDeath，服务器是知识唯一写入者。
- 炼器台采用玩家私有临时菜单，无共享方块库存；实体锻器台一次供一人占用，方块实体只同步台面表现，不额外持有或持久化物品；关闭、死亡或断线由原版容器返还/掉落暂存物品。交互复查菜单本人、存活、旁观者状态、距离与方块，客户端只发送有界按钮编号。
- 当前入口使用阶段锻造：起坯、加热锻打、淬火、回火、精磨、装柄，再一次性炼灵；入门工具不要求觉醒，炼灵仍受资质上限约束。旧即时菜单仅保留注册兼容，不再由方块打开。
- 淬火消耗同层正交邻格水槽中的水，注水时返桶；水槽在工序期间独占，完成须复查原槽仍存在且有水。水保存于方块状态，操作占用与展示器坯不持久化；取消不耗水，展示不能另行掉落或复制物品。
- `forging/workshop.json` 是工序时间、火候、历练门槛、逐锤材料与成长收益的唯一来源。服务器在接触 tick 提交每锤事务；不按客户端时间戳结算，不设每锤评分，重复请求不能跳过动作间隔。
- `workpiece` 保存阶段及已完成锻打，`temper` 保存物品历练及各方向已付锻数；改名、交易、维修和重启不重置。热度和未付操作只属于当前菜单，关闭返还器物并取消未付操作。每件物品的累计可锻上限不得通过切换方向绕过。
- 每次提交前在副本规划完整扣料并构造结果，缺料、阶段或火候不符、历练不足、达到上限、输出占用均不扣费；品质仅在首次炼灵时由资质上限确定，后续锻炼不得重抽。
- 原有武器 registry ID 与动作保持兼容；有界持久 `forge_mark` 记录稳定专长 ID 和品质。锋锐使用唯一主手属性修饰，坚韧写入原版最大耐久，导灵在服务器剑气扣费前应用一次，正成本向下取整且至少为一；不重复处理伤害减免。
- 维修只接受配置支持的受损兵器或工具，复制整个物品后只减损伤，不重抽品质、不清除附魔或命名。资源由 `tools/gen_forging_assets.py` 生成；武器模型继续归属原有专用生成器。

实现及限制：[炼器](../ai-kb/54_forging.md)。

- 炼器鼎保留 `forging_table` registry ID；四向/亮炉状态是表现，完成事务后才发光与粒子，拒绝请求不点火。熄灭由原版计划方块 tick 处理，形体碰撞与模型同源，配色和反馈参数在 `tools/forging/ding.json`；不因外观加入生产队列或共享库存。

- 专长辅材由炼器 rules 引用真实注册物品，名称和用途由 `tools/forging/materials.json` 维护；该生成器不再产出材料获取配方，并检查已退役配方和配方书入口不存在。玄铁锭/赤铜锭/淬锋砂为普通材料，炼制扣除仍由原有服务器事务完成；不在客户端按材质名猜专长，也不改变旧武器的已存属性。

- 赤铜灌灵只由服务器从当前菜单所属玩家扣灵力；有界进度组件保存每锭已付灵力，拆分/合并不能放大投入。关闭临时菜单必须按原版规则返还或掉落材料，不能留隐形离线任务。批量和耗灵以 `forging/acquisition.json` 为唯一来源。

- 炼器成本兼容具体物品 ID 和 `#物品标签`；库存分配必须同时满足所有要求，重叠标签不能重复计数或因贪心次序误拒绝可行组合。仅在完整分配成功后提交扣料。灌灵的插槽、快捷移动与服务器脉冲使用同一通用铜锭标签判断，重载移除资格不清除已付进度。

- 剑痴剑势为服务器在线暂态：注册 sword 族普通剑招每招至多叠一层，同招所有目标使用起手层数增伤；满层终段接受命中至多派生一道剑气。换武器、死亡、离线、跨维度清空，超时由定义 ticks 判定。派生波不占动作会话、不付费/返还、不扣额外耐久、不叠层或触发进攻天命/附魔后效，不能反向给百炼战骨充能。
