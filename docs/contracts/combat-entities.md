## 战斗权威与数据

- move/weapon/skill 文件由 `data/myvillage/combat/index.json` 索引，双方读同一资源。所有 timing、命中采样、位移、反应、反馈和镜头数值在数据中，不在 Java 复制。
- 多段高级武技单独读取 `combat/advanced_arts.json`，由 `tools/advanced_arts/arts.json` 和 `gen_advanced_arts.py` 生成。复用旧动作片段但不追加基础连招；技能书仍是原有功法定义，冷却按玩家与武技 ID 计时。
- 高级武技 C2S 仅一字节槽位 0/1，客户端外部动作标记阻止基础连招预测；格挡只保护首段前摇正面，范围命中沿用友军/PvP/视线/伤害管线。
- 两个攻击 C2S 为空；闪避仅一字节八向意图，剑气充能/释放/取消也为空。时间、命中、伤害、连段、取消、位移、冷却和无敌窗口均属服务器。
- 武器条目通过 style/family 选择行为；combat 包不得硬编码物品或妖兽名称。CombatWeaponItem 保留原版 re-equip 规则但去除耐久变化触发的重复装备动画。
- move 满足 active/buffer/chain/total 的时序约束；样本按 tick 非递减排序，多样本活动帧数量一致，绘制轨迹的远端达到武器 tip radius。仅 presentation 的 trail.samples 不参与服务器命中。
- 服务器 step 决定冲量和计划命中原点，客户端物理执行；击停、轨迹、声音、镜头和手臂是展示，不能改写结果。抗硬直通过通用 StaggerResistant 钩子，不按实体类分支。
- PAL 精确根依赖与 client-only 边界保留；客户端战斗计时仅 ClientCombatClock。已有青锋/枪/拳回归基线不可被无意 retune，故意调值同步对应数据和基线。
- 多部位实体以真实 `PartEntity` 做命中几何与原版 `hurt` 路由，不能把父级大包围盒当作受伤部位；按实际接触距离排序后，以父实体身份去重、计容量和活动段命中账簿。权限、血量回执和境界伤害 trace 使用父实体，实际伤害仍提交给命中的部位。
- 末影龙受伤必须经过原版部位与 phase 路径，保留头／非头系数、阶段易伤、死亡阶段拒伤与玩家来源归属；不冻结或强制击退龙父体。剑气沿用其已声明伤害来源，不能因外观像投射物就伪造箭矢免疫。

- 武器流派资源读取 `combat/disciplines.json`：普通剑招实际伤害每动作至多一次剑意；护体只认同源同 tick 正伤害收据；消费在成功扣费之后冻结整次施放倍率。派生命中不能积累或触发枪锋奖励，枪锋使用目标真实碰撞表面距离并复用原抗硬直管线。暂态资源随精确武器／槽位、模式和玩家生命周期清理，不与天命剑痴的剑势混用。

- 主动战斗栏由服务器向本人同步固定八个状态位：六个可分配键位加右键波技能和 Alt 身法；空白额外槽位不绘制。H 绑定仅接受已学且有实际执行器的技能，或已确认且定义有效的天命所授予的主动能力，角色 CombatPreference 保存六槽并兼容旧存档默认。施放包只提交槽位和有界方向，服务器从存档解析技能并重查资格，共用原有动作、费用和冷却。接收端核对实体、维度和手持物，客户端仅插值展示。

## 模型和动画

- 武器模型/纹理/图标/geometry 由各自生成器拥有；PAL 动画由 `gen_sword_pal_anims.py` 的独立 pose tables 生成，不手写输出。
- 几何格式 2 使用 butt/handle/collar/head/head_base/head_tip 和 axes.length；拒绝格式 1 兼容回退。抓握由契约和撤销 baked display 变换计算，不在 Java 写武器偏移。
- 两手武器有 off_hand_grip_center 与 rig.off_hand；空副手槽才展示辅助手。free off-hand 不握武器，paired 装备按通用配置镜像，不按物品 ID 判断。worn 表用 fist_key，保持拳套贴手。
- 动画长度/活动窗口/strike 覆盖与服务端数据一致；双手上杆关键帧校验握点、身体穿插与地面净距。改第一人称解算/rig/几何时更新 Java/Python parity golden。
- 客户端资源缺失或非法时可回退原版持握，不能污染其他武器。视觉姿态 probe 不发送动作包，不是实战输入证据。

## 妖兽和 NPC

- 妖兽属性、追击和每个招式数值在 beast JSON/index 中；contract 只引用字段，不复制调参数字。起手资格、锁定朝向、突进、去重命中、冷却均服务器决定。
- beastgen/npcgen 是模型、动画、贴图的唯一作者。招式长度与服务端 ticks 同步；正在招式中的一步位置更新与 clip delay 必须成对修改。公共 entity 代码不导入客户端类。
- NPC 完全相同的模型／动画由 npcgen 的打包步骤共享；authoring 输出及 golden 不变。旧运行时资源路径保留单跳引用，必须还原为原内容；不改 Look、骨骼、贴图、关键帧或资源包的逐外观覆盖语义。
- 持剑 NPC 的 AI 只提交基础攻击意图，共用 CombatSession 的时间轴、命中、伤害与装备损耗；Mob 来源不得伪装为玩家。纯击停暂停动作，硬直清除动作与缓存；NPC 命中跟随实际服务器身体，不能沿玩家计划终点造成隔空伤害。
- 化身战斗快照仅同步位置、装备、冷却时不得擦除命簿已有致伤者；生命值、最大生命值或攻击回执发生变化时才更新该归属，不能凭首次近场记录的空攻击者重写人物历史。
- NPC 攻击动画与握点仍由 npcgen 从共用姿态输入适配；客户端原子动作快照覆盖中途追踪，旧实体展示状态不得复用。
- NPC 基础 body 不自行决定敌友；宗门对话、化身等由明确后续 runtime 提供。不要把早期“无交互”条款覆盖到现有命簿化身功能上。
- 友善修士主手交谈统一经 `NpcDialogue`，事务按命簿事实组合并经原服务授权；普通弟子的宗门话题不授予执事或长老权限。普通召唤/蛋生修士暂作无关系散修，保存出生闲逛锚点，不因此登记命簿或社会关系。通用页面会话必须绑定实际实体、玩家、维度和租约，逐次复查距离/视线/战斗与已提供选项，见 KB56。
- NPC 服装用真实分层几何和逐像素体积/阴影/褶皱；shell cutout 的 alpha 为 0/255，避免共面。可选 model.scale 统一作用于模型和步态。
- 一个 look 对应 npcgen 定义、生成资源、contract looks、Java LOOKS；可由显式 variant_catalog 与同一 factory 展开，目录和产物必须一致，不按字符串前缀猜测变体。共享骨架/碰撞不变，只可增骨。实体身份、属性、渲染、语言、蛋、掉落和自然生成的真实支持范围须一致。
- 修士自动选款只使用生成目录中的保留组合及其族权重；命簿按永久身份稳定选款，不因境界回退旧模型。旧 Look 仅作存档与显式指定兼容，普通新生选款和磁盘加载必须区分，已选款实体不得在重进或跨维度时重抽。
- 自然生成同时需要数据注入和 Java placement predicate；召唤、蛋生与自然出生的状态不能混为一谈。化身不存档，由命簿投射和撤回，不套用普通 NPC 所有生命周期假设。
- 首领洞府使用显式 `structure_anchor` 路线并核对 native 结构链，不添加环境随机刷怪的 biome modifier／placement。锚点以持久 UUID 占位；卸载不视为死亡，只有明确死亡回执进入终态，防止重复首领。
- 多部位首领的断角只接收露角窗口内真实头部／角部位的玩家归属伤害；身体命中不推进断角。断角与作者配置的固定遭遇境界身份保存，搬迁或重载不重抽，伤害减免沿用共享管线一次；暂态攻击与窗口在重载安全取消。

## 乘骑飞剑

- 每玩家至多一把 owner-bound 暂态飞剑；真实源物品完整暂存到玩家回执，落地或生命周期清理仅归还一次。创建失败不留绑定、不扣费；旧实体不能归还新绑定的物品。
- 网络仅传前后左右升降/催剑位及空落地意图；服务器从当前 vehicle 推导身份，检查 owner/passenger/维度/存活，决定位置速度朝向。斜向归一化，碰撞覆盖乘客头部；不得主动加载飞行前方区块。
- 资格、速度、灵力和阶段规则来自飞剑配置；骑剑暂停自然回灵，丹药保持原规则。低灵禁催剑，耗尽只保留有界低速修正并持续下降，不能凭输入或重登恢复巡航。渡劫与起飞互斥。
- 高空召回先缓降再移除。实体不保存，玩家保存待落地标记；重登恢复只下降的临时载具或有时限的安全兜底。死亡、换维度和普通落地清理标记，不保留永久免摔属性。
- 两档三维模型/配方由 `gen_flying_swords.py` 拥有，表现参数由 `tools/flying_sword/visuals.json` 生成。服务器同步档次，客户端插值、站姿和尾迹只作展示，不恢复客户端载具坐标权威。

- 派生剑气由服务器创建，独立记录每波的有界目标去重和飞行位置；沿用扫掠碰撞与合法目标/PvP/墙体规则。客户端实例键区分主动动作与派生波 ID，派生消息不改主动充能姿态或连招 revision。

- 太白剑脉锁定绝技从 `combat/locked_sword_arts.json` 读取，灵力成本由原功法 catalogue 唯一拥有；其无默认槽的 `slot=-1` 只能经已保存绑定施放。共用 CombatSessionManager 的时间轴与伤害管线，服务器一次取得目标、逐段重查视线/范围/权限，不中途换目标、不穿墙。身法无敌逐段全免，余势仅对锁定绝技缩放完整出伤一次，不改旧近战/剑气；破甲为不叠层的暂态修饰，生命周期必须清理。

- 五行法修经既有 CombatSessionManager/CombatArtActions 调度，不检查武器家族但保留手持变更中断。元素伤害使用独立施法基础与明确类型，不借用近战武器攻击/附魔；五系对应抗性与穿透，原版减免一次。积蓄每个常用技每次有效施放至多一次；护体全系共享冷却，持续伤害有施法者归属及数量上限，不递归触发攻击天命。详见[五行法修](../features/elemental-arts.md)。

- 太白范围冲击先保留主目标，再按真实实体归属去重并限制总人数；次级伤害比例来自锁定武技配置。主目标失效不改锁其他目标；所有冲击目标保留墙体、友军、PvP 与身法校验，主目标不能同时收到完整伤害与次级伤害。

- 普通野外人形可声明 `ordinary_entity` 自然出生路线，但不占用命簿人物身份；持剑意图仍走公共战斗执行器。扩展妖兽的投射／区域伤害必须有轨迹遮挡、目标上限与寿命，原版减免一次。模型作者保留 beastgen／npcgen 分工，见 [野外敌人](../features/wilderness-roster.md)。

- 天命基础能力复用六槽意图和服务器资格校验；费用／冷却提交前完成执行器准备。控制按来源与期限清理，根缠约束服务器认可的水平移动并拒绝主动闪避／脚步。治疗与护盾不另开伤害减免路径，吸血只认一次实际主伤害回执；领域限实例、目标和粒子，不强加载区块。定义、持久冷却与生命周期见[天命基础能力](../features/fate-foundations.md)。
