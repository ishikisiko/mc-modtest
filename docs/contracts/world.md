## 宗门身份与供奉

- 宗门等级在成立时保存，分宗、总舵、主宗的生成与任职境界由 `world_sim/rules.json` 配置。新建、继位和衰退判定读取同一等级，不根据称号文字推断等级。
- 玩家与NPC月供奉读取自然历法月份，余额、最后结算月份和考核目标由命簿持有；预演、重复查询、重登和重启不重发。领取先核对余额与整份背包计划，实际放入多少才扣多少。
- 分宗玩家长老晋升保留筑基资格并要求专属对手的真实战斗胜利回执。客户端只提交申请意图；命簿绑定尝试和目标，失效旧对手不得取消新尝试。

## 宗门贡献与江湖声望

- 贡献、声望、已接任务的冻结奖励和各城接取日期由原 `PlayerMember` 及命簿保存，只经 `WorldSim` 门面修改。宗务基础贡献沿用 `sect_tasks.json`；额外贡献、灵石和江湖任务奖励范围由 `player_economy.json` 维护，接取后不再重抽。
- 任务交付、经书领取和琳琅阁购买先完成整笔背包计划，再复核任务、身份及余额并提交；提交失败不扣余额、不清任务、不记借阅。声望是购买门槛，满足后仍检查原报价、灵石及库存，交易不扣声望；出售商品不套用购买声望门槛。
- 琳琅阁坐标与连通性归原宗门蓝图生成器；主城江湖榜由作者坐标合入正式城市切片与既有生活场所，聚落榜随原旋转在当前生成区块施工。运行时只绑定真实已加载设施，不新造人物、不回填被拆设施、不为手放方块赋归属。菜单校验设施、玩家、一次性序号、维度、距离、视线和资格。具体入口见[功能说明](../features/sect-merit-jianghu-reputation.md)。

## 区域图与宗门世界生成

- 区域配置与拓扑规则只在 `data/myvillage/worldgen/` 的 JSON 中维护；Python/Java 生成须同 seed 同结果，覆盖并列等级与 walled 区域的 parity 样本。
- 当前修仙大陆的州序以 `blueprints/worldplan/rules_v11.json` 的 `region_progression.order` 为唯一来源，覆盖全部地区、阶位严格递增并以中心 anchor 结束。非中心州按此顺序排列在共用半径的环带上，种子决定整体旋转、角度扰动和地形；每对连续州必须共享真实边界并开放通路，官道必须逐段覆盖。
- 州阶位读取地区 profile 的 tier，中心 anchor 使用规则的 tierMax；地区妖兽境界仍使用原地区数表。魔域沿固定州序设置进入与离开关隘，其余边界封闭，宗门自然生成仍排除魔域。离线拓扑工具的随机图规则保持独立。
- 运行时区域层是被动查询和一次性出生点绑定；不因此接管地形或生物群系。出生点选最低阶可接纳区域并做有界安全表面搜索；region_at 的最近中心近似和有界范围要明确。
- 当前大陆的 `next_rung_regions` 按固定州序返回下一州，包括魔域，顶阶返回空集合；离线随机图的等级并列仍返回集合。
- 宗门几何、山体、入口、经架和活动区以 `blueprints/sects/` 为唯一 authored 来源；预览与正式资源共用最终施工分块。已确认设计由 owning exporter 生成当前清单、整数高度场和稀疏 NBT，Java 不再另写台地或单体尺寸表。
- 蓝图锚点对应实际山门入口。低于世界底界的站点整体抬升，超出世界高度或边界的站点拒绝建造；山体边缘按声明宽度衔接确定性的天然高度。门槛改动须显式声明，组件与支承保持连续。
- 世界生成、命令和分帧建造消费同一份清单和分块；自然生成仅写当前 chunk、不 force-load 邻区。运行时核对资源 SHA、palette、坐标和实体容量；可选模组缺失继续经原 fallback 处理，不用空气吞掉构件。
- 命簿宗门的经架全部在声明坐标成功绑定后，才提交建造收据与 gateRealized。收据保存布局身份和资源摘要；化身与经架只接受当前蓝图身份，格式随当前开发版维护，不实现旧台地格式迁移。

## 遗迹状态

- 丹霞旧观使用原生 jigsaw 分块放置与旋转；模板入口和自然生成使用同一资源。旧区块不回填，不为遗迹强制加载邻区。
- 残阵是整座遗迹共享的服务器状态；确认绑定玩家与选项，提交先于奖励写入，正常保存/重启不补充次数。目标块被改动或未加载时拒绝交互，不覆盖玩家建设。
- 遗迹妖兽以明确结构出生标记一次性赋境界并初始化满血，重载不重抽、不回血；不伪装为地区自然出生或命簿人物。

- 战斗遗迹的阶段和箱内奖励由服务器宝箱 BlockEntity 拥有；已绑定守卫 UUID 的真实死亡才计为击败。未加载或和平移除不算击杀；死亡回执允许箱体未加载时保存，和平恢复只补未击败槽位。
- 战斗宝箱在通关前无奖励库存，通关后同一存档对象一次性提交状态与物品；共享次数和已取走物品正常重启不刷新。箱体不可生存挖掘、爆炸破坏或活塞移动，不开放漏斗访问。

## 命簿权威

- 天骄身份、筑基/金丹品质和当前灵力属于人物档案，容量由共享数表派生；化身只读取和提交有界消耗。小阶段、刷新或重启不重抽身份与品质，不补满灵力。NPC 元婴仅使用已确认的最低档数表，不因此开放玩家元婴。
- 命簿是世界模拟唯一权威；化身和宗门建筑是投影，通过 `WorldSim` facade 回写。纯 `sim/**` 不依赖游戏类型、时钟或随机源；随机均由 seed/day/subject/固定 purpose code 派生，不能重排 purpose 编号。
- 药业职业复用同一生活活动与执行租约，采集、种植、炼丹技艺分别持久保存，解除岗位不刷新经验或财物。分类药材与旧未分类库存分开核算，不能把旧库存变成任意指定灵草；`herbalist` 只交易，丹药仅由合资格炼丹师消费完整配方后生产。账本药圃按生活时钟成熟；显式绑定的实地药圃只接受当前化身在已加载真实地块上的成功回执，以真实作物和掉落为准，离场不走抽象生产。位置唯一、玩家改动不覆盖、重复到站/回执/换身/重启不重复发产出，见 [KB68](../ai-kb/68_npc_herbal_professions.md)。
- 药铺收购、转售的丹药按物品与品质共同记账；玩家交易不检查或修改 NPC 生活公库，玩家买入仍须付足灵石。报价、数量、品质匹配和整笔背包替换由服务器决定，客户端只提交原有会话绑定的报价索引和数量。药材外部进货保存在同一命簿的门店商品库，与职业原料库分别核算；补货只补到配置目标，下次到货时间持久保存，重启、回拨日历和重复查询不能重领同一批货。营业日光与补货日历独立，改日光不补货。
- 数值在 `data/myvillage/world_sim/`，年率按调用方 days_per_year 换算；存档版本变更显式迁移，新增文本在双语资源注册。
- 近场化身共同领取命簿执行权，真实损耗与死亡只接受当前 epoch；删除、卸载与死亡必须区分。生命、装备与必要恢复状态及时回写，投射不刷新；真实死亡一次记录并复用关系和席位后果。玩家用 ActorRef/UUID 归因，不伪造 NPC ID。
- 战斗切换结算生活时钟并挂起收益；重启与脱战要求重新到达设施。尚未结束的坠落或燃烧按真实身体状态恢复，不能用生活安全点免除后果。
- 化身仅由 `WorldSimAvatars` 投射，不随 chunk 存档；人物身份唯一，有全局/局部上限和 loaded-chunk 边界。玩家不是命簿 Person，不混入 NPC members。
- 命簿人物的五行、兵器与技艺资质为独立点数，按人物身份保存；化身读取同一记录，授业读取老师当前资质。生成、日常培养及后台修改保持命簿权威，详见[资质点数](../features/aptitude-points.md)。
- NPC 出生天赋只生成一次；预算取 fates/npc_rules.json，天骄恰好用满，普通人物低于上限。命簿保存词条、当时预算与花费，化身只读投影；普通实体自行保存同一记录。新增已启用词条从当前 registry 自动入池，抽取仍验证灵根、互斥与成本。分配结果和实际效果支持分别记录，见 [KB48](../ai-kb/48_innate_fates.md)。
- 玩家入宗、离宗、晋升、资质变更、任务、借阅、战争和灭宗走各自 facade API。交谈/经架输入只携带意图与必要定位，服务器复查距离、维度、身份、门派与权限。
- 宗门在世界规划中冻结完整预留地和具体蓝图，在本区块生成阶段施工；GateRealizer 仅观察已加载内容并绑定命簿归属，不能临时补建。经架实体由蓝图生成，ScriptureShelves 只绑定既有完整上下半部；借阅记录与经架下格 Sect 根一致，不给匿名手放经架自动赋门派。
- 客户端天下页只读有上限的查询快照，保持节流；不建立第二份客户端命簿。新视图扩展已有查询/section，而非另加任意数据通道。

## 境界伤害与野外投影

- 玩家 stage aliases 来自 `stats/rules.json`，凡人至金丹的属性加值和品质贡献只来自 `stats/progression.json`；服务器属性修饰符 ID 稳定且刷新幂等，不叠乘、不借刷新回血；加载时最大生命先于原版 Health 恢复。
- 原版护甲与附魔各执行一次，额外分类抗性也只执行一次。肉身防御先于招式/暴击倍率结算，原版护甲压力不再按境界额外归一化；实际护甲输入与输出仍以同一伤害容器记录。
- 原版上限、bypass、护甲损耗、盾、无敌帧增量和吸收次序不改。诊断绑定实际 damage-container 身份，区分请求伤害、护甲入口、后续减伤和真实失血。
- 物理穿透保留旧 registry id 且只用于物理通道；五元素各读自己的属性，不能复制/叠加旧物理值。非生物攻击者穿透为零；未接入的元素攻击不能因属性注册成功就宣称可玩。
- 自然妖兽的出生境界只分配一次并存档，移动/重启不重抽；旧召唤/蛋生无分配个体保留基线。区域外或其他维度不捏造高阶默认遭遇。
- 普通原版怪物的新出生个体保留洲域与结构、维度合并范围的上限，下限由 `wilderness/vanilla_monsters.json` 的 `minimum_realm` 单独声明，允许无境界；新增怪物的地区 beast 范围最低为炼气一层。原版实体排除项、出生原因和非属性伤害来源由同一原版配置声明。先记录出生，再在原版初始化完成后赋属性；旧存档无分配个体不补抽。转化/分裂继承出生记录，近战不二次缩放，箭矢/爆炸等声明来源在原版减伤前仅加入一次对应的境界攻击贡献。
- 原版敌对怪物的群系生成权重系数只由 `neoforge/biome_modifier/scale_vanilla_monsters.json` 提供，在 `MODIFY` 阶段按命名空间和 MONSTER 类别筛选。新增怪物、动物、组大小、生成成本及怪物容量不随之缩放；已有个体、刷怪笼和事件生成不作为群系抽签的替代调整入口。
- 原版探索的地点、结构、显式场景、下界和末地普通怪物范围只由 `exploration/rules.json` 声明。主世界结构与洲域按境界端点取较高范围后一次采样，不叠乘；下界／末地使用独立范围。查询只读已可用区块与结构 start，不为提示申请区块票。四类特殊首领保留普通怪物排除项，经独立配置与运行时接入，不能复用普通出生抽样。
- 四类特殊首领的 profile、有效属性和伤害通道倍率／上限仅由 `exploration/bosses.json` 声明。首次接入保留当前生命比例并持久保存归属与永久修饰符；既有或异常归属不重分配，重载不重抽、不回血。旧无归属首领的一次接入与旧普通怪物不补抽策略明确分开。
- 首领伤害只接受精确原生来源和直接／间接 owner，保留同一伤害容器及原版阶段、护盾、音爆绕甲和减伤次序；不得将无归属魔法、持续凋零或环境伤害按附近首领放大，也不重复放大属性近战。
- 指定有限箱子／宝库奖励只在原版战利品展开时追加，原生保存状态拥有次数；不另建可重复领奖、实体刷怪或宝库内部子表的第二次追加。
- 可选 `portal_gates` 默认关闭，仅服务器根据玩家真实境界在原版下界门／末地门处理目的地前拒绝进入。返回主世界、同维度、末地折跃门、模组门、命令传送与非玩家不套用该限制；不得变成传走后回弹或全局维度旅行拦截。
- 城镇向导为命簿人物的生活职业。出生省城通过 `WorldSim` 一次性预留四个普通服务岗位，其余城镇从已有本地人物安排；持久岗位和化身共用原有权威，死亡或离岗不自动造替身。交谈读取当前玩家真实进度，不收客户端完成声明、不写第二份玩家境界。
- 首城试种与阡镇章节分别保存个人进度，修炼状态仍只读写真实修炼档案。材料先做完整背包计划，再与一次性接受回执一同提交；本人种植须经未取消事件、tick 末真实作物和土壤以及同 tick 后续变动校验，不用持有物品或他人的作物冒认劳动。
- 野外散修只投射本地区既有、存活、无宗门且符合范围的人物，不能另造身份；共享化身去重和容量边界。

## 第一章单人秘境

- 第一章默认按玩家 UUID 使用独立持久维度；人物、古阵和场景状态按该秘境隔离。仍由 WorldSim facade 管理人物，不能用全服固定剧情键共享四名角色。
- 归属和返回点在传送前持久化；登录恢复、传送、观战、维度旅行和剧情输入校验同一主人。模板维度拒绝玩家进入。退出、死亡、重登不重置章节和领奖回执。
- 新 V7 主世界不再放置第一章建筑，V1–V6 与旧显式场景保留。不得清空旧任务或回删已经生成的建筑。中断场景不自动重放覆盖。
- 首次无章节且无归属的玩家自动进入新秘境；行迹界面只提交进入/离开意图，仍由服务器核对归属和安全返回。旧记录不因升级自动重进或重置。
- 普通天下页按查询玩家过滤其他秘境的人物、关系与事件；猜测人物 ID 不能绕过过滤，隐藏人物不占据可见搜索上限。秘境坐标不解释为主世界地区、不计入地区巡察。

## 剧情人物与个人章节

- 剧情角色绑定是命簿的持久身份关系，初始化、岗位迁移和共享救援只经 WorldSim facade；已死亡或缺失的绑定不能因重进自动补造替身。身体仍由 WorldSimAvatars 唯一投射，迁移先撤回旧执行者，再提交同一人物的新位置。
- 明确标记的剧情保护角色跳过普通后台成长、寿元和迁移，并在伤害入口处理保护；不在身体已死之后拒绝死亡回写。保护不得扩散到普通居民、宗门人物或野外散修。
- 个人章节与奖励收据独立保存，死亡复制由所属 Attachment 的 copyOnDeath 完成。共享人物返回和阵法处置不能自动完成其他玩家的章节；后加入者必须有可达的确认路径。
- 对话意图绑定本次会话、实际身体与租约、玩家进度版本和可用选项；服务器重查存活、维度、距离和视线。调查只接受真实右键的精确目标及合法方块状态。奖励先规划容量，满包保留待领，正常保存后的重复交付不再发放。
- 学徒任务只有接受、领苗、领奖可由对话选择；教学与本人播种事实由服务器核验并自动推进，客户端不能提交完成事实。播种以真实事件及 tick 末最终状态为证，同一格重复与他人操作不计数。
- 当前目标标记仅使用本人服务器快照，跨维度、无目标、完成或隐藏时不显示；标记不代替交互距离、视线或会话授权。
- 新场景保存实际冻结布局；已知旧场景按对应历史快照回读，不能用当前模板覆盖旧建筑或假定旧世界已有新设施。
- 显式剧情场景部署保存实际维度、原点、资源版本与完成状态；重复部署不覆盖已有场景，不隐式迁移冻结世界计划或改变玩家出生。生产模板和交互坐标均由 authored 输入生成。

入口：[区域](../ai-kb/13_region_topology.md)、[世界生成](../ai-kb/07_neoforge_worldgen.md)、[命簿](../ai-kb/40_world_sim.md)、[入宗](../ai-kb/43_player_sect_entry.md)、[境界与野外](../ai-kb/47_realm_stats_wilderness.md)。


## 新建世界默认预设

- 当前 V11/v4 七府城市经正式 `manor_relayout` 构造和 `blueprint_plan/runtime.py` 导出，主城 manifest 是区块、入口、舆图及 NPC 岗位的统一来源；中州沿用现有布局。只生成当前区块，不为完整组件增加跨区块写入。下方 V8/V9 的旧资源保留段仅记录历史实现，当前开发包不维护旧档兼容。
- 仅新建入口默认选中 `myvillage:cultivation`，同时更新 UI 选择与实际世界维度设置；不得只改标签。
- 不在界面重绘、换页或数据包重载时重设用户选择，不影响“重建”及已有 `level.dat`。
- 专用服务器仅补充缺省/空白 `level-type`，显式预设和旧世界生成器保留。生成器缺失时客户端保留原默认值并记录诊断。


## 八城官道路网

- 初始城排除名单只由当前世界规则的 `spawn.excluded_regions` 提供；东海保留城市与道路，不作为新世界初始城。城郊矿场在完整官道路网就绪后选址，必须在初始城附近的同州陆地，避开全部既有城镇、宗门和官道。其位置、旋转及完整支路保存到生成器，绑定世界、道路和蓝图摘要；每次只写当前生成区块，不能重进回填已开采方块。树木和矿石须保持原版材料的采掘与掉落，地下由世界种子和原版洞穴雕刻算法生成，必须保证实际洞体体积、入口短通道及落脚面的连通，不以提高出现概率或放置固定洞室模板替代。地面整形在洞穴雕刻前完成；普通矿脉只避让精确通道和设施保护范围。实现与检查见[开局矿场与各州天然矿口](../features/starter-mine.md)。
- 各州普通矿口只搜索已有天然洞体，不调用开局洞穴雕刻器，不额外补矿石。候选必须具备地下覆盖、连续干燥落脚点、足够空间和无流体的连接通道，禁止把露天地面或断开的空气块计作洞体。数量、间距、搜索预算均从矿场作者配置读取；不足时保留实际数量与原因。选址及勘探坐标随生成器保存，读取时核对身份，区块完成后不得重放入口施工。地下连接段的侧壁、顶板与地板共同形成连续封水边界，保护范围必须包含衬砌的实际三维体积，并覆盖跨区块接缝。
- 开局矿场和各州矿口的人工连接段共用作者配置的双侧火把规则。火把须依附真实岩壁、随矿口旋转并保持中线净空；完成区块不因重进补回已拆除的火把。
- 初始食物由服务器登录事件逐人发放，数量以服务器配置为准；领取回执持久保存并经 `copyOnDeath` 保留，重连、重启、死亡和换维度不能重复领取。实现说明见 [KB71](../ai-kb/71_capital_opening.md)。

- 青石护栏仅放在已有外侧石缘的临崖、临水和高路基危险段，判定与几何由 `config/roads/guardrail.json` 经道路生成器提供。不得侵入中央完整通行面、城内只读通道或借护栏扩大施工权限。护栏状态包含支撑高差与连接，纳入存档及逐列审计，不能将护栏列计为可步行宽度。

- 当前默认自动规划八座省城的连通主干网；魔域经唯一正式关隘接入，禁止从关隘外跨越隔绝州界。地形和精确州属由 WorldPlan 提供，不从取整后的图坐标推断边界。搜索域可沿端点城域外缘有界绕行，不能因此扩大任何列的写入权限。跨接坡点的寻路共享一份总预算、路径前缀与可达标高，不得用回头重叠路径虚增坡长。
- 完整路幅拟合发现高度冲突时，保留冲突列及上下限来源，并在配置次数内避开冲突路径位置重新寻路。城门、关隘和支路端点仍是必经点；绕行、分段和备选过境点共享该路线的展开预算。只有完整路幅、坡度、土方与保护区检查全部通过，才可把路线加入全网；预算耗尽或必经出口不可行时保留具体失败原因。
- 路线中的普通过境点和城外接坡点只要求经过对应位置，不能把采样得到的天然地表高度当成已经建成的只读地坪。只有真实出口和已有道路具有固定标高；其余路面继续在原有土方范围内逐列求解。默认世界生成必须检查实际新世界创建，编译和少量固定种子通过不能代替这项检查。
- 每座省城的公共接坡必须独立规划并通过完整路幅校验，官道共用同一接坡和外端标高，不得因相邻城市或规划顺序改变接坡。新主路仅能在接坡外端接入，不能在陡坡中途搭接形成更短的高差路径。接坡、主路与宗门支路使用同一地表及标高区间采样实现；一条官道的两端接坡展开数、改道数计入该路线原有总预算，复用接坡不能重置预算。
- 生成器在种子绑定阶段完成全网计算与校验，再进入区块生成；规划失败不得先写入部分区块，也不得用空路网或缺路布局继续建档。
- `terrain_relative` 陆地省城的自然落位基面不得低于配置海平面，不能把海底实心表面当作城市所在的自然地表。平面选址、地块范围、authored 地形和局部标高保持各自原有输入，海面相对和绝对标高城市继续按其声明计算。
- 出口由 `config/roads/prototype.json` 绑定正式蓝图的 `public_passages` 与当前城市资源，只读通道经 `tools/gen_road_ports.py` 生成；支持四向出口。城内地坪、台阶和净空只读；写入不得进入任何城市本体。真实出生点及城体保持保护，出生点方框不得误封已经声明的城外公共接坡出口。预留边缘只开放配置限定的所选城门外接坡范围，不放宽全局保护。水上桥面与桥墩分别受配置深度和间距约束，低于水位的门外石缘须挡水。
- 城外路幅与现有门洞净宽分别声明、逐格检查。南疆实际门洞 3 格、西漠 5 格；城外 5 格通过不能表述为全程 5 格。元数据范围不是已清空的物理门洞证明。
- 共享路口按完整通行面并集生成石缘和护栏。规划线程不访问区块；完整路网按区块压缩，与世界、道路规则及布局摘要一并存入生成器 codec，重启不得重新移动已规划道路。规划缓存须保留全部省城连通和中央五格路幅，不能接受半张网或裁掉主路。
- 官道仅写当前生成中的 ProtoChunk，在洞穴雕刻后、装饰前放置，并在装饰结束时重申本区块。不得使用 ServerLevel 普通邻居更新清场，不得回填已生成区块、跨区块写入、禁用正常掉落或删除物品实体。生成保护覆盖实际基础和净空高度，矿脉直接写入也要受保护；结构按部件三维边界避让，完全低于路基的结构不因水平重合被排除。
- 状态与管理员检查在服务器线程运行；预生成命令显式加载缺失区块并读回完整路幅，已生成区块只读。失败保留具体坐标，未加载项、原生读回、行走、外观、FPS 和玩家接受度分别汇报。实现说明见[城际驿道](../features/intercity-roads.md)。

- 正式主城资源与 preview manifest 分开；heightfield 为 top-solid Y，WorldPlan 继续返回 first-air Y。中州绝对高度原点为0，不能再次整体上移。
- 每次只放当前区块的稀疏结构，山基地形逐列生成；资源摘要、输入预算和旧版本断言不以缺城/缺模板为由放宽。查询不隐式加载整城。
- 旧 V1–V7 资源、规则和存档不迁移；V8 生活容量由该世界冻结配置提供，不全局改旧命簿规则。所有持久人物、岗位与库存仍经 WorldSim facade 修改。
- 正常资源生成和源码接入不代表原生、旧档、多人或玩家验收。交付边界见 [八州主城接入](../province-capitals-game-integration.md)。

## 宗门世界生成

- 宗门完整蓝图、山体过渡与结构缓冲在 `WorldPlan` 中按种子预留，其他结构和主干道路必须提前避让；宗门支路只允许通过冻结山门外的有限走廊，不能进入内部。必需地块不足时拒绝整个规划，不临时降低要求。
- 新世界宗门候选地必须避开双方完整结构缓冲，并为山门走廊外侧保留以同一 `structure_buffer` 为尺度的转向空间。后选地块也要避开已有山门的转向空间；该选址检查不增加道路在任何地块内的写权限。
- 命簿只认领同地区未占用的预留地块，不能任意迁移。区块 FEATURES 阶段只写当前生成区块，探索顺序不影响结果；靠近、绑定、重启不能触发建筑重放。
- 经架随蓝图生成。运行时只能在已加载区块绑定既有完整经架及山门归属，不补块、不修复玩家破坏、不强制加载远处建筑。
- 蓝图及高度场摘要必须与冻结世界规则一致；地块尺寸、数量、高度和缓冲以 `blueprints/sects/catalog.json` 的共用 `worldgen` 和各布局尺寸为唯一来源。
- 建筑形制与功能分区由 `blueprints/sects/architecture_profiles.json` 声明，经已有屋顶注册表和建筑 pass 生成。单体沿用原占地，整地只覆盖实际基础，不能把未覆盖的院地削成沟槽；楼层、床铺及设施操作位置须接通蓝图入口。
