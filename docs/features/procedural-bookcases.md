# 千机阁书册按位置生成

0.131.2 起，总舵的23组书架继续保留原有木框、层板和攀取梯。书册不再逐本导出盒体、可见面和独立模型，生成器只记录连续的排列区域、朝向和整排底部。

世界生成照常把共享构件放入新区块。客户端为区块建立模型时，依据书架横向位置和整排底部计算稳定的排列种子，生成书册四边形并缓存。重新进入世界、资源重载和不同玩家观察同一位置时，排列保持一致。书册沿用原有青、朱、素三份像素贴图。

书册排列的宽度、高度、间隙、种子范围和缓存上限由 `blueprints/qianji/bookcases.json` 维护，生成到 `data/myvillage/qianji/components/bookcases.json`。`ProceduralBooks` 与 `tools/qianji/bookcases.py` 使用同一整数算法，Java 检查读取 Python 生成的固定样本核对。每个烘焙模型最多保留配置指定数量的排列缓存；当前上限为4，不按世界中的每个位置永久保存一份模型。

区块使用普通静态模型渲染，没有新增书架方块实体、显示实体、网络消息或逐帧渲染器。资源重载会创建新的烘焙模型和缓存，贴图继续参与正常材质图集。木框和相邻透明窗的渲染层仍沿用原实现。

服务器使用相同算法计算书册选框，保留书脊间隙。书册继续不提供行走碰撞；原有木构碰撞和构件发光等级保持不变。跨上下两格的书册部分共用整排底部计算种子，深度方向的切片也使用同一横向位置，保证颜色和高度衔接。

生成器归属仍为 `tools/qianji/generate_assets.py`。正式城市重导出同步更新构件编号和切片摘要；对已有构建输出进行局部更新时，必须核对楼体尺寸、房间、功能点、地形、非千机阁方块及方块实体。改变这些条件的输入仍需由中州 owning 导出器完整重建。这里的局部更新只操作当前开发构建资源，不承担玩家旧存档迁移。

开发者的离线形状比对、编译及运行检查分别记录。玩家近景外观、行走手感和实际硬件性能需要单独观察。

本次减量、固定源码、定向检查及原生运行证据见[0.131.2 检查记录](../testing/2026-11-14-procedural-bookcases.md)。
