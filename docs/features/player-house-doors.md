# 住宅木格双开大门

0.135.1将用户确认的门体设计注册为`yuanxian:courtyard_double_door`，三套独立住宅共替换10处原版小门：小院2处、合院5处、工坊宅3处。原版月洞水院继续使用原有月洞门。

[住宅三维与蓝图下载](https://assets.ishiki333hhh.win/previews/player-house-doors-20261117/index.html)提供“主屋大门”机位和“打开双开门”开关，使用游戏资源中的闭合及全开模型。住宅蓝图可下载为NBT或SCHEM，尚未接入城镇生成或游戏选房菜单。

## 游戏使用

- 创造栏“月洞水院 · 建筑构件”新增“木格双开大门”，也可用`/give @s yuanxian:courtyard_double_door`获取。当前没有生存合成配方。
- 一件门占用5×5×3格，正面门框厚1格，门后两格用于门扇开启；需给整个范围留空。正面净开口宽3格、高4格，石门槛高1/8格。
- 放置一次消耗一个物品。右键可见的门框或门扇，双扇一起切换为闭合或向内全开90°，模型、碰撞和开门声音一起更新。关闭后的门扇若与实体重叠，本次操作失败，整门保持原状态。
- 生存拆除任意部位，整门移除，只掉落一件；创造拆除无掉落。中键取任意部位可取得整门。开合状态、朝向及含水状态随普通方块状态保存。
- 游戏采用闭合、全开两个状态；独立设计页的连续开度用于检查回转空间。红石、NPC自动开门和门锁未接入。

## 作者输入与运行时

`blueprints/player_homes/door_study.json`与`tools/player_homes/door_model.py`拥有已确认的门框、双扇、铜环和转轴几何。`tools/reference_courtyard/assemblies.json`声明独立构件族、`behavior:double_door`及摆放尺寸；生成器由该字段选择`CourtyardDoorBlock`，逐格输出闭合/全开模型及`open_parts`碰撞。

`CourtyardDoorBlock`在服务器检查75个部位的归属、朝向、开合一致性、已加载区块、世界边界、交互权限和目标碰撞，再批量更新状态；中途写入失败则恢复已经写入的部位。放置与根格掉落复用原有整件构件事务。单款门省略方块`variant`属性，物品保留既有构件选择协议中的款式0。

`tools/player_homes/model.py`从住宅配置读取门的构件族与款式，保留完整开合空间和门槛站位；离线动线按全开碰撞计算。新门与窗、梁柱和屋顶的完整构件不会共用占位。原版月洞水院的10,437个非空气格保持原样。

## 检查边界

针对性检查涵盖六项Python回归、院门模型/碰撞生成一致性、共享语言资源、庭院Java状态/碰撞/选择测试，以及独立服务器中的四套NBT逐格回读、四向受阻放置/一次消耗/右键联动/实体阻挡/整件拆除和开门状态重启。运行证据随配套交付清单提供，未执行的项目保持原状态。

离线截图与服务器命令夹具用于开发者检查。玩家操作手感、原生客户端外观、声音体验、FPS、SCHEM导入工具及多人体验尚未验收。本轮不修改玩家已有世界。
