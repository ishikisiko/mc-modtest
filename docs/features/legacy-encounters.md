# 四组遗迹传承（0.116.2）

四门新功法均需炼气四层，通过已有秘籍研读学会，在 H 的技能页分配键位，按 R 进入修炼战斗模式。它们使用同一战斗会话、输入校验、灵力事务和冷却。持续存在的飞剑、残影、火种与镇岳尺由原战斗管理器推进；投影不是另一份物品，换手、死亡、离线、跨维度或离开战斗模式会清理。

| 妖物 | 功法与器物 | 生存获取 |
|---|---|---|
| 游剑妖 | 回锋御剑诀、归燕剑；放出整柄剑，再次按键召回，回程沿当时的玩家位置改变路线，离手期间不能近战 | 新生成的剑痕碑遗迹；击败绑定守护者后用纸拓印，古剑灵核用于制剑 |
| 照影妖 | 分影步、照水镜；闪身留下残影，可返回安全落点；镜面短时截取一枚迎面箭矢或小火球，随后释放水属性灵光 | 沼泽、红树林沼泽或河岸；水显绢卷在水中右键得到秘籍，也可制镜 |
| 吞火蟾 | 伏火诀、赤玉葫芦；放置有限火种，潜行按键主动引爆；葫芦收取实际喷吐留下的余焰，保存有限次数的火焰攻击 | 恶地、疏林恶地、热带草原；余焰丹砂配书与墨囊制秘籍，也可制葫芦 |
| 守碑石灵 | 镇岳诀、镇岳尺；立尺后区域迟滞和周期震击，再按键收回；立尺期间不能近战 | 新生成的镇岳碑遗迹；触动石碑开始试炼，击败绑定守护者后用纸拓印 |

照影妖观察到玩家实际出招后，记录当时的位置，等待配置的延迟再向该位置回击；未观察到出招时使用普通近身攻击。它不复制其他功法的完整执行器。分影步的残影采用施法者皮肤，不穿墙，返回时重新检查路径与落点，也不额外赋予无敌。伏火与镇岳尺不修改世界地形。原版投射物的截取属于照水镜自身功能，不改变其他法术的碰撞规则。

两座石碑以持久 UUID 占位，实体卸载或暂时不可见不会生成替代者；只有绑定实体的死亡才解锁拓印。拓本为共享的一次性奖励，领取标记先提交，再扣纸、给物品。自然出生境界沿用地区范围与持久出生记录；已有存档区块不会补建新遗迹。

作者数据是 `tools/legacy_encounters/catalogue.json`，`python3 -m tools.gen_legacy_encounters` 生成数据、配方、器物模型、中文说明及两座原生遗迹。该入口已加入 `generate_all_structures.py`，因此清理后会重新生成遗迹。妖物几何、动画和原生像素细节由 `tools/beastgen/legacy.py` 拥有；内置 imagegen 的材质候选按 UV 二值遮罩回贴，最终小尺寸五官和发光区域仍由确定性像素规则控制。

轻量检查是生成器 `--check` 和 `tools.tests.test_legacy_encounters`。定向 Java 检查覆盖 `LegacyRulesTest`、原高级武技、锁定剑诀、五行法术和妖兽数据。原生采集入口为 `python3 -m tools.legacy_encounters.evidence --out <新目录>`，命令只准备夹具、读回与控制时间，研读、技能分配、施放、使用器物和试炼攻击由映射键鼠触发。实际完成场景与失败以对应报告为准，开发者截图不能代替玩家外观、手感、音效、FPS 和长期平衡验收。

`python3 -m tools.legacy_encounters.natural --out <新目录>` 在 Colab 创建另一份普通新世界，定位两座遗迹、保存区块并读取真实 StructureStart 与石碑 NBT；该检查不使用模板放置命令。客户端采集的重启场景检查已学功法、绑定、器物存量、妖物蓄火与已领取的石碑状态，暂态飞剑不会恢复。

管理员可执行 `/function myvillage:legacy_encounters_kit` 获取器物、零进度秘籍和刷怪蛋，不会直接学会功法或改变境界。`/myvillage legacy status <玩家>` 只读当前投影与器物储存状态。HTML 从当前模型和动画生成可旋转预览，另列原生画面和文件身份。

0.116.1 扩大了妖物的实际几何和注册碰撞尺寸。吞火蟾通过独立腹部骨骼表现蓄火，喷吐从作者数据中的嘴部位置开始，并从该位置复核遮挡；石灵采用宽厚肩背与明显的蓄力、下压动作。武器模型和握持几何继续由同一 shape 输入生成，立地后的镇岳尺按完整展开尺寸检查可用空间。

连续剑光、残影、火浪、镜面与地面震纹由客户端绘制，位置、范围、阶段和寿命来自服务器创建的非持久投影。特效实体不执行伤害、消耗、掉落或状态结算。每名使用者、可见特效、轨迹样本和地面采样均设上限；退出世界时清理客户端缓存。新表现参数统一归 `catalogue.json` 的 `visual`，正式伤害范围仍归现有功法和妖物数据。

体型和特效的定向实机入口为 `python3 -m tools.legacy_encounters.visual_evidence --out <新目录>`。它读回真实注册尺寸，检查原有试炼场的生成空间、立尺低顶拒绝、特效换手清理和重启；两名客户端另行采集同镜头人物比例与真实时间视频。视频不使用时间步进，也不作为玩家手感、音效或性能结论。

0.116.2 的石灵和镇岳尺表面由 `tools/legacy_encounters/stone_models.py` 定义连续截面。石灵的 `surface_mesh` 绑定现有骨骼；模型文件中的盒体仅保留为骨骼与步态计算边界，绘制时由三角形表面替代。每个面带独立 UV，实际法线由顶点计算。原有方块妖物继续走原渲染路径。石灵的躯干下压使用动画约定的负 Y 位移，避免与根骨骼上的双腿分离。

镇岳尺通过既有 `tools/equipment/mesh.py` 导出 NeoForge OBJ，材质、握柄和尺首仍来自同一份作者数据。`tools/legacy_encounters/stone_materials.py` 负责实际游戏贴图，内置 imagegen 只提供固定 UV 内的材质底色；碑文、眼部、刻纹及透明区域在本地确定性回贴。这里没有接入网页预览的法线、金属度或粗糙度着色，也不需要外部光影包。

本次外观检查使用 `tools.tests.test_stone_models`、`BeastSurfaceMeshTest` 和受影响的原有资源检查；实机入口为 `python3 -m tools.legacy_encounters.stone_evidence --out <新目录>`。静态图与管理员触发动作仅用于模型审阅，镇岳尺的施放和收回使用映射键鼠。外观审美、手感、音效及实际设备性能仍由玩家确认。
