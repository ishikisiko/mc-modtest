# 山寨清剿与兽巢讨伐的关卡模型

状态：两张完整场景的作者模型；0.131.0起接入[游戏远征](combat-quest-runtime.md)。本页说明离线模型与预览，主世界兽群聚集地留待后续。

模型包含地形、建筑内部、连续通路、掩体、交战场地、敌人站位参照和撤离位置。敌人形体用于检查尺度，实际实体模型、AI、命中与奖励不由本预览实现。原先的[六关设计](quest-realms-gameplay.md)与[书院复玩候选](quest-realms-candidates.md)继续保留。

## 山寨清剿

作者输入为[bandit_stronghold.json](../../blueprints/quest_realms/bandit_stronghold.json)，范围192×208格。

- 外寨位于14格标高，内院位于20格，主厅台地位于26格；入口标高12格。宽阶与西坡侧路连接各台地。
- 木石门楼、完整栅墙、西门楼、营房、粮仓、灶房、修械棚、主厅和后寨物资屋共同组成连续山寨。
- 房屋保留地基、地板、木墙、门洞、窗格、梁架、双坡屋顶与前檐廊。营房有床铺，仓库有货架与粮袋，灶房有灶台与烟囱，修械棚有工具和兵器架。
- 四处必需战斗预留在门后、粮车场、内院和寨主主厅。粮车、矮墙、箱堆和侧廊提供实际遮挡与侧向接近路线。
- 主厅中央保留宽阔交战面，陈设集中于两边。击败目标后使用后寨出口，东壁栈道仍能回到内院。

当前动作阶段按钮只展示守敌位置消失后的场景，不执行战斗或阻止玩家通行。地图主要流程没有必需机关谜题。

## 兽巢讨伐

作者输入为[beast_den.json](../../blueprints/quest_realms/beast_den.json)，范围208×208格。

- 从林缘进入天然洞口，依次到达狼群厅、双向岔口、岩柱守兽厅与首领巢厅。东侧赤甲蜥岩厅构成可选支路，与采光泉台回环到主路。
- 洞室按不规则轮廓雕出，洞顶高度随距洞壁的位置变化，洞道使用宽窄交替的拱顶。山体、岩壁和地表属于同一套体积。
- 主路从18格标高缓降至14格，所有必需路线可步行；岩柱与石块置于通路侧面，首领巢厅保留约52×38格交战面。
- 采用天然石、安山岩、凝灰岩、深板岩、苔藓和兽骨材质；浅泉、根系、巢床与旧猎人遗物补充不同岩厅的用途。
- 采光泉台有贯通地表的开口；其余洞室保留实际岩顶，首领巢厅出口就近布置。

全景默认移除覆盖山体与洞顶，以建筑剖视检查洞室关系；玩家视角会恢复完整山体和岩顶。剖视隐藏地表树木，避免把悬空的树误作模型构造。

## 作者与工具归属

- 地图坐标、建筑用途、洞室、通路、敌群、观察镜头和光线参数只在两份作者JSON维护。
- [combat.py](../../tools/quest_realms/combat.py)注册两类场景与木石建筑、寨墙、岩柱、兽窝等构件。场景使用显式注册表分派。
- [预览工具](../../tools/quest_realms/README.md)按同一份场景生成可旋转地图、本地离线数据、路线图与渲染图，不写入正式游戏资源。
- 新增天然材质从已有的Minecraft 1.21.1客户端jar读取；包内记录每张材质的SHA-256，不修改原始图片。原有材质继续来自项目资源。
- 相邻面只在相同可见性层内消除，隐藏岩顶后保留下层完整截面。

## 检查与交付边界

模型检查包括路线图连通、关键点站立体积、连续通路支撑与头部空间、固定镜头位置、屋顶切换、战斗展示阶段和页面宽度。新增回归用中途阻墙与缺地面夹具确认检查确实能发现问题。

这些检查针对离线几何。Minecraft方块导出、原生碰撞、敌人寻路、实际走位与战斗、多人、帧率、任务和实例生命周期仍待正式实现。外观接受由用户查看模型后决定。

预览发布到约定的HTTPS资源域名，复用已有服务。渲染图、检查记录和下载包放在忽略的`reports/`，不提交生成输出、不升mod版本、不构建JAR。
