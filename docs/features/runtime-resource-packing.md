# 当前资源的共享几何与无损打包

从0.131.3起，构建在各拥有者完成导出后，统一整理当前资源。建筑布局、注册方块、形状编号、碰撞、遮挡和光照继续消费原有输入；模型和结构保留原逻辑路径，运行时通过内置资源包读取。

## 实际覆盖范围

- 七座城主府和千机阁总舵的全部精细构件模型，以及关联的方块状态、物品模型和掉落表。
- `assets/yuanxian/models/` 中其余JSON、OBJ和MTL，包含装备、炼器阶段和普通物品模型。
- 当前全部结构NBT，包含正式省城、城主府、宗门、阡镇和自然结构。
- 全部PNG的无损压缩检查，以及最终JAR的ZIP整理。字体沿用此前暂缓调整的决定，原字节和字形范围保持不变。

37,280个构件模型实例引用30,987份共享几何，其中1,747份模板跨建筑使用，涉及5,286个模型实例。该统计包含注册组的填充状态槽。原有模型路径、状态数量和游戏中的放置数量保持原含义；共享模板数用于衡量几何定义的复用。绘制面数按原模型保留，FPS尚未实测。

## 生成归属与数据

拥有者继续输出完整模型、结构和目录。`processResources` 完成复制后，调用 `tools/runtime_resources/pack.py`，只转换当前构建输出，不回写作者输入或拥有者的生成资源。

构件模型的坐标、元素顺序、面方向、剔除面、AO、渲染层和复合模型顺序组成共享模板；材质绑定、面UV及程序书册区域作为实例参数保存。模板和参数恢复原JSON字面量，生成时逐条检查与拥有者输出的原始字节一致。恢复继续使用Minecraft和NeoForge原有的模型解析、烘焙、透明面包装及物品覆盖规则。

其它模型、关联JSON及结构NBT按原始字节分组；NBT自身的GZIP编码和摘要不改写。物理包位于JAR根目录的 `yuanxian_packed/`，由当前清单指向逻辑资源。只打包这一份表示，不再同时携带展开副本，不为历史资源编号添加别名。

所有分组、解压及缓存限制来自 `tools/runtime_resources/packing.json`，并随构建输出为 `rules.json`。读取器核对命名空间、规范路径、重复记录、整数索引、资源大小及分组和恢复内容的SHA-256。每个资源包实例的缓存同时受解压字节预算和分组数量约束，关闭资源包时清空；新一轮资源重载建立新的实例。

## 游戏读取与覆盖

`SharedResourcePack` 为客户端资源和服务端数据各注册一个自动启用的隐藏内置包，优先级位于用户资源包之下。按原路径覆盖单个模型和贴图继续有效，纹理仍参与原有图集与重载流程。服务端类只使用公共资源接口。

Minecraft的结构管理器、城市放置和原有模型加载均从 `ResourceManager` 读取。确需读取内置固定数据的 `CapitalGameBundle` 与 `SectBlueprint` 使用 `BuiltinResources`，保留调用方已有的摘要检查和覆盖含义。开发工具的 `DirectoryResources` 可读取拥有者目录及已打包构建目录，`CitySource` 继续核对当前城市模板摘要。

## PNG与ZIP

PNG只重新压缩IDAT，不改尺寸、像素、过滤后的扫描行或其它chunk。颜色配置、透明度和动画元数据保留；无法获益的文件保持原样。

最终JAR使用配置中的压缩等级，按实际文件大小和条目数写入ZIP64。分组GZIP的外层ZIP采用实际更小的存储方式。归档重写前后核对完整条目集和每个条目的解压内容，清单、服务声明与资源原始字节保持一致。
