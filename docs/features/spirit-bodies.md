# 金刚灵体与凤凰灵体

两项天命从确认后完整生效，继续属于互斥的 `spirit_body`。H → 先天查看结果与实时状态；没有新增技能按钮或独立觉醒树。

## 属性与配置

天命定义 `metal_spirit_body.json` / `phoenix_body.json` 拥有属性倍率；`fates/spirit_bodies.json` 拥有容量、增长、温养、凝聚、位移、粒子预算和识别表。不得在 Java、客户端或采集器另设生产默认数值。

新灵体的生命与防御贡献取 `CultivationStats.base(profile)`，包含角色初始、境界与筑基/金丹品质，不包含装备、功法、其他天命和临时状态。贡献以稳定 ADD_VALUE 修饰替换；已有百分比修饰的计算系数会被抵消，保证新贡献不会再次被这些修饰放大。刷新不治疗，原版护甲与韧性继续独立结算。

## 金刚适应

真实敌方主攻击的实际损血形成分类适应，护盾、吸收、闪避与格挡部分不增长。精确伤害容器在 Post 冻结损血，当前一击先使用旧适应；同次自定义招式的所有多段共用增长限额。灵兽招式携带执行序号，延迟飞弹保留该序号；同一所有者在同 tick 发射的投射物按一轮处理。持续、衍生、自伤、友军与普通环境伤害不训练；正式劫雷按每次有效命中训练。

斩击、穿刺、冲击、一般物理、五行与雷击分别记录；实体与招式识别从显式表读取。分类只影响适应，不改变公共抗性通道。各类共享容量，满额时增长会按占比挤出其他类别。有效攻防刷新战斗期限，超过期限按在线时钟逐步衰减；死亡、退出与换维度清空。

每类适应提供的额外肉身防御加入本次共享 BodyDefense 输入，再让敌方肉身穿防正常作用；不增加独立百分比减伤，不重复计算护甲、抗性或衍生主击防御。

## 凤凰火种与自愈

`FateState.phoenix` 保存初始化标记和火种储备，所有替换经过 CultivationService。首次确认初始化一次；死亡清空储备但保留初始化标记，重登、重启、管理员清空再选均不重新赠送。

火种只按真实在线 tick 恢复。附近已加载且没有阻隔的普通火、熔岩和点燃营火可加快温养，多个不叠加，自建火源有效。自愈只使用涅槃保留线以上储备，经过共享治疗修正一次；凤凰受疗倍率乘在可接受的治疗上，不能绕过完全禁疗，仍遵守共享治疗上限。满血、完全阻止治疗或零实得不扣火种，少量缺血按实际修复比例扣除。普通雨水和游泳不扣储备。

凤凰普通环境火免疫不覆盖有敌方归属的火法。火伤增益遵守原有直接/衍生伤害的单次归属规则。

## 余烬与正常死亡

原版图腾先处理；其救命失败且火种足够时，凤凰才消耗当前全部储备并进入余烬。旧致命一击不把溢出伤害再打到余烬；虚空与管理绕过伤害不触发。原有雷劫致命前散去仍判失败，不消耗凤凰火种，也不转为通过。

余烬保留真实玩家实体和敌对关系，以单独的耐久与凝聚时钟继续经过正常防御链承伤。短暂攻击保护结束后可被击破；受击不延长凝聚。初始储备高于门槛时增加余烬耐久。持续浸水按耐久上限消耗，雨水不造成这项损失；普通治疗和用药不能修复余烬。

玩家仅保留视角与有限慢速移动。移动包先走原版线程和非法坐标检查，再受每 tick、全程位移和原生碰撞约束；临时移动属性补偿原版爬行输入，客户端与服务器每 tick 都停止水平惯性，并归一斜向输入，避免重复减速或斜向加速。凝聚结束时同步最终位置，不能积累普通步速的偏差。不能跳起、攻击、施法、用物、修改背包、丢物、骑乘或传送。旧燃烧、中毒、凋零停止，成功后清理；外部领域仍可再次作用。

凝聚成功按固定比例重塑生命，不乘受疗、不补灵力；失败才调用正常玩家死亡、掉落和击杀结算。火种保持耗尽，需重新温养。

普通断线后，PlayerList 完成原生退出清理，再保留同一个短时玩家实体；不保留在线连接、技能权限或第二份背包。余烬结算后经原生 PlayerList 保存，并撤出临时实体。重登前先保存并撤出旧实体，避免同 UUID 双实体。

正常停机时，`myvillage_phoenix_embers` 保存剩余时钟、耐久、归属与完整玩家快照，重启续接，不补算停机时间。余烬仅使用短时区块票，完成、转交或停机时释放，不修改既有强加载票。

玩家击杀归属同时保存原生剩余期限。重启后攻击者仍离线时，只建立不入场的归属对象；只保存击杀统计与进度，不写该对象的背包或玩家文件。玩家快照的 UUID 必须与余烬所有者一致，损坏记录直接报错。

## 同步与检查范围

协议 62：只有所有者收到适应、储备、耐久和凝聚进度；旁观者仅收到带实体 UUID 的余烬形态。客户端不提交火种、伤害、凝聚或复生数值。显示使用现有字体与有界原版火焰粒子，没有新增艺术资源。

纯逻辑与资源检查、原生伤害/图腾/余烬/死亡、离线与重启结果分别记录。探针不是玩家映射输入；外观、手感、音效、真实硬件 FPS 与长期平衡仅在实际观察后确认。
