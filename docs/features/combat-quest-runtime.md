# 山寨清剿与兽巢讨伐的游戏接入

从0.131.0开始，两关在登记过的千机阁江湖榜提供。其他六张委托图仍保留设计和离线预览。主世界兽群聚集地尚未制作。

## 玩家入口与流程

打开江湖榜第二页，选择“山寨清剿”或“兽巢讨伐”的“办理远征”。服务器显示签发城镇和敌人境界范围。日常城镇事务与远征分别登记；每人同时保留一轮远征，待领报酬处理完后可再次接取。

按H打开“行迹”，选择“进入远征”。聊天中的可点击按钮与`/expedition enter`使用同一个服务器入口。首次进入先分批营造整张关卡，检查光照、入口和全部守敌出生点，再传送提出进入请求的玩家。

开始前，接单者可用`/expedition invite 玩家名`邀请附近玩家；对方使用`/expedition accept`加入。队伍开始后固定成员和人数倍率。队友按H自行进入，同一队共享本轮守敌与进度。

- 山寨依次清理门后守敌、粮车场、内院和寨主。
- 兽巢依次清理入口狼群、岩柱厅守兽和巢厅首领；赤甲蜥支路可选。
- 靠近当前敌群后出现出生预告；服务器检查站位和玩家距离后生成有限名单。进度条显示必经守敌数量与下一处目标。
- 必经守敌全部击败后，在出口磁石附近右键或执行`/expedition finish`验核。具备本轮参战记录的成员分别结算，然后返回江湖榜办理远征领取报酬。

`/expedition status`显示签发地、境界、队伍和个人救援余量。`/expedition leave`或H菜单“暂离远征”需要静止读条，移动或受伤会中断；`/expedition abandon`结束本人的本轮任务。致命伤害优先经过既有保命能力，再消耗本关救援；救援送回入口，耗尽后本轮失败。背包与消耗品沿用真实玩家状态。

## 境界、光照与刷怪

签发设施必须通过既有江湖榜的位置、距离、视线和命簿登记核验。服务器从该设施的`LifeSite.regionId`读取[wilderness/rules.json](../../src/main/resources/data/myvillage/wilderness/rules.json)：山寨使用`rogue`范围，兽巢使用`beast`范围。普通守敌逐个抽取，首领取范围上限；接取时冻结全部境界、UUID和签发地。玩家修为、传送位置、队长在线状态和重登均不重新决定难度。缺少地区配置时不提供远征行。

正式场景由[两关作者输入](combat-quest-models.md)经[game.py](../../tools/quest_realms/game.py)导出。Minecraft方块、原生楼梯、可见灯具和无碰撞补光均由该生成器负责。通路、节点、交战面与出生点具有亮度检查点；服务器等待光照传播，实测达到[runtime.json](../../blueprints/quest_realms/runtime.json)的下限后开放入口。环境亮度不代替实际方块光检查。

独立维度关闭自然刷怪、怪物改地形和火焰蔓延，并拒绝名单之外的Mob进入。原版主世界规则保持自身状态。每个遭遇具有预告、生成、战斗和清除状态，活跃敌人数受配置限制。玩家占据出生点时等待，不把敌人推入墙中。

和平难度不开放战斗秘境入场；在关卡中切换到和平时，进度条明确显示暂停生成。切回其他难度后继续同一轮，不把和平模式的实体丢弃当作战果。

守敌使用已注册的劫修、符修和妖兽，境界属性经共享`StatsRuntime`接入；人数与首领生命倍率使用独立、幂等的永久修饰符。真实死亡经`BattleReceipts`回写。实体卸载、短时找不到实体和离开区块均不算击败，也不自动补刷；和平模式明确丢弃的守敌可用原UUID和境界重试。已击败的守敌在本轮不再生成。

## 保存与回收

`myvillage_expeditions.dat`保存实例、成员、返回位置、冻结名单、进度与报酬回执。玩家离开后保留本轮；无成员在场时暂停守敌，空置期限由运行配置决定。正常保存、退出和重启恢复同一实体生命和任务事实。场景营造中断后标为失败，不重放地图覆盖已有方块。

维度使用`myvillage:expedition/<实例UUID>`。入口、登录恢复、传送和观战均检查成员归属，模板维度禁止进入。回收只处理无人、已结束或到期的远征，关闭世界并核对专用目录标记后删除自身目录；阡镇个人秘境不属于该目录。

报酬在出口验核时登记，回江湖榜领取。容量不足保留待领，正常重复办理不重复发放。提交前持久化`claiming`日志，库存与WorldSim声望提交后保存，再记已领；若进程恰在跨文件提交期间崩溃，保留待核对状态，停止自动再次付款。这里没有承诺多份存档文件之间的断电原子事务。

## 检查入口

- `python3 -m unittest tools.tests.test_quest_game`：正式方块的站位、楼梯、支撑、光源及故障注入检查。
- `python3 -m tools.quest_realms.game --out build/generated/quest_realms/resources`：同源导出；Gradle的`processResources`自动依赖该任务。
- `python3 -m tools.quest_realms.game_audit --resources build/generated/quest_realms/resources --out reports/quest-runtime/voxel-audit.json`：检查导出后的实际方块数据。
- `QuestStateTest`与`WorldSimPlayerEconomyTest`覆盖八地境界冻结、名单完整性、死亡回执、归属和经济门面。
- 管理员`/myvillage quest status 玩家名`只读回服务器实例、敌人、规则和报酬状态。
- `-PquestEvidence`仅为原生采集加入真实城镇任务榜定位夹具；带此参数时禁止打包JAR。原生采集中的任务接取、出入、攻击与验核必须记录真实客户端输入。

离线检查、原生开发者验证与玩家的美观、战斗手感、音效、FPS和多人体验验收分别记录。
