# 天命基础能力与乙木灵体（0.85.0）

本批补齐天命主动入口、控制与净化、治疗修正与吸血、多来源护盾、持续领域五块能力，并以乙木灵体作为实际使用者。其他高阶占位天命不会因基础能力存在而获得效果；当前候选池有 16 项已实现、10 项无效果占位，另有 10 项仅在设计目录。

## 玩家入口

在测灵碑确认乙木灵体后，H → 技能中出现「乙木缠根」。选择它、选择六个键位之一并分配，关闭界面后在修炼战斗模式按该键释放；不需要额外研读秘籍或装备特定武器。已有存档中确认过乙木灵体的玩家直接获得效果，不重抽灵根或天命。

乙木灵体吸取直接主攻击造成的实际生命损失，排除吸收、过量、持续和衍生伤害。按主世界固定 tick 窗口计算的实际回复受最大生命比例上限约束（不是滚动窗口），治疗增益也不能突破该上限。吸血不复活已死亡的攻击者。

缠根在施法处创建短时领域，对范围内可见、允许攻击的目标施加一次根缠；强敌缩短受控时间，免控首领不会被锁死。根缠限制水平移动，保留视角、纵向物理和受伤，不冻结整个实体 tick；主动闪避和攻击脚步不能绕过定身。环境流体、活塞等未经控制服务登记的水平位移仍受锚点约束，尚未作为支持范围验证。无目标仍允许正常空放并付费。灵力不足、冷却中、动作占用或服务器创建领域失败时不消费灵力。

吸血比例及上限来自 `myvillage/innate_fate/wood_spirit_body.json`；能力费用、冷却和半径来自 `combat/fate_abilities.json`；领域寿命与根缠时间来自 `combat/foundation/fields.json`。这些配置为数值唯一来源，中文界面显示相应能力和服务器状态。

## 代码与状态所有权

- `cultivation/fate/ability` 负责能力定义、天命资格、执行器准备、消费与冷却；六槽保存及槽位意图复用原技能系统。确认的天命 ID 不是额外的已学功法。缺失或禁用的天命定义不授权能力。
- `FateAbilityCooldowns` 使用主世界 SavedData 和游戏时钟保存逐玩家、逐能力的冷却期限；死亡、退出、换维度及正常重启不能刷新期限。过期项回收；暂态领域和控制不落盘。
- `ControlService` 负责带来源与期限的根缠、减速、霸体及净化。减速取最强来源；净化只撤销本模块控制和原战斗硬直，不任意删除药水效果。首领和重复控制规则来自 `control.json`。
- `RootedPlayerMovementMixin` 在原版移动包切回服务器线程并校验非法坐标之后约束 X/Z，保留原版 Y、视角、碰撞和着地处理。`CombatDodgeService` 与 `CombatStepService` 同步拒绝受控位移。
- `HealingRuntime` 提供来源明确的治疗及限时增减疗；原有 `heal` 调用也经统一治疗事件修正。自定义伤害在精确容器 Post 冻结实际主生命损失，hurt 返回后消费一次，避免图腾恢复污染基数；原版近战和有玩家来源的投射物在 Post 直接结算，两条路径互斥。规则来自 `healing.json`。
- `ShieldRuntime` 管理新增的暂态多来源护盾；同源替换、异源有数量和总量上限，按到期时间及来源排序消耗。旧吞丹化势保留原持久状态和冷却，先消费旧护盾再消费新护盾，最后由原版处理黄心。所有池都在原版盔甲／魔法／类型抗性之后处理，虚空和管理绕过伤害不被拦截。规则来自 `shields.json`。
- `FieldRuntime` 管理有界固定／随身领域及定期根缠、减速、治疗效果。目标经过友军／宗门／PvP、可见性和已加载区域检查；同源同类领域不能通过重叠重复获益。治疗领域只是基础接口，未启用长生道胎。实例、目标、生命周期及粒子预算来自 `fields.json`。

公共代码不引用客户端类型。新文字沿用中文，技能页和快捷栏沿用现有布局与图标，领域使用有界原版粒子。协议 43 隔离新旧能力语义，原天命状态和绑定 ID 继续兼容。

## 检查与证据

本地检查：天命资源校验、相关 Python 变异测试和验收脚本解析测试。重型 Java 编译、聚焦 JUnit、jar 与真实客户端验证使用用户指定的既有 Colab，固定提交和文件哈希。

`tools/fate_foundations_evidence.py` 记录选中用例、完成用例和未运行用例。玩家选词条、绑定、释放、攻击通过真实映射输入；管理员命令仅准备与读取夹具。`/myvillage foundation` 为 permission 2 的诊断树，不是玩家施法入口。工具实现和单元测试通过不能替代实机结果。

实际结果以本次交付记录为准。玩家外观、操作手感、音效、真实硬件 FPS、长期平衡及未观察的多人行为保持 `not_verified`。
