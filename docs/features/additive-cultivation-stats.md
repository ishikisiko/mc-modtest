# 修炼属性加值与肉身防御

当前玩家数值覆盖凡人、炼气九层、筑基初中后、金丹初中后。唯一数表为
`data/myvillage/stats/progression.json`，四元组依次为生命上限、角色自身攻击、肉身防御、灵力上限。
realm JSON 继续维护修为、稳定度和突破条件，不再另外维护灵力容量。

## 属性来源

角色原有基础值加上境界贡献，再叠加装备、功法及已实现天命的各自贡献。境界不再整体乘算武器或其他来源。
筑基品质保存为 `foundation_quality`：0 未筑基，1/2/3 地道下中上品，4 天道。
金丹品质保存为 `golden_core_quality`：0 未结丹，1/2/3 下中上品。当前 profile 格式为 v5，网络协议为 61。
开发阶段不提供历史 profile 迁移。

属性由已达阶段和两项品质重新计算，使用稳定的 ADD_VALUE 属性修饰替换，刷新与重登不累计。
突破扩容不补满生命或灵力；保存的属性修饰在生命值读取前恢复。附件继续依赖 copyOnDeath，未增加手工 Clone 复制。
补基丹仅提高地道品质，重新计算对应差额，不能将地道改为天道。既有根基百分比加成已退役。

兽与原版怪物继续使用默认下品数表；NPC 使用自己的持久品质。在各自原生生命/攻击上添加境界贡献，不重抽出生境界。雷角虎等大原生基值走已有的原生边界入口，最终生命/攻击仍受 Minecraft 硬上限约束。

## NPC 的身份与灵力

`progression.json` 的 `npc` 段是天骄和品质概率的唯一来源。人物出生时独立抽取天骄身份；普通人物筑基、结丹均用下品，天骄在成功达到相应境界时分别抽取地道中/上品、金丹中/上品。两次品质抽取使用独立随机用途，失败不确定新品质，小阶段、化身刷新和重启不重抽。天骄没有额外整体系数。

命簿格式以 `StateCodec.VERSION` 为准。`Person` 保存 `prodigy`、`foundation_quality`、`golden_core_quality`、`spiritual_power`，以及出生天赋 `fates` 和效果状态 `fate_runtime`，只经 WorldSim facade 修改。`PersonView` 提供实际灵力及其容量。化身同步服务器给出的天骄身份，通用交谈、剧情和宗门事务页面均在姓名下显示现有书法字体的“天骄”。普通召唤/蛋生 NPC 在自身实体中保存同样的身份与灵力，不伪造命簿人物。预算与共享效果规则见 [NPC 出生词条](../ai-kb/48_innate_fates.md)。

NPC 容量使用同一加法数表；扣费、恢复和溢出处理与玩家共用 `SpiritualPowerMath`，恢复计时使用同一 `QiRegeneration` 与 `qi/rules.json`。正在工作阶段修炼的居民使用打坐恢复倍率，功法及灵根匹配继续读取其已有功法规则。只累计实际加载、可行动化身的服务器 tick，没有离线回灵；新化身、重登和重启从完整恢复延迟开始，不缩短消耗后的等待。基础持剑攻击与玩家一样免费，本次没有额外给 NPC 添加法术。`SpiritualPowerRuntime.spend` 是角色共用的扣费入口。

元婴暂时只有最低一档，`nascent_soul` 段维护突破增量和初、中、后期增量；以人物自己的金丹后期为基准，因此先前品质差额保留。仅供 NPC 使用，未开放玩家元婴。离线斗法保留原有阶段、功法、法器、伤势模型，以本人的基础攻击与同境界普通下品攻击之比反映已取得的品质；不新增独立天骄调参倍率。

扩容不补满当前生命或灵力。现有战斗档案只保存肉身、装备和冷却，不再拥有第二份灵力。开发阶段拒绝其他命簿版本，不增加历史迁移。

## 肉身防御

`myvillage:body_defense` 是独立的同步属性，`myvillage:defense_penetration` 只削减肉身防御。
设攻击为 A，穿防后的防御为 D，转折比例为 t、保底比例为 p，这两个比例只取数表：

```text
A = 0：结果为 0
D <= t*A：结果为 A-D
其他情况：结果为 p*A + [A*(1-t-p)]² / [D+A*(1-2*t-p)]
```

低防区线性扣减，高防区在转折处数值与斜率连续，伤害渐近攻击的一定比例。
自定义招式用其 outgoing 收据中的攻击计算防御，再保留招式、暴击等倍率；原版近战用攻击属性分离这部分倍率。
投射物以自身命中的伤害为基准。环境坠落、窒息、无归属伤害和绕过无敌的管理伤害不经过肉身防御。
以主击实际损血为基数的火灵衍生伤害不再重复扣防；有独立攻击基数的剑气、元素持续伤害各结算一次。

之后仍由原版执行护甲、韧性、附魔、药水与吸收结算，既有分类抗性在吸收前应用一次。
境界不再额外降低护甲压力。装备破甲、物理穿甲与肉身穿防各自作用于对应步骤。
`stats trace` 可分别读到攻防、护甲入口、护甲输出、分类抗性、吸收和实际生命损失。

## 正式突破雷劫

H → 内视页提供天道筑基和下、中、上品金丹的正式引劫选择，N 键也会打开选择。通过服务器确认的 6/6/9/12 次命中并存活后，才按所选品质结算；地道筑基继续服用筑基丹。
雷劫次数与时序只由 `tools/tribulation/rules.json` 维护，基础属性数表不再含 MOCK 开关或雷次数。
资格、一次结算、失败及重启续接见[突破雷劫](tribulation.md)。

## 检查

Java 覆盖批准数表、品质固定差额、防御连续性/保底/穿防、profile 编解码、单字节正式引劫意图与重复结算拒绝。
`tools/validate_additive_stats.py` 检查数表及交付资源；`tools/validate_realm_stats.py` 保留原版护甲拦截范围和原生上限保护。
`-PtribulationEvidence` 仅为独立原生服务器 fixture 增加探针，禁止以此参数打包交付 jar。
原生探针检查实际属性、装备属性叠加、伤害顺序和真实服务器重启后的存档读取；它不代表玩家映射输入或手感验收。

`-PnpcCultivationEvidence` 仅为独立原生 NPC 数值、共享回灵和重启 fixture 注册探针命令；打包任务明确拒绝此参数，交付 jar 不包含探针类。
