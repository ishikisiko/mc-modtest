# 炼丹、炼器的随机品质

0.126.0 起，炼丹和炼器共用正态分布。炼丹每颗独立抽取，炼器每件抽取一次。初始两项资质各自在 0～60 中生成，培养仍可继续增加；制符继续使用原有品质规则。

## 公式与品阶

唯一数值来源为 `src/main/resources/data/myvillage/crafting/quality.json`。将资质记作 A、配方品阶起点记作 B、该品阶跨度记作 W：

```text
平均分 = 100 × (A − B) ÷ W
本次得分 = 平均分 + 标准差 × 标准正态随机数
实际阈值 = 品阶基础阈值 + 丹方难度 × 每级修正
```

当前标准差为 12。炼气四个基础阈值为 20、40、70、90；筑基及以后为 −20、20、60、80。四个阈值依次划分失败、下品、中品、上品、极品。得分恰等于阈值时进入右侧结果，低于第一个阈值则失败；失败不会生成“零品质”物品。

当前品阶起点从炼气的 0 开始，每阶增加 100，跨度均为 100，配置已覆盖筑基、金丹、元婴和化神。这是本次接入使用的初始标尺；后续高阶装备和丹药可以继续调整配置。配方明确声明 `quality_tier`，计算取配方品阶，不取操作者当前修炼境界。

丹方难度为 0～3，每级将全部四个阈值提高 10。现有炼器器谱难度修正为 0。资质达到门槛后仍可能失败，也可能得到各品级；提高资质会平移分布，没有按资质切断高品质的规则。

## 丹方与四格产物

`alchemy/rules.json` 格式 3 保存原料、数量、燃料、时间、每炉尝试颗数、最低资质、品阶与难度。原有多张筑基／补基丹方全部保留，材料更贵的版本难度更低；学习物品和菜单名称显示难度，悬停显示实际材料与学习／开炉门槛。`scroll_quality` 只指定原有卷轴边饰，不参与结果计算。

普通青铜丹炉现为三个药材槽、一个灵石槽、四个只取产物槽。炉阵保持三个进药通道、一个灵石槽及四个产物槽。每炉尝试颗数沿用配方原值，成功颗数由独立结果决定；同一炉可以出现多种品质和失败。相同品质可合并，不同品质分别占槽。

服务器接受开炉后，立即冻结每颗得分与结果、配方、操作者、资质、品阶和难度。满输出、暂停、结构损坏、卸载、关服及重载均不重新抽取。输入／燃料和全部成功产物在同一次完成事务中提交；整炉失败也会完成并扣除完整配方成本。无成功产物时不增加本炉制作资质练习收益。

普通炉仍需每炉手动启动，炉阵按已经授权的资质连续开炉，每批各自独立抽取。普通炉当前库存格式 2、批次格式 2；炉阵批次格式随当前实现更新。开发版本不迁移旧库存／旧批次格式，已有世界中的旧炉应先清空。

## 炼器结果的保存

普通鼎自动制作、组装台新器坯装配及现存成品合成入口都使用同一正态公式。自动制作和组装在开始时冻结结果，失败炉次仍完整计时并在完成时消耗已确认投入；输出阻塞暂停，重启不重抽。只起坯不抽品质。

成品换柄、炼灵、辅助火、再锻和维修保留已有品质。界面只展示资质和随机结果规则，不用预览用的下品模型冒充已经确定的成品品质。

## 筑基丹与补基丹

两类丹药现在都能炼出下、中、上、极品。丹药品质到地道根基效果的映射由 `alchemy/foundation.json` 保存：当前下／中／上／极品分别对应根基 1／2／3／3。极品筑基丹沿用地道上品的成功率和属性，天道筑基仍走引劫。

补基只补足到对应根基，效果相同或更低时拒绝消耗。原有筑基资格、成功率、稳定度损失及补基单调性保持原规则。炼出极品与获得天道根基是两个有各自规则的游戏结果。

## 检查范围

共用配置与概率参考实现位于 `tools/crafting_quality.py`，Java 执行入口为 `CraftingQualityRules`。必要检查覆盖阈值边界、跨品阶计算、独立抽取、配置拒绝、失败扣料、原子输出、冻结结果及实际保存重启。测试准备可指定结果以覆盖极小概率分支；该准备不作为自然随机频率的观察证据。

游戏中的丹炉、炉阵和工位菜单是实际操作入口。新的概率展示与开发者服务器回执分别说明公式和事务，玩家界面操作、手感与平衡结论按实际观察单独记录。
