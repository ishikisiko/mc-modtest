# 妖兽材料与城镇回收

三类材料为妖兽皮、妖兽骨和妖丹。每件材料按妖兽自身的大境界及独立抽取的稀有度取得固定物品身份；同类、同境界、同稀有度可堆叠64个。五个大境界与四种稀有度共有56种有效组合，妖丹从筑基开始，炼气没有妖丹物品。未分配境界的召唤妖兽使用目录声明的默认境界；明确分配了境界的目标只使用自己的境界，不跟随击杀者变化。

## 掉落来源

- 妖狼、荆背獾、赤甲蜥、寒翎雉和吞火蟾使用普通兽类的皮、骨掉落，筑基开始另抽妖丹。
- 雷角山君使用首领掉落；首领各份材料分别抽取稀有度。
- 灯孢妖保留原灯孢囊，筑基开始另抽妖丹。
- 人形敌人、行尸、骸弓、游剑妖、照影妖和石灵保留原掉落。这次没有为它们增加兽类皮骨。

普通、生态据点和战斗遗迹场景使用这些追加规则，原专属材料继续由各自战利品表提供。生态兽类优先使用 `beast_habitat_materials` 的继承规则，替代原据点的直接灵石奖励；据点身份、代次和真实死亡回执仍由服务器核验。委托秘境、宗门考核和资质试炼的禁掉落规则保持优先。

玩家、NPC、驯养生物及环境造成的正常死亡使用相同的材料规则。卸载、消失和清理实体不触发死亡物品结算。

## 数量、概率与稀有度配置

`src/main/resources/data/yuanxian/drops/monster_drops.json` 是掉落数值的作者入口，沿用包内默认与显式外置覆盖的[统一加载规则](monster-drops.md)。普通和首领的数量、概率、适用实体、场景、境界门槛及稀有度权重都在表中配置。

材料条目使用 `factory: beast_material`。`item` 指向本类材料中的一个有效物品作为类别样本，实际输出境界来自目标，实际稀有度来自 `rarity_weights`。四个非负整数权重依次对应普通、不凡、罕见、传说，总和必须大于零。每份材料独立抽取，首领的一批皮骨可以出现不同稀有度；这些物品不接受额外的丹药品质或原版稀有度覆盖。

`chance_looting` 的 `per_level` 与 `max_level` 管理抢夺的概率增量。最终概率为基础 `chance` 加每级增量乘计入等级，计入等级按配置封顶，最终概率不超过1。普通兽类的第二条皮掉落和骨掉落最多计 3 级抢夺的概率增量。

从 0.136.2 起，普通兽类和雷角山君的皮、骨、妖丹每条规则抽中后，再按实际抢夺等级增加数量。游戏从 0–1 之间抽取一次随机系数，乘抢夺等级并四舍五入，结果加在该条的基础数量上。例如抢夺 X 给每个抽中的条目随机增加 0–10 件。妖丹仍要求被击杀的妖兽达到筑基，且每份材料分别判定稀有度。

网页工作台可以编辑材料工厂、稀有度权重和已有的抢夺概率增量，也可以选择固定境界、固定稀有度的材料直接掉落。服务器、网页完整校验后才替换规则，失败保留当前快照。

## 回收与资源归属

每座已营业的城镇铁匠在“卖出”页收购三类材料，按材料类别和境界筛选，选择数量后批量成交。目录中的价格由基础价、境界倍率和稀有度倍率生成；玩家境界、城镇生活公库和商店普通库存不参与定价或收购容量。

0.144.1 起，铁匠先计算整笔回收总价，再按灵石品级将实收金额列在报价中。每满 10,000 枚下品折为一枚上品，余款每满 100 枚下品折为一枚中品，最后用下品付清。单枚化神传说妖丹的报价仍值 25,600 枚下品，实收 2 枚上品和 56 枚中品。

回收材料退出流通，不进入有限货栈，也没有每日收购限额。单笔数量继续受原交易上限限制，报价、商人岗位、近距交互、人物租约、版本和一次性序号继续在服务器复核。回款优先进入灵石袋，手动回收也可存入暂停自动拾取的袋；没有可用袋时尝试放入主背包。材料不足、组件不匹配或回款空间不足时整笔拒绝，原背包保持不变。

`tools/beast_materials/catalogue.json` 拥有材料基础价、境界倍率、稀有度倍率与像素图标输入。执行以下命令生成物品目录、模型、贴图、中文名称和分类标签：

```sh
python3 -m tools.beast_materials.generate
python3 -m tools.beast_materials.generate --check
```

生成的 `data/yuanxian/beast_materials/materials.json` 同时用于Java注册、固定回收报价和网页物品能力。`BeastMaterialContent` 注册物品并放入创造栏，`BeastMaterialItem` 显示稀有度颜色与回收说明；现有 `DropRuntime` 负责服务器死亡结算，现有 WorldSim 商业 facade 负责交易回执。

定向检查为 `tools.tests.test_beast_materials`、掉落规则及商业测试。`python3 -m tools.beast_materials.native_evidence` 在隔离平坦测试世界观察真实死亡事件、落地物品、原生注册表、回收背包事务和存档容器重启。该探针通过独立测试模组运行，不进入交付JAR；命令夹具不代表玩家战斗、菜单操作、外观、手感、FPS或多人验收。

加 `--client` 可附加真实客户端画面及鼠标筛选检查。此时由测试夹具打开正式回收菜单，再以实际鼠标切换卖出页、材料、境界和分页；它验证渲染及筛选交互，NPC接待与真实购买操作仍需分别观察。

0.135.0的实际构建、测试、原生场景与画面记录见[专项检查](../testing/2026-11-16-beast-materials.md)。
