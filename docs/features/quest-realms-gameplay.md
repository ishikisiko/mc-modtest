# 六座委托秘境的完整玩法设计

状态：设计稿，尚未接入游戏。本文深化六张既有地图的玩法；用户已明确要求大多数关卡必须包含战斗，只允许一至两关没有战斗。本稿采用五关包含必需战斗、藏书天井一关纯解谜的配置。具体敌人、奖励和数值为本轮设计建议，不代表游戏已有行为或用户已逐项接受。

当前地图见[地图设计与预览](quest-realms-maps.md)。本文定义玩家需要观察什么、如何操作、战斗如何改变局势、失败后如何继续，以及成功后怎样结算。现有网页的阶段按钮只演示旧的先后关系，不能作为本文玩法已经实现的证据。

### 1.1 空间、建筑与场景表现

每关沿主路组织三次空间变化：入口先看见一处与目标有关的地标，中段通过高差或遮挡改变对地形的认识，后段打开能认出先前位置的回程捷径。支路分别提供线索、准备资源或路线优势，进入前能观察到部分收益。地图复杂度来自这些位置之间的联系。

建筑采用完整的Minecraft硬边主体、方块结构和像素材质。房屋、祠堂、书楼必须有连续墙体、门窗、内部楼板与可使用的楼梯；崖壁、地基、廊桥和支架共同解释建筑为何处在这个高度。重点构件先确定轮廓、受力和用途，再补接缝、修补痕迹、潮湿与积灰。

## 二、共同规则

### 2.1 接取、准备和进入

1. 千机阁办事厅增加“秘境远征”页，宗务堂增加宗门远征入口。原三类城镇事务继续使用原入口与资格；远征单独登记，每人同时持有一份远征委托。
2. 接单时显示地图目标、固定难度档、推荐境界、主要危险、内部破拆和放置规则、是否存在限时阶段，以及本次基础奖励。奖励在接单时冻结。
3. 首版支持一至四人。发起者选定一份委托及签发设施，队员在进入前确认；开始生成后冻结名单、难度和奖励规则。本轮中途不增补队员，队长离线后由仍在线成员继续。
4. 单次远征只采用一份签发委托。城镇签发使用江湖声望，宗门签发使用宗门贡献；同一次目标不重复领取两套委托奖励。接单时检查宗门身份，未结算期间身份失效的处理见结算规则。
5. 玩家从准备界面主动进入，记录各自的外部安全返回点。登录不自动接取或进入，未完成生成的实例不开放传送。
6. 进入后先到入口营地。营地提供地图规则、已知目标和紧急撤离入口，不自动发放永久装备、功法或无限补给。第一次开本提供必需的本轮工具，工具数量足以完成基础路线。

### 2.2 境界、战斗与队伍规模

首版先制作一个标准档，按已经掌握基础战斗与恢复手段的炼气中期玩家校准。建议以炼气六层作为统一标定样本；地图中普通敌人固定为炼气四至六层，必需精英或首领固定为炼气七层。藏书天井无境界硬门槛。生命、攻击、防御和抗性继续来自既有境界与敌人数据，实际数值要在可玩切片中验证。

每张委托的档位在开本前声明，敌人不会根据进场玩家实时重新抽取境界。高境界玩家可以重访，奖励仍按委托档位计算。

组队先按一、二、三、四人分别使用1、1.6、2.1、2.6倍首领最大生命作为调试起点。伤害、攻击速度与招式预警不随人数抬高，少量杂兵采用预先配置的队伍人数变体。倍率只应用一次，重登、卸载和队员离开不重算。

战斗关采用以下共同要求：

- 主路通常同时面对二至四名敌人。一至三人队的局部同时活动上限为四名，四人队为六名，首领与杂兵合计计算；超出预算的名册成员在原区域等待，不在玩家身边补出。
- 普通招式的可辨认前摇至少约0.9秒，危险范围攻击至少约1.2秒。重要预警同时使用动作、声音和地面形状，颜色只是辅助。
- 攻击锁向之后保留可利用的侧移空间。机关与环境可以创造约二至四秒的明显出手机会，具体窗口由敌人的原生动作时间表承接。
- 敌人继续使用既有命中、灵力、硬直和伤害服务。境界加值与原版减免各执行一次，不另加一套关卡伤害结算。
- 地图机关不要求特定灵根、稀有天命或某一本功法。近战、远程、身法和丹药分别提供不同的准备优势，单人可完成所有必需操作。
- 首领血量可以被正常伤害打穿阶段阈值，不用强制锁血拖长战斗。新增反应、路线和机关联动属于待实现的遭遇配置。

### 2.3 地图边界与玩家工具

山体外壳、实例边界、承重结构及关键机关固定。内部按区域开放旧木障、碎石、矿层和修桥槽位，界面提前说明。爆炸、流体搬运、活塞和实体携带同样遵守服务器区域权限。

全部必需路线可以步行完成。御剑和身法可缩短已开放路线、方便侦察；矿井低顶自然限制飞行，渡口风口另设可见且局部生效的扰流区。关卡限制不修改玩家的永久能力，离开区域或实例后恢复正常规则。钥匙、首领死亡和救援等事实仍由真实目标判定。

药水和功法提供的抗火、水下呼吸等能力正常生效。它们可以拓展通路和交战方式，不改写固定销、矿核、器匣和救援回执本身的状态。

### 2.4 状态、战利品与回程

每个实例保存机关状态、敌人的唯一身份与剩余生命、已采集节点、已开容器、任务物的位置、救援人物状态、队员资格和各自返程点。敌群在开本时确定总名册；触发噪声、援兵或伏击时只激活名册中的未出场成员。已击败者不因离场、掉线或重启复生。

普通带入物品保留在玩家真实背包和装备槽中，消耗、耐久及灵力损失照常结算。实例内新获得的可带出收获进入本轮收获袋，成功撤离后才交付永久物品；关卡钥匙、矿核、救援工具等使用实例任务记录，不进入自由交易。原有灵石袋继续拥有自己的货币账本。

主目标失败、强制撤离或主动放弃时，本轮收获袋不转为永久物品。途中找到的本轮恢复用品仍可在实例内使用，未用部分随回收清除。渡口的合法部分救援使用自己的部分成功规则。

首版实例容器只接收指定的本轮任务材料，玩家不能把带入的永久物品存入其中或丢到地面。普通材料消耗使用完整背包事务，取消操作不扣料。关卡允许的采矿和破拆收获均有明确清单，固定机关、承重块和本轮借用工具不产生可带出掉落。

入口营地一直保留主动撤离。H的行迹页提供六秒返程引导，受到有效攻击时中断；同一实例的返程台使用相同规则。回城符经远征的合法离场入口完成交接，再按符箓原有规则返回合法目的地，实际消耗符箓；闪回符只回到本实例仍然合法的记录点。

出口区承担任务物验核和收获袋封存。未经过出口区就使用返程手段，只算暂离，任务物留在实例安全中转位，收获袋不进入永久背包；它仍可用于保命。已经抵达出口并符合成功或合法部分成功条件时，才能确认结算。

离场选项明确区分“暂离保留”“放弃本轮”和“目标验核后结算”。暂离保留资格与未结算收获；主动放弃清除本人的任务资格和收获袋，并退出本轮。任何成员可以个人离场，不能用个人操作强制送走队友或回收仍有人活动的实例。渡口的部分结算由成员个人确认，按离场时已经验核的救回人数冻结结果并退出本轮；后来队友再救出另一人，不向已结算者补发第二份奖励。未选择结算的队员可以继续救援。

追猎凭证、矿核、器匣和拓片在出口正式验核后，转为实例共享的完成记录，不再留作可反复取出的任务物；尚未离场的合格队员到出口使用同一事实结算。工坊器匣验核后停止炉压。已经验核的目标保留完成事实，仍在场的队员继续承担现有敌人与地形风险，个人被强制撤离仍按失败处理。任何成员完成个人结算后都退出本轮资格，不能再返回采集。

拿到任务物后可以先战斗、存放到本轮中转台或交换携带者。任务物不会以普通掉落实体落入虚空。交接要求双方处于同一实例、距离足够近且任务物仍由当前持有者占有；服务器一次性替换持有记录。持有人离场、掉线或倒地时，物件回到已开放、具备合法站位且从当前通路可达的安全中转位，避免剩余队员等待离线持有人。

### 2.5 濒死、失败与恢复

每人每次远征有两次阵符救援。既有保命机制先按原规则执行，仍将死亡时才消耗本轮救援次数：

- 单人使用救援后回入口营地，恢复至30%生命；装备、物品消耗和已经造成的世界变化保留。
- 组队玩家先倒地20秒，队友在安全范围内持续救助三秒可将其扶起；无人救助则送回入口。两种方式都消耗一次救援，倒地者不能攻击或操作机关。
- 次数耗尽后的下一次濒死会强制撤回外部安全点，该玩家本轮失败并退出队伍资格。其他队员可以继续；失败者不能重新进本领取首通和完整目标奖励。

这项机制只在本轮远征维度执行，不改变主世界死亡规则，也不通过回滚修炼档案或整份背包实现。服务器必须阻止重复救援、重复死亡复制与重复退还消耗。

解谜错误、普通摔落和单次操作失误通常提供局部恢复机会；每关的终局失败条件在后文单独列出。首领脱离交战后回到合法巡行点，保留生命与阶段；不凭重进补满血。所有可恢复情况都保留回入口或安全点的路径。

### 2.6 暂停、续玩与实例回收

最后一名队员离开或离线时保存并暂停实例。炉压、敌人招式、救援倒计时和任务计时均暂停，不在无人观察时推进；从最后一人离开开始保留24小时，采用现实经过时间。

名单内玩家通过行迹页主动续玩。恢复时保留机关、敌人、收获袋与救援次数；给出短暂恢复提示，控制和遭遇同步恢复，恢复保护期间不能造成伤害。部分队员离线而仍有人留在实例时，关卡继续运行。

完成、全员放弃或超过保留期后才进入回收。先把玩家送回合法位置并持久化完成/失败及领奖回执，再撤回化身和区块票，关闭世界，确认无人及无打开的存储后删除本轮目录。仍有玩家在场时不执行到期删除。服务器重启不把未完成实例当作新本，也不重抽奖励。

## 三、断崖旧寨：踪迹与钟声影响追猎

### 3.1 委托与关键选择

千机阁要查清旧寨商路上的袭击，并消灭首领。玩家在下寨找到两类互相印证的痕迹，判断首领当前在西侧猎人洞还是东侧兽巢，再决定从哪一侧接近、在哪里引它交战。

这关希望产生的具体经历是：玩家先在桥下看见高处钟楼，沿村巷爬上去，借钟声把首领引出难以转身的兽巢，最后从先前头顶的吊桥返回。首领的移动与回程设施都要在实际地图上发生。

### 3.2 流程与空间

1. 在`creek`和`village`查看新旧脚印、猎物拖痕；至少两条证据指向同一候选巢穴。线索使用形状、方向和文字记录，避免只靠颜色。
2. 在下寨主巷和磨坊侧道之间选路。主巷较短，常有狼群；侧道更长，可以从高处查看巡行并进入药畦或桥洞支线。
3. 到`tracks`确认首领行进的山口，在`bell`选择一次引导钟声。发声后给出八秒左右的远处回应，首领沿已验证的道路离巢，不瞬移到玩家旁边。
4. 玩家可以守在较宽的`ambush`岩庭，也可以在高寨拦截。首领到场后执行正常战斗；找到巢穴并直接开战也可完成目标。
5. 击败绑定首领后获得追猎凭证，启动`winch`放下吊桥。桥面连接`return`高哨，再回入口撤离。

### 3.3 敌人和首领

| 遭遇 | 数量与位置 | 作用 |
|---|---|---|
| 下寨狼群 | 两只妖狼，在主巷与断桥下巡行 | 教玩家利用转角、侧道和较宽的战斗空间，可绕行 |
| 磨坊支线 | 一只荆背獾，守住补给处 | 可选战斗，用原有冲撞和收招空隙 |
| 狼王 | 一只实例专属妖狼首领，开本时确定巢穴 | 必需战斗；复用妖狼身体，新增追猎与呼群配置 |

狼王先用锁向扑咬和侧跃撕咬。扑咬有明显压低身体的动作与低吼，落地后留出约两秒收招。玩家可以侧移后反击，或利用岩庭石柱阻断后续追击。

剩余生命约40%时，狼王尝试退回巢穴。玩家可继续追击，也可在钟楼改变它的下一段路线。退行期间保持可受伤；已经打出的伤害不会被抹掉。

狼王全场只进行一次呼群。援助来自名册中仍然存活的下寨狼群；提前清理狼群能减少首领压力，已杀死的狼不会重新生成。首领场地同时出现的敌人不超过三只。

### 3.4 风险、支线与复玩

错判巢穴会多走一段路并惊动对应巡逻，不直接使任务失败。钟声短期内不能连按，首领当前扑击结束后才重新规划路线。可选的落木机关只使用一次，能打断扑击并造成少量环境伤害；它不能独自杀死满血首领。

桥洞可找到商队遗物，磨坊支线有本轮恢复物资。两处巢穴、狼群巡行方向和遗物位置从作者给出的有限组合中选择，线索必须与本轮真实状态一致。必需首领死亡由绑定身份确认，击杀别处的普通妖狼不能代替。

本关没有全局倒计时。终局失败来自全员失去远征资格、主动放弃或实例到期；扑击落空、选错路和丢失目标都保留恢复办法。

## 四、回水古祠：调水解谜与守卫战

### 4.1 机关的真实关系

古祠的门和匣座依靠同一套水轮、配重与固定销。玩家要先让水轮抬起配重，再插入固定销保持门与匣座开启，最后排水，从正常步行路线取匣。

| 操作点 | 两种位置或状态 | 可直接观察的结果 |
|---|---|---|
| 西闸W，`sluice_w` | 蓄水／排水 | 改变前庭水位；水位降低后露出下行石阶 |
| 东闸E，`sluice_e` | 回池／驱轮 | 水流回到蓄水池，或流入水轮铜槽 |
| 固定销L，`wheel` | 未固定／已固定 | 固定抬起的配重，并释放匣座的机械扣 |

初始为蓄水、回池、未固定。西闸处的水痕说明排水能露出下梯；东闸的铸造箭头说明驱轮所需流向；高阁旧告示说明必须固定配重才能取出器匣。三条说明都在对应设备附近，不要求背诵谜语。

常规解法是：保持蓄水，将东闸导向驱轮，击败石卫取得压闸销，固定已升起的配重，再把西闸转为排水，沿井壁下梯进入封存室。

固定销只能在水轮受到驱动且配重已升起时操作；未供水时会明确提示缺少动力。固定后关掉水轮也不会把门砸下来。玩家可反复调整闸门，机关不会因试错报废。自带水下呼吸可提前涉水观察，但取匣仍需实际释放匣座机械扣。

### 4.2 战斗与水位

西岸巡水廊有两只照影妖，它们借转角和水边高差对玩家出招作出反应。玩家可绕开一部分巡逻，先查看闸房与高廊。

必需首领是上池的镇水石卫，使用现有守碑石灵身体作为首版基础，新增本关遭遇行为。压闸销在其身上，死亡后作为队伍任务事实记录，不占背包格，也不会因满包卡住解谜。

石卫使用三种清楚可读的攻击：

- 抬臂重击前出现裂纹预兆，随后锁定一处地面。玩家可以侧移；命中指定铜槽时，冲击带动逆流，使石卫出现短暂失衡。
- 定向水冲沿已有沟槽分段推进，先显示流向再产生伤害。高水位时玩家主要使用上桥；低水位时可以走池底，但要避开低槽。
- 生命约55%时，石卫唤醒两只预先登记的照影妖，整场只触发一次。全部敌人仍遵守同一遭遇数量上限。

机关提供出手机会，但玩家的正常攻击一直有效。绕后攻击、远程消耗和利用铜槽都能战胜石卫，不要求使用水属性或指定功法。

### 4.3 错误、成功与支线

误把水流导回池只会停止驱轮；排水过早需要回闸房重新蓄水。水位变化分段进行并提前提示，门和水体变化不把站在边缘的玩家直接埋住。有人处在配重门下时，服务器拒绝释放固定销并说明原因。

`script`碑室记录古祠的维护方式，`cistern`和`leak`构成额外检修路线。支线可以提前打开返程暗门，但不能凭一个无关机关代替压闸销与匣座。

成功条件是石卫已被本队击败、固定销有效、队伍取得本轮器匣并成功撤离。正常操作没有永久失败次数，也没有全局倒计时。复玩时可改变支线容器和巡逻组合，闸门的物理含义保持一致。

## 五、赤石矿井：破拆声音与携核突围

### 5.1 进入矿层前的判断

玩家受托回收一枚封在深层的矿核。入口给出主井和副井的大致位置，矿工标记说明短道、排水道和废弃检修道的用途。地图不直接把矿核位置显示为透墙光点。

在`timber`与`drain`之间有两种处理：拆开旧木撑与碎石可以走短道，但会惊动附近矿兽；沿排水渠绕行能减少破拆声音，需要处理积水和一处灯孢妖占据的窄道。玩家可以先进入避难室取得本轮补给，再决定是否深入。

本关只允许开采指定矿面与拆除标记木撑，整座承重山体固定。可采矿材有限，采出后登记进本轮收获袋，不通过重进恢复矿面。

### 5.2 噪声如何产生后果

噪声采用0—3级警戒，不随普通走路、聊天或菜单操作增加。拆开一处指定木障或破开一组封矿碎石提高一级；同一组材料只记一次。普通攻击只在命中明确标记的共鸣矿架时产生本关噪声，不把玩家正常作战的每一击都变成惩罚。

| 警戒 | 环境反馈 | 既有敌群的反应 |
|---|---|---|
| 0 | 只有远处矿灯与活动声 | 矿兽保留原巡行，玩家可观察后通过 |
| 1 | 壁缝传来刨地声 | 最近的一组矿兽向声源移动 |
| 2 | 上层横梁出现落尘 | 副井守敌提前转入连接廊，堵住一条较短路线 |
| 3 | 主井出现连续回声，入口已明确说明会惊动深处敌群 | 启用名册中剩余的一组追击者；整场只触发一次 |

玩家也能主动敲击两处共鸣矿架，把已经苏醒的矿兽引离狭窄位置。警戒本身不随等待自动清零，已经引出的敌人保留实际位置与生命。全部反应来自有限名册，不额外无限召怪。

### 5.3 泵站的必需战斗

恢复`hoist`卷扬与排水之前，需要清除泵站守矿兽：一只精英荆背獾和两只普通矿兽。精英沿既有刨地、锁向冲撞与收招机制扩展，新增对两处松动矿柱的碰撞反应。

玩家可以直接侧后攻击，也可以把冲撞引向矿柱。命中矿柱会短暂卡住它，给出约三秒输出窗口；同一矿柱只提供一次这样的机会。矿柱变化限制在作者声明的构件内，不造成整片随机塌方。

泵站守敌全部清除后，修复操作累计约八秒即可完成；单次操作可中断，已完成的阶段保存。之后排水露出通往`blast`的入口，玩家取得封矿层的本轮核验标记。

其余遭遇包括矿口的一名劫修与一名灰符术士、排水支路的一只灯孢妖，以及警戒触发的两只预置矿兽。它们不会全部同时压入泵站，活动数量受共同上限约束。矿口守敌可以绕过，泵站战斗必须完成。

### 5.4 拿矿核之后怎样撤离

`core`中的矿核装入本轮任务匣。携带者移动速度暂降至85%，暂时不能御剑，仍可使用当前武器、身法、丹药与正常攻击。此限制只作用于本轮携核者，放到中转台或交给队友后立即解除。

矿核可以放到封矿石门、主井底、避难室三处有标识的中转台。单人可以先放下矿核清理前路，再回来取走；多人可以安排一人携带，其他人探路和接应，随时更换携带者。

`lift`升降台在排水恢复后可从井底接通。若此前已经清理追击者，回程不会为补足战斗数量再刷一波；剩余敌群会在已有井道里追来。升降台按一至四人的真实可站立平台设计，队伍可以分次运送，不要求全员同时踩点。

矿核持有者倒地、离场或掉线时，任务匣回到最近的合法已开放中转台，既有采矿与敌人状态保留。全队暂停也保存该位置，不会生成第二份矿核。成功必须是队伍完成泵站战斗、携带真实矿核通过撤离出口。

本关没有取核后的硬倒计时。风险来自准备不足、狭窄位置遭遇和携核机动下降。复玩变量是矿工标记指向的可用侧道、矿脉位置与有限敌群巡行，保留主井、副井和回程升降台的稳定结构。

## 六、藏书天井：唯一的纯解谜关

### 6.1 委托需要真卷和证据

书院留下四卷外观相近的《归流篇》，其中一卷属于委托要求的正本。玩家需要找出真卷，并提交来自西院、东楼和后库的三份校勘依据。找对卷与证明来源共同构成任务，战斗能力不会代替这两项工作。

该实例禁止自然敌对生成，不配置首领、守卷敌人或解错题后的袭击。错误不造成伤害。楼层通路使用正常楼梯、廊桥和可恢复的移动书架，不要求御剑或精确跳跃。

### 6.2 三处证据各自说明一件事

1. **西院修桥记录**：通过窗内图稿与天井另一侧实物对照，确定目标批次正本已经采用三孔新桥图记。图案旁附文字说明，避免依赖视力或特定视角精度。
2. **东楼入藏账簿**：将散落在同一阅读台的两张残页拼合，明确目标批次在修桥后第二年封存。拼合按清楚可辨的边缘和页码，不靠极小纹理猜测。
3. **后库装订记录**：查看装订样本，得知这批正本采用三钉装订，双钉为外借副本。样本可以右键查看近图和文字解释。

三份依据各登记一次，队伍共享调查事实。玩家可提前找到并携带候选卷宗，最后在`seal`校勘台提交真卷和已经核对的来源。正文不要求玩家输入长篇文字或记住无关年代。

### 6.3 一组完整、可验证的题目

| 候选卷 | 图记 | 封存年代 | 装订 |
|---|---|---|---|
| A | 旧单孔桥 | 修桥后第二年 | 三钉 |
| B | 新三孔桥 | 修桥后第二年 | 三钉 |
| C | 新三孔桥 | 修桥后第五年 | 三钉 |
| D | 新三孔桥 | 修桥后第二年 | 双钉 |

三条证据共同指向B。每少一条依据，都仍有两个候选符合已知条件，因此三处调查分别提供实际信息。玩家的行迹页可以并排查看已经记录的事实，最终由玩家选择卷宗，界面不提前高亮答案。

正式题目不固定把B放在同一书架。首版采用四组经过审校的正本条件：三孔图记固定，封存年代在修桥后第二年、第四年中选择，装订在三钉、四钉中选择。每组都生成三个分别只改错一项特征的副本，再打乱四卷摆放位置和外部编号。旧桥图记、比目标批次晚三年的封存年代、双钉装订分别作为该项的错误值。

因此首版共有四组题目、每组24种卷位排列。三处记录、书院实物样本和候选卷必须同源生成；不能只改答案而保留另一组提示。正确标记只保存在服务器，不把答案字段传给客户端。

### 6.4 检索、运输和错误反馈

西院卷架保留一条较宽阅卷道和一条可移动书架后的夹道。玩家在明示的轨道端点推动书架，一次只移动到下一个固定位置；运行前检查玩家位置，不能把人封入墙内。书院高廊可以从上层看到候选架所在分区，地库承担送卷返程。

取下卷宗后，原架位留下空位与书签，任务记录保存该卷的唯一身份。放回、交给队友或放到阅读台都不会复制卷宗。跌落和掉线采用共同任务物恢复规则。

提交错误卷宗时，校勘台指出一条具体矛盾，例如“此卷封存年代晚于入藏记录”，并退回卷宗；不销毁证据、不关闭已经打开的通路。没有尝试次数用尽的死局。第一次错误会取消本轮“首次辨卷正确”的小额额外奖励，基础完成奖励保留。

玩家可在行迹页请求逐级提示：先提示需要比较的内容，再提示证据所在楼层，最后明确解释正本应具备的三项条件。前两级提示保留额外奖励资格，使用最终解释只取消该项额外奖励；基础奖励和后续尝试均保留。

成功条件是三份来源已核对、正确卷宗交入校勘台、队伍取得封存拓片并撤离。复制的书、同名普通物品和先前实例的卷宗均不能交付。全程没有必需战斗，也不因快速完成或误解题目临时增加敌人。

## 七、沉炉工坊：冷却准备、炉兽战与撤离

### 7.1 开机前可以充分准备

委托目标是回收主炉中的旧器匣。入口告示直接说明：主炉开机和取匣后才有炉压危险，先把冷却水路与检修廊准备好，能显著降低风险。

玩家先从料轨和铸模间观察两个旁炉，查看阀门、总冷却管和排烟检修图。西侧遇到一只吞火蟾与一只赤甲蜥，东侧遇到一名灰符术士与一只赤甲蜥，两组分别占据对应阀房。清除后获得阀房操作权，可以关闭旁炉。

两处旁炉都关闭后，玩家能接通`control`的主冷却管。`water`分水房还能提前修好一段检修廊，开启更短的撤离路线。玩家也可以提前开机，边战斗边完成剩余准备；开机界面明确显示当前未完成的项目和后果。

### 7.2 炉压的阶段规则

炉压使用同一条0—100刻度，界面同时显示当前变化原因。场景中的铜管排气、炉口颜色和阀门声音提供相同信息。

| 阶段或行为 | 炉压变化的设计起点 |
|---|---|
| 尚未开机 | 保持20，不自行计时 |
| 主炉开机 | 至少升至40，唤醒炉兽 |
| 开机后 | 每10秒增加4；每一座未关闭的旁炉再增加4 |
| 接通总冷却管 | 每10秒降低6，最低维持20 |
| 炉兽把余焰打进标记炉槽 | 增加8；普通受击和玩家每次施法不逐次增加 |
| 炉前手动冷却喷射 | 每次降低15，约15秒后可再次使用 |
| 取出器匣 | 进入撤离阶段；初值至少40，之后每10秒增加5，原主冷却回路失效 |
| 撤离廊的三处应急阀 | 每处本轮只用一次，每次降低20 |

60开始出现明确标记的局部喷气，85进入危险提示。达到100时先自动卸压一次，退回55，并把器匣标记为受损；再次达到100则器匣毁坏，本轮主目标失败。任务失败后停止继续累加危险，保留正常撤离，不把失败转成必死场面。

这些是首轮调试数值。取匣后的已修复短路应能在约90秒内步行通过；未修短路的玩家也有应急阀延长时间。实际路线耗时必须用生存移动验证后调整，不能只按直线距离估算。

### 7.3 主炉战斗如何利用冷却设施

主炉炉兽采用赤甲蜥身体为基础，保留正面护甲、侧后攻击价值与尾扫，新增本关的余焰和冷却反应。它占据`main`周围可完整绕行的环廊，不把战斗压在一条只能前后移动的窄桥上。

炉兽有三种主要招式：

- **锁向喷吐**：先抬头蓄热，再沿明确方向扫过一条通道。命中标记炉槽会提高炉压，玩家可用既有耐火挡板阻断；挡板只在两个固定轨位之间移动。
- **前扑与尾扫**：前扑锁向后可绕到侧后，尾扫有抬尾提示，保持远近打法各自的安全位置。
- **贴炉回热**：生命约30%时尝试贴近主炉。玩家可在其经过冷却槽时启动喷射，令它短暂失衡并露出腹部。回热只改变招式与站位，不直接回满生命，也不让它无敌。

玩家可以直接从侧后作战；冷却喷射能额外创造窗口。抗火药效减少实际火伤，但不会替玩家操作炉匣冷却系统。喷射和挡板都可由单人短操作完成，不要求两处开关同时按住。

首领增援只有两只开本时登记的吞火蟾，分段出现，整场不超过一次。玩家若在外部检修侧道先发现并清除它们，主炉战不再补造替代者。

### 7.4 取匣、撤离与失败

炉兽死亡、两座旁炉关闭、主冷却管接通后，`core`才允许取匣。任务匣作为队伍物件跟随持有记录；玩家仍可正常战斗，器匣落到已开中转位时炉压继续推进。

取匣切断主冷却回路，入口清楚提示转入排烟廊。去程下层逐段关闭几处带有警示的炉桥，关闭前确认无人站在会收起的段上；上层`vent`、`chimney`、`escape`与山壁回梯提供始终可达的撤离链。

已经开放的应急阀不会因持有人倒地或换人而恢复。倒地使器匣回到最近检修中转位，炉压继续；全员离线则按共同规则暂停。受损器匣仍可完成委托，但取消完好回收额外奖励；器匣毁坏后可使用已经找到的本轮恢复用品撤离，收获袋不转为永久物品，不领取目标奖励和首通奖励。

本关支线包括废铸模库与旧器物库。可选探索主要放在开机前，避免把第一次玩的玩家用不明提示骗进倒计时。

## 八、风隙渡口：战斗中的搜救和路线准备

### 8.1 两名探路人的状态不同

千机阁的两名探路人被困在峡谷两侧。西壁探路人腿部受伤，行动较慢；东壁探路人能正常行走，并留下关于跨峡桥与洞道的线索。两人的姓名和短篇经历来自本轮故事模板，状态与实例绑定。

先查看渡口的两条求救信息，然后沿西岸或瀑后路线进入峡谷。营地中的守敌必须清除后，对应探路人才同意离开。两名人物可以分次送回，先救出一人不会自动结束另一条支线。

| 遭遇 | 配置 | 与救援的关系 |
|---|---|---|
| 西壁营地 | 两名荒岭劫修 | 必须处理，才能接走伤员 |
| 东壁悬营 | 一名灰符术士、一只寒翎雉 | 必须处理，才能接走另一名探路人 |
| 跨峡回程 | 两名劫修和一名术士的有限伏击组 | 站在已声明的藏身处，修桥前可以侦察和提前清除 |
| 洞道支线 | 一只灯孢妖 | 清理后形成较长但少受远程攻击的回程选择 |

只救一人的部分结算也必须完成其营地战斗。本关的战斗不会因队伍选择部分救援而全部消失。

### 8.2 修桥和洞道各有什么价值

跨峡桥较短，伤员少走一段路，但桥面暴露，适合先清除两岸远程守敌。三个修桥槽共需六份本轮桥材，西壁营地提供足量材料；玩家也可用自己的合格木板替代，服务器只在对应槽位完整提交时扣除。

回水洞道较长，转角提供掩护，但需要先清除灯孢妖并处理狭窄段。玩家可以侦察后决定使用哪条路，也能先修桥、发现压力过大后改走洞道。基本任务不要求购买解毒丹或使用某种身法。

风口的扰流区域有可见风标和提前提示，只在指定峡段生效。两条步行路线都不要求玩家背着人物飞行或在空中托举角色。

### 8.3 护送指令和救治

玩家在有效距离与视线内，可对人物使用“跟随”“原地等候”“到前方避风点”三个指令。避风点是有实际石壁或屋顶遮挡的地点，敌人是否能击中仍取决于真实遮挡。

人物沿预先验证的节点廊道行走。落后玩家约12格时会呼喊并停下，玩家回到约6格内继续带路。伤员以较慢速度移动；正常探路人可以带到下一避风点等候，允许玩家先清理前路再返回接应。当前带路者离场或掉线时，人物就地转为等候，临近队员可以接手，不继续追逐已消失的目标。

人物的临时状态为受困、跟随、等候、倒地、已救回、失救。敌对攻击可伤害两人，队伍自己的误伤不扣这两个本轮救援角色的生命。

人物前两次濒死时倒地20秒，玩家可用本轮包扎品持续救治三秒，也可消耗自己的养元丹。两处营地各提供一份本轮包扎品，足够分别救治一次。超过倒地时间未获救，或同一人物第三次濒死时，该人物记为失救。

导航卡住、错踩寻路边缘或模型挤入方块不应触发失救。系统先在本段寻找合法站位；仍无法恢复时退回该段上一安全节点，保留原伤势、不给出路线前进或救援完成记录。不能靠自动传送把人物直接送到终点。

### 8.4 部分完成与完整完成

每名人物抵达渡口后单独登记“已救回”，并退出战斗风险。救回第一人后，玩家可选择继续救援或按当前结果结算。两人都救回才算完整通关并开放首通奖励；一人救回只发半额基础报酬。

人物失救的原因与名字写入本次行迹，下一实例重新创建本轮人物，不把主世界里某个真实居民反复搬入和复活。正式实现中，实例剧情人物仍必须经WorldSim门面登记、迁移、撤回化身与归档。

完整成功要求两人实际走到渡口并有合法队伍成员撤离。部分成功要求至少一人已救回，由离场成员个人明确确认并冻结自己的结算，其他成员可以继续。两人都失救、全员失去资格或主动放弃则失败。旁路敌人不因玩家开始护送而在人物身边突然补刷。

复玩可改变两处营地谁受伤、敌人有限巡行和伏击组所在掩体，桥与洞道的基本位置保留。任务文本、人物表现和本轮记录必须对应真实状态。

### 9.2 支线与表现奖励

支线容器和允许采出的材料按每名成员的独立收获预算生成，敌人不另外掉落一套可重复拾取的永久物品。开本时固定生成结果，打开容器只改变同一份记录；队员的收获袋分别结算，不由最后一击者独占。

额外灵石最多为基础灵石的25%，向下取整，不提高声望或贡献。每图只设一项清楚的加成条件：

- 旧寨：核对踪迹并利用引导钟声完成追猎。
- 古祠：取得完整维护记录，并在无人被水位变化逼入救援的情况下取匣。
- 矿井：带出避难室的矿工记录，并将警戒控制在二级以内。
- 书院：三份证据齐全、第一次交卷正确且未使用最终答案级提示。
- 工坊：器匣完好，未触发自动紧急卸压。
- 渡口：两名人物都救回，且没有进入过倒地状态。

这些加成条件都在接取或行迹说明中可见，不以隐藏成就惩罚首次游玩的玩家。主目标完成后仍然发放基础奖励。

### 9.3 交付和重复游玩

完整奖励需要成员进入过本关关键区域、参与过调查、机关、有效战斗、救援或有效支援中的至少一项，并成功撤离。倒地后被正常救起仍可合格；强制撤离和始终未参与的成员没有完整结算。

成功撤离时先保存完成回执和收获袋结果。千机阁签发的委托可以到任一已登记分阁交付，记录仍属于原签发委托；宗门签发的委托在本宗宗务堂交付。该规则只用于新增远征，原三种江湖事务继续按原榜交付。

在未结算期间退宗、被逐或原宗门灭亡时，保留已取得的物资与首通资格，转为千机阁的协助结算，只发冻结的灵石和物资，不发宗门贡献，也不补发江湖声望。已经提交完成的奖励不因事后退宗再次计算。

背包满时，未领物品保留为外部持久回执，界面显示待领；不能先清除领奖资格再尝试塞入物品。实例可以在回执持久化后回收，玩家随后到相应设施继续领取。

远征允许重复进入，不新增每日打卡要求。重复通关获得固定基础报酬和有限材料，首通奖励只有一次。控制收益主要依靠真实目标、有限收获和完整撤离；后续平衡比较单位游玩时间的收益，不靠无限刷怪或重进重置容器维持奖励。

## 十一、实现职责与持久化边界

- [QianzhenRealms](../../src/main/java/com/example/myvillage/story/realm/QianzhenRealms.java)可参考归属、返回点、分批建场景和重启恢复。阡镇是持久个人剧情秘境，新增临时远征要有自己的实例身份和回收状态，不删除或重置阡镇目录。
- [EconomyMenu](../../src/main/java/com/example/myvillage/sim/runtime/economy/EconomyMenu.java)提供实际设施与菜单请求校验、背包事务及奖励入口；新增远征回执和首通资格仍需独立实现。
- [WorldSim](../../src/main/java/com/example/myvillage/sim/WorldSim.java)继续作为命簿人物修改门面。本轮探路人使用实例专属剧情键，化身只负责实际身体投射。

### 11.2 新增的权威与数据

新增远征服务拥有实例编号、名单、签发来源、阶段、机关、遭遇名册、任务物、收获袋和保留期限。玩家的修炼档案仍由CultivationService拥有，远征不保留第二份境界、功法或灵力档案。

入口与续玩状态按准备、生成中、可进入、运行、暂停、目标达成、撤离、结算中、可回收、已删除保存。目标达成后仍可能在炉压撤离或护送中失败，不能提前发奖。每次转移先保存目标状态和返回点，再传送玩家。

机关输入只表达意图，如选择闸位、推动某一架、接通指定阀门；服务器检查实例成员、距离、视线、冷却、当前状态和目标是否存在。客户端不提交“已击杀”“已救回”“答案正确”或直接增加奖励。

战斗完成只接受本实例绑定目标的真实死亡或明确作者声明的击败事件。关卡机关伤害、兽招和环境各保留真实来源；不会把附近的环境伤害按某个首领境界二次放大。首领与援兵绑定身份在卸载时继续存在，未收到击败事件时保留未完成状态。

受限地形编辑先核对当前方块、修改范围和站位，再提交有限变更。闸门水位用预制受控区域和明确的流体边界，避免靠大范围原版流体更新承担解谜状态。

临时剧情人物通过WorldSim新增的实例角色生命周期接口创建、保存和归档；关闭实例先撤回其化身，清除所属生活场所与租约，再处理世界目录。接口需要补齐，当前个人秘境代码并没有现成提供临时人物回收。

敌人、机关、线索、掉落与奖励只由各自作者配置拥有。本文数值是设计建议；落地时一次性迁入正式作者数据，运行时和预览共同读取，文档改为引用配置，不维护第二套常量。

### 11.3 关键异常的确定处理

| 情况 | 必须得到的结果 |
|---|---|
| 队长掉线，其他成员仍在 | 已冻结队伍继续运行，在线成员可操作本轮设施 |
| 全队掉线后重启 | 同一实例与同一敌人状态恢复，暂停阶段不偷偷推进 |
| 暂停超时，玩家随后登录 | 返回已保存外部安全点，说明本次已过期，不自动创建替代本 |
| 两人同时取匣、拿真卷或交接矿核 | 同一任务物只有一次所有权变更，另一请求获得当前状态 |
| 两人同时推动机关 | 按服务器状态版本串行提交，材料与冷却各结算一次 |
| 奖励满包或玩家在交付中断线 | 完成与待领奖回执保留，重连不丢失、不重复 |
| 首领区块暂时未加载 | 不补造首领，不重置生命，不判定通关 |
| NPC导航失败 | 停止或退回当前段合法节点，不推进救援、不直接判失救 |
| 清理时仍检测到玩家或打开的世界存储 | 延迟回收，记录原因，禁止直接删目录 |

## 十二、实施顺序与验收目标

### 12.1 建议先后顺序

1. 先做共用实例、名单、任务物、回执与回收，再完成断崖旧寨的一条完整可玩流程。这个切片必须能接取、进本、真实作战、撤离、领奖和保存恢复。
2. 做古祠与书院。古祠验证可逆机关与战斗结合，书院验证三条证据、唯一答案以及无战斗的完整流程。
3. 做矿井。重点是可破拆区域、有限警戒、任务物交接、携核移动与升降台。
4. 做工坊。重点是主动启动危险、冷却反馈、局部路线变化和目标达成后仍需完成的撤离。
5. 做渡口。重点是实例人物生命周期、单人指令、导航、救治与部分结算；使用已稳定的其他基础设施。

这套顺序属于后续实施安排。本轮只交付设计，不修改Java、地图作者JSON或正式资源，不把文档提交计为关卡已完成。

### 12.2 每关应观察到的玩家行为

- **旧寨**：玩家根据本轮真实踪迹找到首领，钟声确实改变其下一段路线；没有收集线索而直接击败真实首领也能结算。
- **古祠**：玩家可从多种错误闸位恢复；水轮、配重和匣座表现与保存状态一致；正常步行解法和水下观察路线均不出现死局。
- **矿井**：短道破拆会提前引来名册内敌人；反复制造声音不会无限出怪；携核与交接、倒地恢复、升降台都可由真实输入完成。
- **书院**：完整线索只有一个正确候选，每少一条线索仍有两个候选；错误和提示不生成敌人、不损坏已开路线；正常玩家操作无法触发战斗内容。
- **工坊**：准备冷却设施确实降低战斗压力；炉压原因可读，取匣才启动撤离阶段；一次卸压可恢复，二次超限明确失败并仍可离开。
- **渡口**：两种路线、先去任一营地、人物等候与救治都能单人完成；两人实际到达才给完整首通，一人获救按半额合法结算。

### 12.3 技术与人工验证分开记录

纯逻辑先检查机关状态可达性、题目唯一性、奖励一次性和失败恢复。地图生成再检查所有必需通路、门与水体变化、敌人及人物碰撞空间、任务物安全节点和活动数量上限。

需要游戏运行时，使用固定源在Colab做受影响的服务器、客户端与重启检查。必须通过真实映射输入触发开关、战斗、搬运、护送和交付；管理员命令只准备场景与读回。多人至少覆盖两个真实客户端，分别验证共享机关、独立奖励、掉线和重返。

记录每次选择、完成、失败与未运行的场景。视觉、战斗手感、谜题是否易读、NPC是否烦人、首次实际耗时和玩家设备FPS分别等待人工确认，不能由脚本通过代替。
