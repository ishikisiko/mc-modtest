# 八城官道路网

0.124.1 在全网路线确定后统一处理交汇节点。三岔和十字节点从实际路线邻接关系识别，近邻分岔合并为同一枢纽，普通弯道保持连续道路。节点先在参与路线允许的公共用地上选择削角平台，再统一求解新路网标高，使高差在外围引道过渡。原有通行面、城门和土方界限继续作为硬约束；平台与外缘逐列沿用原路线的城市、宗门、避让区和水深限制。平台可以在许可范围内有限移位，按实际汇入道路宽度保留交汇通行面，主干五格、宗门支路三格；场地较小时按配置收小。相邻平台与引道共同传播标高上下限，求解失败保留具体约束来源。石缘和护栏最后沿合并后的外轮廓生成，通行面内不增加障碍。

枢纽尺寸、合并距离、中心搜索范围和数量预算归 `config/roads/prototype.json/network/junctions`。当前默认三岔平台十一格、十字平台十三格；受限处可收至七格。整理发生在新区块施工前，已有玩家世界的道路不回填。道路缓存格式为 3，保存实际平台中心、宽度和标高，并校验完整平台；本次请使用新修仙世界。

0.113.0-fix1 将陆地省城的地形锚点限制在自然地表与海面中的较高者，避免把城市按海底高度落位，造成城门与道路海面接坡约束互相矛盾。城市仍使用原有平面位置、完整地形和局部标高输入。

本版保留普通过境点和城外接坡点的必经位置，取消它们在天然地表高度上的硬性锁定。这些路点尚未施工，路面高度应当在原有土方范围内求解。真实城门和已有通行面仍锁高，完整五格路面与半砖坡度检查不变。世界生成开始和官道绑定时记录种子、规则及布局摘要；失败信息包含具体寻路段。

每座城先规划一段公共接坡，确定完整通行面及城外连接点。同城的各条官道共用该接坡，从外端分岔；主路不能在陡坡中途重新接入。接坡、主路和宗门支路共用地表及高度约束采样，主路搜索仍扣除两端接坡已消耗的展开数与改道次数。终点标高区间为空时直接报告输入矛盾，避免无效展开。

0.112.3-fix1 为主干和宗门支路增加完整路幅高度冲突的重规划。规划器会记录相互矛盾的高度约束来源，在 `network.grade_replans` 的次数限制内选择绕行路径。全部尝试共用原路线的寻路展开预算，过境点仍受正式关隘与州界权限限制；城门、地块、整幅路面、土方和半砖坡度检查继续执行。不可行时仍明确失败，不保存缺路的布局。

新世界的宗门选址会同时检查双方完整缓冲，并在山门走廊外留出转向空间，避免后选宗门把已有出口封住。转向空间按现有 `structure_buffer` 计算；不合格候选地在选址阶段重选，道路仍遵守原有地块权限。

0.111.0 在八城主干网上为全部宗门预留地添加三格支路，终止于各自声明的山门入口。支路保持本州范围，使用主干的通行面锁高与路口合并，不进入宗门内部；没有安全连接就让整张规划明确失败。原有四个规划聚落仍没有专用支路。路网格式更新，请使用新修仙世界。

0.107.0 在新建修仙大陆时确定八座省城的官道路网，路面、基础和护栏随所在区块一起生成。大陆仍按探索加载；创建世界不会强制生成整张大陆。魔域经唯一正式关隘接入，四个规划聚落目前没有专用接入支路。

首次生成需要计算整张路网；规划在独立线程运行，不访问游戏区块。完整布局按区块压缩后随生成器保存在 `level.dat`，再次进入世界直接读取并核对世界、道路配置和布局摘要。规划无法连接全部省城时会保留原因并让本次生成失败，不写出半张路网。

## 生成顺序

1. 原有地形、城市地基及洞穴雕刻完成。
2. 直接向当前生成中的区块写入道路基础、路面和护栏，不经过 `ServerLevel.setBlock`，不触发普通邻居更新或方块掉落。
3. 树木、植物等装饰的起点进入道路实际写入范围时整次取消，避免只过滤下部写入而留下悬空树冠；邻区装饰与矿脉直接写入也遵守相同三维预留。
4. 与道路实际施工体积相交的结构，在生成前按结构部件三维边界避让；完全位于道路基础以下的结构不因水平投影重合被排除。
5. 装饰结束后只在当前生成区块重申路面；生成工作不写入相邻区块，也不回填已经生成的玩家世界。

不依靠关闭 `doTileDrops` 或删除物品实体掩盖掉落。原有城体、城门和城内通道保持只读；仅正式城外接坡范围允许道路写入。道路仍采用 A 青石官道：中央五格完整通行面、石缘与有界缓坡；护栏限于临崖、临水和高路基危险边缘。

## 查看和检查

新世界无需执行修路命令。

```text
/myvillage roads status
/myvillage roads export
/myvillage roads audit
```

`status` 显示布局计算、已规划路线和当前加载的道路区块。加载区块数不是整张大陆已经生成或玩家已经走通的证明。`export` 导出世界目录下 `data/myvillage/worldplan/roads.json`；`audit` 只读检查当前已加载道路区块，未加载项明确保留。

管理员可显式预生成并逐区块检查整张道路范围（包括城门）:

```text
/myvillage roads pregenerate
/myvillage roads pause
/myvillage roads resume
```

`pregenerate` 会生成缺失区块并读回道路；已生成区块只读，不会覆盖玩家改动。报告保留实际路面、基础、护栏、净空、只读城门差异与观察到的掉落物数量，写入 `roads-audit.json`。管理员预生成任务的游标仅在当前会话有效；区块本身与路网布局正常存档。重启后可重新检查，已生成区块不会重新铺装。

## 当前开发边界

本版检查应使用新世界。已有世界中的已生成区块不自动改造，旧的事后铺路入口已停用。当前没有全路程玩家行走、声音、FPS 或多人验收；生成、静态几何、原生读回与玩家接受度分别记录。

道路配置仍以 `config/roads/prototype.json`、`capital_zhongzhou_port.json` 和 `guardrail.json` 为唯一 authored 输入，正式出口由 `tools/gen_road_ports.py` 从当前城市资源生成。没有手改城市输出或改变已选道路样式。
