# 云山巨城 MC 化:搭建方案与分工(草案)

> 状态:草案,2026-10-04,待 owner 审阅。尚未立项,未进入 CRAFT run,未改任何受保护路径。
> 原作:分支 `origin/claude/voxel-cloud-mountain-city-2f0j1n` 的 `web/yunshan-city/`(three.js,0.2 米体素)。
> 工具:DevBridge 加创世神(分支 `build/devbridge-work-20260924`)。

## 1. 已定方向

- 水平 1 米 = 1 格。搬的是 plan 和高度场,不是 0.2 米体素。
- 大地形和重复落位用脚本。小而独特的东西由正常 agent 照着画。挑选类的事用规则,量大时才考虑决策模型。
- 降采样只当脚手架,必须带角色语义。细节在重建时补回。
- 提高手画比例:**手画模板和场景,批量只管落位**。
- agent 是开发辅助,不代玩。流程归脚本,模型只在写、看图、给失败分类三处介入。
- 验收以 DevBridge 真客户端截图为主,离线对比和本机无头近景为辅,Chunky 只在最后出美图。

## 2. 五类执行者

| 执行者 | 负责 | 不负责 |
|---|---|---|
| 脚本 | 导出、地形生成、模板落位、闸门检查、推送与回收、批量截图 | 任何审美判断 |
| 建造 agent | 写模板、写场景补丁、调材质表、写上面这些脚本 | 给自己的作品下结论 |
| 审图 agent | 对照参照图挑缺陷,另起会话,不看建造过程 | 改方块 |
| Commander | 派单、排队、路由、记证据、维护清单和锁 | 审美判词 |
| 你 | 方向决策、每批判词、想改时直接在游戏里动手 | 敲管线命令 |

建造 agent 对应 GenOps 里的 generator-engineer 和 java-worldgen-engineer。审图 agent 对应 visual-reviewer,主角构件再加 aesthetic-critic。落库归 resource-asset-steward,检查器归 validator-engineer,回归归 regression-steward。

## 5. 各阶段细节

### P0 地基

1. 归并两个分支。`web/yunshan-city` 并入 main 作为工具目录。DevBridge 分支有未提交的改动,需要提交并推送。两件都要你点头。
2. 做四件工具。
   - 推送:把仓库里的结构数据经命令推到展台,不重新打包模组。
   - 回收:分块读回展台上的方块,转成结构数据。目前仓库没有这条路。
   - 批量机位截图:隐藏界面,固定时间和天气,等区块加载完再拍,图存到本机。
   - 原作三视图:直接从体素网格做正交投影。原作自带的预览脚本太慢,不能用。
3. 展台约定。单独建一个开发世界,不用 dev1。平坦,按槽位编号成网格,每槽 64×64。agent 只许动展台。
4. 写 yunshan 风格档和一页风格指南:材料槽位、屋面做法、禁用方块。原版没有对应方块的东西在这里定,比如枫树的红叶。
5. 校准。先做 3 个样板把回路跑通:house_1 江南民居、house_5 徽派民居、summit_ting 揽云亭。你判过之后再放量。

### P1 导出

脚本一次跑完,全程无模型。

1. 按 1 米采样高度场,出 C1。范围先取城区加山顶加南崖,约 1200×1300 格。
2. 序列化 plan,出 C2。
3. 对 100 个构件定义逐个生成体素,按角色优先规则分格,出角色格和三视图,即 C3。
4. 闸门:同种子两次导出逐字节一致;高度范围装得进目标维度;每个实例都能找到定义。

### P2 地形

1. java-worldgen-engineer 写维度类型和区块生成器,读 C1 逐列填充。
2. generator-engineer 调材质对照表,把 29 种地表材质映射到方块,带坡度和海拔变体。这张表是照着画的,agent 对着原作地图的色调调。
3. 规则部分:水面向下挖 2 格床;瀑布面放下落水;台阶段按坡向放楼梯;城墙做垛口;台地挡墙贴石砖面;云海用白玻璃加细雪片。
4. 验收:与原高度场逐列比较,差值不超过 1 格;用 8 个名胜机位截图;你走一遍白模。

**单件回路**

1. Commander 派单。任务卡含:定义 id、角色格、参照三视图、占地和高度上限、风格档、要暴露的选项、展台槽位。
2. 建造 agent 写模板。从角色格出发,挖空,分层,开门窗,屋面换成楼梯和半砖,补檐口、脊饰、灯。写成结构数据或小生成器,不逐格下命令。
3. 离线闸门,脚本执行:
   - 占地与原定义一致,否则落位会和邻居打架;
   - 方块在风格档和模组集允许范围内;
   - 方块数在预算内;
   - 门是真洞,门外可达;
   - 室内净高至少 2 格;
   - 无悬浮方块;
   - 柱、檐、脊这些角色都有对应方块。
4. 推到展台,四个固定机位截图:正面、斜 45 度、俯视、人眼高度。和参照图拼成一张对比图。
5. 审图 agent 按缺陷词典挑错:轮廓、屋面曲线、比例、配色。主角构件再过一道 aesthetic-critic。
6. 不过就回到第 2 步,最多 4 轮。超出由 Commander 升级,换做法或交你定。
7. 攒够 8 个出一张总对比图交你判:接受、带修改接受、拒绝。你也可以直接在游戏里用创世神改,回收脚本把改动收回数据。
8. 接受后落库成 .nbt,记哈希,状态锁定。

**顺序**:先 3 个校准样板,再民居商铺,同时开主角地标,最后派生件和小件。

### P4 落位

1. 实例坐标吸附到整格。宅基垫块按吸附后的占地重新铺,不用栅格里的垫块。原作垫块是占地外扩 0.4 米,直接采样会错位一格。
2. 模板底到地面之间自动补台基。4 向旋转用模板自带的旋转。
3. 生成时按区块查空间索引,裁剪粘贴。
4. **基础落位不需要任何选择器。** 原作 plan 已经给每块宅基选好了户型,直接用。变体包和道具位是后加的,那时才需要规则或决策模型,结果冻结成 C5。
5. 闸门:实例数与 plan 一致;无重叠;每栋门前 2 格内接到巷道;从正阳门到揽云亭走得通。
6. 验收:8 个机位加漫游路线截图,与原作同机位并排。你判整城体量。

**单区回路**

1. Commander 定区:包围盒、机位、验收条件、方块预算。
2. 建造 agent 写世界坐标补丁,只能用封闭的操作目录:放模板、区内填充、连线、堆叠、贴补丁、撤销。
3. 闸门:不越界;方块合法;不超预算;不堵路;不碰已锁定的区。
4. 推到开发世界,机位截图,与原作同机位并排。
5. 审图,你判,通过后锁区并存快照。

室内放在这一阶段:5 到 8 个可进入地标各做室内,民居做几套室内预设。

### P6 精修

- 手工雕 3 处地形:南崖面、瀑口岩石、观瀑阁脚下的石柱。高度场表达不了悬空,这里补。
- 独特的树若干,由 agent 写小生成器做。
- 167 根灯柱接上光源,云海高度和雾色调参。

### P7 回归与发布

- 确定性:同种子重新生成,方块统计一致。
- 预生成耗时和帧率记录。
- 按 `openspec/config.yaml` 的规则:升版本号,产物落进模组资源,补命令文档。
- 你亲自登录走一遍,给最终判词。

## 6. 并行与排队

- P3 的模板互不相干,可以多个建造 agent 各领一组定义,在各自的 worktree 里写。
- 截图只有你那一台客户端,串行。按展台一排一批地拍,由 Commander 排队。
- P5 的十个区包围盒不相交,可以并行写,同样排队截图。
- 这台 Linux 机器一次只能跑一个 Gradle 或 MC 作业,无头回归也要排队。

## 7. 纪律

1. 只动展台和已派单的区。闸门拒绝其余一切修改。
2. 已验收的模板和区上锁,改它要先解锁并留记录。
3. 每轮操作可撤销,每个区通过后存快照。
4. 手工成果必须回收成仓库数据。只留在存档里的东西视为不存在。
5. DevBridge 只绑 Tailscale 地址,令牌不进仓库,不随模组发布。
6. agent 的截图是证据,不是判词。

## 9. 风险

- **占地漂移。** 手画模板一旦超出原占地,落位就会重叠。闸门第一条就查这个。
- **单客户端瓶颈。** 截图串行,而且那是你日常用的桌面。P3 放量时要约定时段。
- **塔。** 与进行中的 rebuild-pagoda-landmark 有交集,要先协调。
- **构建清理。** 每次构建会重新生成并清理结构目录,yunshan 模板要放独立子目录并纳入生成清单。
- **校验上限。** 现有校验器每轴 64 格的上限会卡住塔和观瀑阁,需要豁免规则。
- **流水物理。** 百米瀑布可能在区块加载时抖动,必要时预放稳定的下落水。
