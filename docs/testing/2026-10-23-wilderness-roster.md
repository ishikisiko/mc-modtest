## 已诊断的失败和复验

1. 初次构建中，旧测试固定了炼丹配方数 8 和协议 41；更新为实际新条目与协议 42 后，相关 378 项通过。
2. 初次药效使用断言混入之前生产的同种丹药；在每项服用前清空夹具背包后，六种丹药真实服用和药效状态均通过。丹方学习同时覆盖已学会时不再消耗的幂等分支。
3. 自然生成夹具第一次 `/fillbiome` 超过原版体积限制；分成 32×32 区域。随后修正成功回复解析（实际回复为 `biome entry/entries set between`）。这些失败不改变产品生成概率。
4. 原版刷怪计数曾达到 73，而可选中实体已为空；切换和平清理后计数归零并恢复原版刷怪。采样改为完整 256×256 可生成半径、100 TPS 和每 5 秒和平清理上限，以避免低权重场景的等待失衡；不调整产品权重。
5. 复用生产世界后，旧炉阵和鼎阵遮挡了战斗展示区。采集器现在只清空自有实验场，再重新准备场景；旧遮挡画面不作为最终模型展示。
6. 回灵测试的诊断狼曾因旧鼎阵／反击后玩家占位而无法放置；移开玩家、等待旧尸体消失，并对成功出生回复增加前置断言后复验。
7. 重启保留的回风剑阵使 H 面板卡片序号变化，导致通用元素采集器点到流云步；先移除测试用残留回风，再按真实 UI 分配并读取确切绑定，重跑 effects / observers，不重跑已完成的自然生成和重启。

## 证据边界

- 真实玩家行为使用映射键鼠。RCON 用于准备材料、调整夹具、定位与读取服务端状态。
- 战斗观察在 20 TPS；为便于观察先给玩家和目标增加生命。单独的掉落边界使用 `Health=1 / NoAI` 目标，再用真实剑击击杀；不把该边界称作平衡验证。
- 炼丹等待使用加速 ticks。两种直接来袭防御的精确时序边界允许署名 `/damage`；施法、连击和反击仍通过映射输入。
- 自然生成如通过，只证明受控群系夹具中的原版生成与出生境界保存，不能证明长期密度或所有地形适配。
- 玩家外观、手感、声音、FPS、长期平衡、全部多人组合仍为 `not_verified`。开发者画面与软件渲染不替代人工验收。
