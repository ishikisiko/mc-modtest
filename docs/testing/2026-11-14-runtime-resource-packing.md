## 原规划和实验的处理结果

本轮读取并核对五组分析与实验中的74个文件：`jar-size-20261114`、`jar-shrink-plan-20261114`、`component-analysis-20261114`、`component-reuse-20261114`、`component-java-probe-20261114`。原文件摘要保存在交付证据的 `prior-experiment-identity.json`。

- ZIP压缩等级与按需ZIP64已接入生产构建；分组GZIP的外层ZIP按实测选择更小的存储方式。
- 构件共享几何已覆盖七府和总舵。37,280个模型实例引用30,987份模板，减少6,293份重复几何定义；1,747份模板跨建筑共享，涉及5,286个实例。实例数包含注册组的填充槽。
- 原分组方案扩展到关联方块状态、物品模型、掉落表以及其余2,688个JSON、OBJ、MTL模型文件，保持原始字节。
- 全部8,371个结构NBT进入同一服务端读取体系，保持其原有GZIP字节及摘要。
- 全部1,643张PNG检查，275张获得无损压缩收益；过滤后的扫描行和非IDAT数据保持一致。
- NPC已有共享资源保留。三份字体及其配置沿用此前暂缓调整的决定。

此前Java模型描述实验提供了几何与实例参数拆分依据。本次生产实现恢复原JSON的完整字节，再交给已有模型解析和烘焙，状态映射、透明面包装、粒子材质及物品覆盖继续由原实现处理。需要改动建筑造型、梁柱尺寸和接头的进一步标准化尚未实施；这些改动需另行预览和确认。

## 保留的失败及现有问题

1. 最初扩大执行的 `DefaultManorCapitalTest` 有两项失败，已使用0.131.2原JAR复现：`currentDefaultReferencesSevenFormalManorsAndTheExistingZhongzhou` 预期256、实际352；`landCityAnchorsDoNotFollowTheSeabedBelowTheWaterSurface` 预期832、实际5088。原断言未改，失败XML及旧JAR类路径记录保留。最终43项定向检查包含本次直接相关的两个方法，未宣称整个历史测试集通过。
2. 修仙世界种子 `202611141` 的灵岳到魔域官道寻路失败：节点 `(-2864,5922)` 展开80,201次后预算耗尽。旧0.131.2在同种子实际启动并复现相同失败，日志和身份保留。本次未修改道路算法，该种子仍无法正常创建世界。
3. 正向修仙世界使用种子 `-6259944962606258298`，63段官道与矿脉规划完成后，首次在准备出生区时触及600秒启动预算；该次超时保留。确认进程及锁释放后，复用本轮独立世界继续启动并完成服务端、18类结构和客户端检查。
4. 一次结构fixture把1.21.1命令的实际成功响应 `Loaded template` 写成 `Placed template`，导致检查失败；修正精确响应解析后重跑通过，原失败保留。
5. 原生最后的广泛日志门将旧包已有的模型警告列为失败。与已验证0.131.2原生日志逐条规范化对照，两边各4,056条不同警告完全一致，无新增；实际F3+T及返回游戏已有记录。`native-v4/result.json` 与退出码1保留，另附 `native-acceptance-assessment.json` 写明依据，不改写原失败为绿灯。
6. 初次ZIP测试对极短GZIP样本的外层压缩判断有误；使用有效且有明确可压缩/不可压缩性质的两类样本后，原存储方式断言和内容检查均保留并通过。首次失败日志保留。
