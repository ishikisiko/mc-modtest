# 18 款亡灵细化与主世界开局交付记录（0.111.4）

## 改动

18 款行尸与骸弓均由原拥有者 `tools/beastgen/undead.py` 重新导出。各款的独立构件与造型说明在 `tools/undead_roster/appearance.json`，实体身份、战斗、出生、境界和掉落仍归原 catalogue。

骸弓使用中空头骨、深眼眶与鼻腔、独立上下颌、牙齿、肋骨、肩胛、脊柱、骨盆及双前臂骨；行尸使用凹陷面部、手指、收腰衣型、领口和袖口。八洲的布巾、盐壳、菌体、薄霜、藤根、浅浮雕与贴骨血纹具有真实厚度。材质按三维位置连续绘制，复用原有明暗素材；本轮没有调用图像生成，也没有增加渲染依赖。

模型按两倍单位导出，使用 `scale=0.5` 保持世界比例。待机不叠加手臂偏转，避免与攻击动画混合后改变放箭方向。既有动作时点、伤害与服务器权威逻辑保留。

新世界和新玩家首次加入默认留在主世界，登录不会创建秘境或排队传送。玩家按 H 打开“行迹”，点击“进入阡镇秘境”后才创建并进入；返回和再次进入继续使用原服务器检查与保存位置。进入不会接取任务。

## 保留的失败与处理依据

- R1：测试筛选参数误放在 `jar` 后，Gradle 将其当成 JAR 参数而拒绝执行。调整任务参数顺序后，原 47 项测试全部通过。
- R2：打包审计漏列 `QianzhenRealms$1.class`。该匿名类由本次修改的同一 Java 源生成；`javap -c -p` 的新旧执行指令完全相同，摘要均为 `f5c8851b8561a1c17a18e8615670e85e304c228501bcd4d87c66ce9235bcc944`。将这个精确类名加入审计，继续拒绝其他未声明变化。
- R3：原生采集器继承的客户端 `-Xmx1g` 在整包资源加载时触发 Java heap space，尚未进入世界，原生 completed=0。保留崩溃报告与日志，确认客户端及服务器结束后，改用 `-Xmx6g` 继续同一固定生产候选。
- R4：六项 H 菜单与生命周期检查完成，拍摄准备因目标区块未加载而失败，原始回复为 `That position is not loaded`。采集器改为先申请四个有界区块、确认地板及实体实际就绪，再保留原实体存在断言拍摄；此后完整六项记录在 `4983fd9e6` 重新完成。
- 侧视及体积复查：补齐肩关节、颅底、骶骨与髋关节连接，连接左臂藤蔓，并将完全埋入基础体块的盐壳、血纹、霜痕和云纹移到实际表面。新增连通性及外露回归检查，保留修复前失败日志。
- 首轮最终 JAR 三方向画面：渲染检查通过，但人工查看发现前一组死亡粒子遮住部分正面。原始画面保留，交付页面采用清场后的近距四方向补拍，不把首轮截图直接当成外观接受。
- 旧采集器失败时会让同一场景同时出现在 failed 和 unrun。保留历史原始数组，后续修正归类并增加两个负例，完成项不被重分类，失败与未运行项互斥。

每轮美术修整使用独立固定输入，模型变化后重新生成、检查、烘焙和采集。通过的结果仅在相关输入满足上述逐字节一致性条件时复用，来源与差异分别记录。失败日志保留在交付证据中，几何、状态与输入断言没有降低。
