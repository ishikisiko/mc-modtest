# 0.131.2 书册按位置生成的定向检查

本次只调整千机阁总舵的23组书架。木框、层板、梯子及位置继续来自原作者输入；书册以连续区域和配置规则记录，在客户端建立区块模型时按位置生成。实现见[功能说明](../features/procedural-bookcases.md)。

产品源码提交为 `4d080525e455c8a1727472da304f3c7be575f384`。后续检查记录的文档提交没有改变打包输入。构建使用源码归档 `5bfc4bc3b` 加该提交唯一修改的 Java 文件，上传前后均核对 SHA-256。Colab 复用了经过身份核对的依赖缓存和未修改生成资源；本次重新生成千机阁资源，并重导出了当前城市中的千机阁构件引用。

交付文件：[myvillage-0.131.2.jar](https://assets.ishiki333hhh.win/previews/procedural-bookcases-20261114/myvillage-0.131.2.jar)。SHA-256 为 `ecb70506b1e266669bf6ed53037452af95c56989827bef6dbe38e50bb4151ea9`。原始云端日志、测试 XML 和截图见[检查材料](https://assets.ishiki333hhh.win/previews/procedural-bookcases-20261114/evidence.tar.gz)。

城市摘要变化同步传入官道城市引用、冻结世界规划和世界预设。逐字段检查表明，这三个相邻资源只改变城市或资源包摘要，没有改变道路几何、地形规则或洲域布局。

本地27项 Python 定向检查、千机阁生成器 `--check`、语言资源检查通过。云端完成 Java 编译、20项定向测试及 JAR 构建；测试覆盖整数算法的 Python/Java 样本一致性、书册区域资源、四向选框、千机阁城市、原有玻璃层及可选加载。语言检查按当前源文件与 JAR 内容逐字节核对。

原生检查使用独立的平坦新世界，从当前正式中州城市切片提取一组书架，分别放置四个朝向。运行目录中的58,300个内容条目与交付 JAR 一致，其中包括2,402个类。`candidate_identity`、`native_model_load`、`four_directions`、`resource_reload` 均完成，`failed=[]`，`unrun=[]`。F3+T 经映射键盘输入触发，完成资源重载后继续显示书册，模型日志没有书册加载错误。

四向画面和重载后画面属于 `captured_for_review`。软件渲染环境的截图已由开发者查看；玩家外观接受、行走手感和实际硬件FPS仍为 `not_verified`。本次没有执行战斗或其它玩法验收。测试客户端和显示进程已结束，服务端正常保存退出，世界锁及两个服务端端口已释放。

保留了两次云端构建失败：首次为旧缓存缺少当前依赖，补齐后继续；第二次为定向构建脚本将资源路径解析到错误目录，语言检查拒绝了不完整包。修正绝对资源路径后通过，失败包没有交付。最终源码补齐物品模型覆盖规则后再次完成上述20项测试和构建。
