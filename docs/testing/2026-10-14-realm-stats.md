# 境界数值与区域野外：验证记录（2026-10-14）

目标版本 0.47.0，基础提交 `414d0d0`。原始证据保留在忽略目录
`reports/realm-stats-20261014/`、`reports/release_gate/` 和
`out/preview/realm_stats/attempt-{1,2,3,4}/`。本报告记录开发验证，
玩家手感、普通地形的遭遇密度和双人验收仍为 `not_verified`。

## 环境与测量边界

Linux 6.8、4 个可见 vCPU、7740776 KiB 内存，Temurin 21.0.11、
Gradle wrapper 8.10.2、Minecraft 1.21.1、NeoForge 21.1.233。
Python 回归使用系统 `/usr/bin/python3`；需要 numpy/Pillow 的预览测试
另用 `.venv-preview/bin/python`。Gradle 依赖、wrapper 和项目缓存已存在，
没有清缓存或测量冷启动。图形为 Xvfb + Mesa 25.2.8 llvmpipe
（LLVM 20.1.2），属于软件渲染，不能据此推断用户 PC 的 FPS。

Gradle/Minecraft 重任务顺序运行，共用 `/home/ubuntu/code/mc/.mc-heavy.lock`。
首次 Java 测试误用了仓库内同名锁，但当时没有并发重任务；随后统一到共享锁。
GNU time 的 CPU 是可等待子进程统计，最大 RSS 是观测到的最大单进程值，
**不是整棵 Minecraft 客户端、服务端和 supervisor 进程树的总峰值**。
客户端 join、ingame 与 setup 的 readiness 数字有重叠，不相加。

## 实际客户端与服务端证据

使用真实 Minecraft 客户端、映射鼠标输入、RCON 夹具与读回，无 DevBridge。
管理员设置境界、目标和抗性是测试准备，不代表玩家自然取得这些能力。

- 真实近战输入的结算为 `(10.5 + 2) × 0.9 × 1.5 × 2 × 0.75 = 25.3125`，
  服务端 trace 与目标实际损血一致。
- 原版护甲先把 10 降至 8，再经 50% 抗性得到 4；吸收盾在抗性之后消耗。
  10 点伤害、50% 抗性和 10% 穿透得到 6；未知 generic 伤害不误套物理抗性。
- 第一轮真实短按/满蓄剑气均命中通过，实际损血分别约 10.154 和 14.175；
  后续只重跑近战与新野外路径，未把跳过的剑气当作再次通过。
- 东海出现命簿人物 103、115 的散修投影；境界在区域范围内，身份不重复，
  区域上限、散修总上限和化身共享上限均满足。离开后投影撤回。
- 第四轮实际自然出生的妖狼为东海炼气五层（零基 stage=4），生命 126、攻击 7.2。
  它来自 biome 表的正常权重与 NATURAL 出生事件，不是 `spawn_test` 伪造。
  夹具设置普通难度、午夜并周期清理其他怪物，因此不能推断普通世界遭遇频率。
  真实刷怪表包含妖狼权重 8，方位的 placement 条件通过。
- 跨地区移动不重抽出生境界；诊断生成的高境界妖狼保持明确的 `natural=false`。
  数值抽样重复输入返回相同结果；图外和其他维度不虚构区域。

第四轮 25/25 检查通过，外层墙钟 220.87 s；CPU user/sys 为

## 失败与修复记录

| 尝试 | 墙钟 | 原因与处理 |
|---|---:|---|
| 重点 Java 首轮 | 18.69 s | 测试 bootstrap 缺少 LoadingModList 初始化；补齐后 31 项通过 |
| 客户端 attempt-1 | 284.77 s | 带冒号的 tag 不能直接作为 selector tag 参数；默认采集服务器禁用了自然怪物。伤害、剑气和存档检查已通过，整体仍失败 |
| 客户端 attempt-2 | 94.07 s | 刚召唤的目标尚未进入 entity ticking，属性/血量查询竞态；增加显式夹具区块和有界就绪等待 |
| 客户端 attempt-3 | 271.20 s | 给 tag 值加引号仍不符合原版 selector 解析；改用 NBT Tags 匹配。60 s 未观察到自然妖狼，保留失败，未宣称自然生成通过 |

第四轮进一步记录实际难度、亮度、刷怪表与 placement probe，并显式设置普通难度。
第三轮没有这些现场诊断，不能仅凭退出后 server.properties 的和平设置断言唯一根因。
实际命令检查还暴露 `stats growth` 的 word 参数不能解析名字空间 ID，已改用
ResourceLocation 参数，并重新完成 Java 全测与真实命令读回。
默认 Python 缺少 PyYAML 的编排启动失败改用系统 Python；未把失败当作正式运行结果。

## 未验证边界

境界差距的战斗手感、普通地形自然生成频率和可读性、两人去重/战斗观察、
真实死亡与末地返回交互、用户 PC FPS 均为 `not_verified`；生命周期策略有代码和
测试覆盖，但不等于这些场景都已在客户端观察。散修仍是无敌且不主动战斗的既有
命簿化身，本次未新增敌对 AI。元素抗性通道不意味着所有元素伤害来源已经接线，
身体功法效果依旧是数据；速度、护甲和灵力上限不做统一境界倍乘。
