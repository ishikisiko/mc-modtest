首轮路口画面未显示完整周围区块，随后在同一临时世界加载相关区块并补拍。补拍时真实缓存状态为 `cached`，布局摘要仍为 `4954724be120c79afdf68ed31b56ecf5abb27a5e45dec5df6366ff7aa1201e0b`；没有注入预先计算的布局。展示采用补拍的路口和府前俯视画面，已查看平台轮廓及台阶连接。补拍的正面机位进入了对街建筑，未用于展示；原图与回执仍保留。补拍与真实缓存重载检查为 `selected=2, completed=2, failed=[], unrun=[]`，这些状态表示采集及存取完成，不替代玩家接受。

## 保留的失败

- 初次相关 Java 检查遇到旧世界资源指纹断言。先核对资源差异和当前实际输入，再更新该断言的精确指纹；护栏高度与行为断言保留。
- 实际路网暴露了平台选址范围过窄。原实现把已铺方块列当成完整公共用地权限，平地窄路分岔无法扩宽。最终平台和外缘逐列沿用原路线的城市、宗门、避让区、水深限制，未放宽保护规则、通行宽度或土方上限。
- 三格宗门支路的交汇范围曾误按五格主干处理，现按实际汇入路宽保留完整交汇面。
- 重放 fixture 曾把只读城门楼梯也纳入新道路半格坡度断言。原始输入中已有 240 对此类门阶；最终逐列核对门阶原样保留，并约束所有新路列及其门阶接缝。
- 平台有限移位后可能改变坐标顺序，现统一结果及缓存中的实际坐标顺序，保留精确读回断言。
- 第一张实际新世界在路网完成后，因初始矿场 384 个候选耗尽而停止。修复将固定预算分配到整个允许距离内，并锁住所有既有道路列和矿口标高拟合短支路；原有距离、土方、护栏和保留区域检查不变。真实失败输入及原有矿场检查均已通过。Gradle 启动任务曾返回 0，仍按服务器异常和缺失回执判定该轮失败。

原失败日志、JUnit、两份完整输入和后续成功结果保留在 `reports/road-hubs-implementation-20261109/`。

道路缓存格式为 3，保存实际枢纽中心、半径和标高。本次应新建修仙世界；旧世界不做回填或迁移。
