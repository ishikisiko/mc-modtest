# 出生省城的 NPC 入门

0.113.0 在修仙大陆的出生省城接入第一批 NPC。出生省城仍由当前世界计划的 `spawn.regionId` 决定，不另存一份出生城选择，也不改城市建筑和地形。

## 四名居民

`story/capital_opening.json` 声明向导、客栈当值者、药铺伙计和铁匠的初始人物资料、床位与岗位。坐标来自本世界实际使用的 capital bundle。西漠向导使用城门附近的现有住处；中州的入口命名由同一配置覆盖。

`NpcLifeSites` 先登记出生城，再经 `WorldSim.ensureCapitalResidents` 一次性预留身份，无须等商店区块加载或先找到闲置散修。整组在写入前核对岗位、床位容量、距离和人物 ID；已有本城同职居民可沿用。命簿 life schema 4 的 `capital_residents` 保存角色到人物 ID 的关系，WorldSim 格式为 12。重进、死亡和离岗不创建替身。

这四人是普通居民，使用原有白天上岗、夜间回家、战斗、成长和化身规则，不使用阡镇剧情保护或固定社交姿态。其他城市仍按原有空缺规则招募。化身只在满足原有加载、位置与执行权条件时出现；岗位已登记不等于玩家已经看到本人。

## 玩家如何开始

所有世界类型中的玩家首次登录时都会获得初始食物。`StarterSupplies` 在服务器登录事件发放原版熟牛排，默认数量为 16，由服务器配置 `myvillage-starter-supplies-server.toml` 中的 `cookedBeefCount` 控制。领取记录保存在每名玩家的 `starter_supplies_received` Attachment，并通过 `copyOnDeath` 保留；重连、服务器重启、死亡和换维度均不重发。背包放不下的部分按原版逻辑掉在玩家脚边。该物资与城镇教学进度无关。

玩家主动与四人交谈；入城口的向导介绍客栈、药铺、铁匠及其实际坐标。交易继续沿用现有报价、库存、营业与背包校验。

未学会基础吐纳的生存玩家可以向药铺接受试种。药铺一次提供配置数量的灵土和种苗，玩家在本州城界外的配置范围内自行选空地试种，完成后回来测灵和学习吐纳。地面可铺灵土，再在其上播种；运行时不会替玩家铺地或改院落。数量、物品和范围只由配置提供。

每个玩家的 `capital_opening` Attachment 独立保存所绑定城市、阶段、修订号及不同播种坐标，并通过 `copyOnDeath` 保留。材料先完成整个背包写入计划，再和接受回执提交；背包不足不接受也不发放。完成后没有物品领奖入口，也不会重复发种苗。

播种只接受本人生存放置、原位置为空、指定幼苗和灵土、范围正确的事件。tick 末再次检查取消、同 tick 后续破坏或替换以及最终方块状态；复用阡镇的 `PlantWitness`，不给其他玩家或被撤销的播种记功。不同玩家的记录互不推进。

教学调用现有 `SpiritualRootAwakeningService` 和 `TechniqueInheritanceService`，修炼档案仍只经 `CultivationService` 安装。原有灵根不重抽，已学吐纳跳过试种与教学；已有真实修炼经历的玩家直接视为已入门。普通或灵石打坐实际结算成功后，记录首次练习完成。选择天命仍通过现有测灵碑入口。

首城对话复用 NPC 共用纸页和一次性会话，额外把个人进度修订号绑入身份。客户端不能指定完成数量、教学结果或下一阶段。阡镇个人秘境章节继续独立运行。

## 检查范围

相关单元检查覆盖整组预留的原子性、身份恢复、死亡与离岗不补人、原商店岗位消费、八城床位和工作点、个人回执及 codec。编译和 jar 打包使用 Colab。本次按用户要求不启动 Minecraft，也不做行走、外观、交易手感和多人实机验收，这些项目保持 `not_verified`。

同期散修、同行出城、借物、欠账与关系变化属于后续范围。
