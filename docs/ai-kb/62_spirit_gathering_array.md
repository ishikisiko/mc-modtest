# 三档聚灵阵

原 `spirit_gathering_core/node` 保持 ID 和 7×7 地基、中央 3×3 生效区。0.74.0 新增
`medium_grade_gathering_core/node`（9×9／5×5）和 `high_grade_gathering_core/node`（11×11／7×7）。
阵心嵌地，四座同品级阵枢位于距中心 3／4／5 格的东南西北地面上。所有地基须有坚实顶面，
生效区上方两格无碰撞、无流体；节点不能混用或被另一座同品级阵心共享。未加载区块一律拒绝读取和成型，不强制加载。

## 玩家操作

1. 原组件保留原配方。中品用对应的旧组件、中品灵石及石英／铜升级；上品用对应中品组件、上品灵石及金／黑曜石类材料升级。精确配方归 `tools/gathering/visual.json`，取得前一级组件后解锁配方。创造栏提供六个组件。
2. 右键阵心，将兼容品级灵石放入唯一燃料槽，点击“启阵”。灵石袋需先取出物品，阵心不自动抽取玩家余额，也不开放漏斗。
3. 在中央生效区按原 V／B 修炼，X 收功。菜单蓝图随尺寸缩放；显示当前余能品级与加成、下一枚品级与加成、余能次数和近期受益人数。
4. 停阵、结构缺件、卸载或重启均保留余能与品级。拆阵心只掉落尚未转化的物品，已转化余能散失。公共阵法允许附近玩家补料、取出燃料、启停与共同受益。

## 收益与事务

`src/main/resources/data/myvillage/gathering/rules.json` 唯一维护各档尺寸、各燃料加成、每石阵能和表现时序。
原阵只接受下品（25%）；中品阵接受下品／中品（30%／40%）；上品阵接受下品／中品／上品（35%／50%／60%）。
燃料分类读取 `SpiritStoneDenominations` 的分级标签；一个物品若同时属于多个品级，拒绝当燃料，不猜测价值。

每枚下品／中品／上品分别转成 20／200／2,000 次有效加成，每人每批扣一次；正常 20 TPS 时对应单人持续受益约 10 秒／100 秒／1,000 秒。它们的燃料续航与货币兑换倍率独立。
额外修为按原实际收益乘对应加成向下取整，并截断到境界上限；原批次已填满或额外收益不足一点，不扣阵能。只影响修为，固本、研读、丹药与突破语义保持。

`GatheringEnergy` 是不可变的“次数＋来源品级”，新燃料只在原次数用完后首次需要时转化。换槽不重估旧余能；暂时取出所有未用燃料，已有余能仍可使用。存档 Version 2 增加 `FuelGrade`，旧 Version 1 的 `Charges` 幂等解释为下品余能，原物品和启停状态保留。无效品级或超出同步技术边界的次数不生效，但不删除槽内物品。

`MeditationManager` 先生成原 `BasicBreathingSettlement.Plan`，然后 `GatheringRuntime`
在玩家脚下按最大生效半径有界搜索；候选分别使用自己的生效区和当前燃料加成，按距离、坐标稳定排序，同一结算最多一份加成和一次扣费。
`GatheringMath` 负责可独立验证的截断、取整及阵能算术。阵心 `Lease` 临时保留燃料和余能，
再由 `CultivationService` 提交完整玩家档案；finally 根据实际安装的档案决定确认或回滚。
安装成功后通知异常不能退款；失败恢复原物品组件、余能和来源品级。余能与物品仍属于阵心的同一份保存数据。
不声称玩家文件与区块文件在异常断电时具有跨文件原子性。

阵枢不允许两座已放置阵心共享，即使另一座尚未完整；所有结构和竞争归属检查都拒绝未加载区块，
不触发强制加载。普通外观检查有界定时执行，每次付费前再次完整检查。阵法重叠可存在，但玩家只受其中一座影响。
最近受益人数和运转标志为短暂表现状态，重启清零；原灵石、余能、启停标志持久保存。

## 资源和验证

- 模型、贴图、碰撞近似、配方、发现进度、中文名称及运行时配色归 `tools/gen_gathering_assets.py`，输入为 `tools/gathering/visual.json`；检查 `--check`。
- 中品青玉莲座与双环四瓣，上品紫金框架悬心与三环八卦；共用阵心 BlockEntity 类型，实例档位由所属方块决定，不相信存档自报档位。
- 世界阵纹由客户端 `GatheringRenderer` 绘制，读取服务器成型／运转标志，不用实体充当光点。
- 菜单使用原版容器同步和按钮意图，无自定义客户端收益、距离或成本请求。
- `/myvillage gathering inspect <x> <y> <z>` 是管理员只读诊断，不是玩家启动入口。
- Modal `gathering-build`：资源检查、聚灵阵与修炼结算 Java 测试、完整依赖 jar。
- Modal `gathering-runtime`：上述检查再执行独立 `structure,mapped,economy,overlap,two_players,restart,visual` 场景。
  `gathering-play` 用于采集器局部重试，可用 `--cases` 选择范围，必须记录复用证据和固定源。

初版重型工作按用户要求在 Colab 执行同一组命令；上述 preset 名称仍是现有云端命令集入口。
三档定向采集器为 `tools/gathering_tiers_evidence.py`，支持 `--cases structure,matrix,switch,legacy_restart,two_players,visual`；
`--finalize-preview --out <既有采集目录>` 仅在三档运转画面齐备时复用该世界，启动服务器补齐物资并导出，不冒充新的映射输入。
固定源、失败和实际运行范围见 [0.74.0 验证记录](../testing/2026-10-22-gathering-tiers.md)；
[初版验证记录](../testing/2026-10-21-gathering-array.md) 保留原始范围。玩家审美、长期平衡、原生硬件 FPS 和广泛多人体验仍需玩家验收。
