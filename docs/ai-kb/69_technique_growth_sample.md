# 功法成长样例（0.95.0）

本次只开放基础吐纳诀、青木长春功、乙木生华诀、剑气诀四门真实功法的完整成长。其他功法沿用原有行为，不把目录内全部功法称为已接入。规则、修习门槛、消耗、收益和秘籍材料唯一来源为 `tools/technique_growth/sample.json`，由 `tools/gen_technique_growth.py` 生成运行时配置与三份合成配方。

## 玩家入口

H → 功法 → 选择上述功法 → 修习与参悟。保留原来的设为主修、技能分配入口。详情显示五阶段、修习进度、可用心得、实际收益、潜力边界与传承条件。

0.95.1 起默认进入四门功法各自的活卷内景：卷底显示阶段和累计修习，右侧参悟签与闭关按钮提交原有意图；悬停读收益／消耗／心得，“功法详解”展开完整潜力与传承说明。流动与落印只响应同步状态，不自动开始修习或代选参悟；资源体积与界面实现见 [KB37](37_cultivation_panel.md)。

0.95.1 的 Colab 基础检查与体积审计见[活卷测试记录](../testing/2026-10-27-technique-scroll-ui.md)。0.95.0 固定按钮坐标的原生采集器尚未适配活卷，不能拿旧结果当本次游戏内验收。

- 闭关修习沿用现有准备、坐姿、受伤／移动／攻击中断与寿命规则。每完成一个配置批次，才通过同一事务扣除下品灵石并增长修习；灵石袋沿用现有来源。中断保留完成的批次，不发未完成批次的收益；圆满后自动停止扣费。闭关不同时增加境界修为或固本收益。
- 普通打坐的原熟练度时钟在样例心法上归属当前主修，达到该功法上限后停止增长；不会一边运转青木长春功一边继续刷基础吐纳。未接入样例的心法保留原有行为。
- 剑气诀成功直接命中后增加修习，每次施放只记一次；空放、受阻、被拒绝的命中及多目标／多 tick 重复接触不额外计数。成长的伤害与耗灵系数在起手时冻结，仍使用原有公共执行器与减免流程。
- 每到新阶段获得该功法自己的心得，小成开放首次参悟。两个方向互斥；首次消耗心得，之后改选消耗灵石，不再用无限刷熟练度换心得。心得随该门功法保存，不作为跨功法全局货币。

心法的调息增加修为获取，守息增加灵力恢复；仅当前主修生效。剑气的凝锋提高伤害并增加耗灵，敛气降低耗灵。界面从同源规则生成效果数值，不额外制造一套说明常量。

## 潜力与旧法用途

基础吐纳与剑气诀圆满即达到本次配置上限，没有重复灌经验升品阶的入口。青木长春功圆满并完成参悟后，才能研读乙木生华诀；已有境界、木亲和、秘籍和研读稳定度门槛仍执行。首次学成乙木时承接配置的初始修习与兼容参悟，青木原档案保留，不自动切换主修。旧档已经学会乙木的玩家不撤销学习、不追缴前置，也不凭空补发承接成果。

旧功法圆满后，对明确配置的相关目标提供研读加速与首次参悟优惠。多个来源只取研读加成最高的一门，平局按稳定 ID；不累加、不跨无关类别、不绕过目标条件、不在已学后持续提高该技能修习速度。基础吐纳对更高篇章的帮助低于对初篇的帮助。同一传承的承接只在普通秘籍真正学成的事务中执行一次；管理员 `learn` 是夹具入口，不冒充玩家完整学习或发放承接奖励。

青木和乙木沿用青帝木脉的真实 ID。原有甲乙长生经等后续目录仍保留，但未接入本次成长。新秘籍可按配方书在工作台合成，取得的是零研读进度的原有通用秘籍物品，不新增物品注册或替换旧 ID。

## 数据与权威

`TechniqueProgress` 在原 `mastery_points` 之外增加可选的 `insight`、`insight_spent`、`growth_revision`；缺失字段分别为空／零，旧熟练度超过当前上限也原值保留，效果封顶。未知历史参悟名称保留但不产生效果。完整 profile 仍由 `CultivationService` 唯一替换，沿用 attachment copyOnDeath，不增加 Clone 复制。

协议 47 增加有界成长意图与独立的修习会话状态；客户端只提交功法 ID、动作及参悟版本，服务器重新校验已学、定义、修习条件、当前会话、成本和版本。参悟版本防止过期重复选择再次扣费。修习、秘籍研读、修炼和突破共用唯一会话；服务提交失败才回滚扣料，已提交后的通知异常不退款重放。
