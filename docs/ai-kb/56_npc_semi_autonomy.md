# NPC 半自主生活（0.60.0 首期）

> 0.64.0 更新：[完整云山 V4 与商业服务](58_yunshan_living_city.md)。本页保留所述历史版本的范围；新世界默认 V4，当前命簿 payload 6、协议 33。


0.63.0 的战斗挂起、损耗、真实死亡与危险身体恢复见 [KB57](57_npc_sword_combat.md)。正常生活的安全脚底格不能覆盖尚未结束的坠落或燃烧状态。

0.64.1：已启用商业的三类店主采用跟随世界昼夜的持续日班，详见 KB58；活动收益与冷却仍用修炼日历有效 tick。生活化身使用碰撞检查更严格的地面导航，检查跨楼层移动时的完整身体空间，并保留转角节点；动态入口路径需要重新可达，原地部分路径不视为有效路线。该检查不强载区块、不传送身体，也不绕过真实到岗回调。

寻路搜索范围从 `life_rules.json` 的 `max_path_distance` 开始，只缩小到完整已加载的缓存范围；不能再按“目标直线距离 + 原跟随范围”缩短，因为隔墙或上下楼的实际绕行路径可能远长于直线距离。节点预算随该有界范围缩放。实际客户端曾在厨房后墙外无法走到相隔数格的厨房，扩大范围后沿外墙绕到前门、再进厨房成功。

当前可达且仍在前进的路径不随重试周期丢弃节点进度；遇到结束、停滞、区块范围或方块变化才重算。下落时保留当前落点直到身体完成下降，避免进入同一水平格就跳到后续节点。开发者可只读调用实体 `lifeNavigationSnapshot()` 观察有界的路径节点片段、租约、进度与碰撞状态。

首期可玩的目标是“云山街区：散修的一天”：将现有命簿中的少量人物绑定到真实建筑的住处与岗位，使用同一份持久活动记录驱动近处行走和远处简化结算。它为后续跨城迁移、真实物品经济、职业与社会关系扩展提供入口。

实现和实际验证范围请一起阅读：[验证与接手步骤](../testing/2026-10-17-npc-life.md)。后续 Modal 已完成原始提交的完整 NeoForge 编译和 98 项 Java 测试；0.60.0-fix1 的实际采药交货配药、映射交谈、双客户端、撤回/重启、设施损坏、化身上限和宗门回归已由全场景批次加局部重启复验覆盖。详见该记录的提交、失败及复验范围，不能由编译或纯逻辑测试代替。自然规划城接入与玩家体验仍未验收。

## 1. 身份与世界权威

| 信息 | 唯一权威 | 本期行为 |
|---|---|---|
| NPC 出生、境界、所属宗门、寿元与死亡 | 原 `WorldState.persons/tombstones` | 沿用现有整数人物 ID，生活登记不创建新人物 |
| 玩家身份 | `WorldState.social.players` | 登录按 UUID 登记，改名更新显示名；从未入宗的玩家同样登记 |
| 玩家宗门、贡献、功法借阅与任务 | 原 `playerMembers` | 仍由原宗门服务写入，首次登录不创建会员记录 |
| NPC 对玩家的熟悉关系 | `social.acquaintances` | 真正近距交谈后写入；每人物、玩家、模拟日只记一次，详细记忆有界 |
| 城镇与场所 | `life.sites` | 持久 ID、维度、地区、建筑原点、脚底位置、设施引用和容量 |
| 人物的当前生活 | `life.residents` | 角色、住处、岗位、活动、目标、阶段、进度、资产和疲劳 |
| 现场身体 | `WorldSimAvatars.AVATARS` | 同一映射管理宗门、野外与生活化身；生活化身同样不写实体存档 |

`ActorRef` 为 NPC 与玩家提供统一引用；NPC 的生死和宗门归属直接查询原命簿，避免把它们复制到另一张人物表。玩家离线以后保留社会身份。本期交往写入入口是生活化身的近距交谈，旧宗门功能保持原有入口。

普通村民和普通刷怪蛋 NPC 尚未迁入这套命簿。生活登记针对现有有名有姓的命簿修士，既支持散修，也支持仍有宗门身份的住镇人物。

## 2. 活动与真实执行

纯内核位于 `sim/life/`，修改只能经 `WorldSim` facade。`LifeEngine` 从人物伤势、疲劳、盘缠、携带药材、岗位、性格与共享修炼日历选择短计划。

| 活动 | 主要前提 | 完成效果 |
|---|---|---|
| `rest` 歇息 | 夜间、疲劳、伤势或空闲；有可用住处 | 降低疲劳，尽可能支付住处费用 |
| `work` 当值 | 客栈岗位，或有药材库存的药师岗位 | 有限工资；药师将命簿药材转成药品，客栈记录服务 |
| `gather` 采药 | 明确登记的采集点、需要生计、当日额度未用完 | 从有上限的城镇额度取得命簿药材 |
| `deliver` 交货 | 携带药材、有市场和足够公库余额 | 药材转入城镇库存，公库支付盘缠 |
| `cultivate` 吐纳 | 有可用修炼点且能支付本次费用 | 记录实际修炼时长，供原日结修炼引擎使用 |
| `social` 小聚 | 可用的社交场所 | 在场所停留；本期尚不生成 NPC 间长篇对话或新的关系事件 |

每个计划经历 `moving → working → waiting`，然后根据最新条件重新选择。选择有稳定优先顺序，不会每帧随机改目标；场所容量防止所有人占同一个岗位。失败后有冷却，寻路超时、停滞、设施消失都有原因记录。

近处的 `NpcLifeGoal` 只负责移动、开关木门、到达检查与报告失败。工作进度和收益由命簿统一推进。到站必须有匹配人物、执行租约、活动版本的回调，并真正进入目标脚底格；计时到期不会替近处 NPC 宣布到达。

交谈由服务器检查玩家、距离、维度、实体和租约。右键显示当前活动及其原因，短暂停住 NPC；重复交谈请求有冷却，同一天的熟悉度不能反复增加。已有宗门身份的长老和宗主仍可使用原宗门交互。

休息、当值、采药目前表现为走到对应站位并停留，使用原有模型和动作；没有新睡姿、采药手部动画，也没有逐格经营装修行为。

## 3. 远近切换与存档

每次生活调度的顺序为：检查已加载场所 → 观察附近玩家并协调化身 → 推进活动 → 原命簿日结。只有这一个入口决定调度频率，避免服务器运行时间与存档世界时间取模不同步。

`observed` 与 `embodied` 是两个临时状态。附近玩家可观察到人物位置，但化身因全局上限、碰撞或不安全站位未生成时，该人物会等待，不能进入远处模式偷偷完成工作。玩家离开以后，只从新的有效时间继续推进，不补发这段等待期间的收益。

远处模式保留同一个人物、活动版本和进度，按距离估算移动时间，随后结算活动；位置只在确定的站位更新。只使用曾经实际观测可用的场所。区块卸载表示本次没有新观察，不会把已有建筑记为消失；确认被堵或设施被拆会阻止结算。现场曾经失败的路线需要实际到达才能解除对应冷模拟限制。

NPC 不申请区块票。现场寻路仅在已经加载且能进行实体处理的缓存范围内执行，远目标使用有界局部寻路；无法安全建立路径时等待或失败。不会为了让整片大陆的人物行走而加载世界。局部直达路径不可达时尝试已有建筑入口作为中途点；中途点不触发到站或收益。生活居民避开装饰活板门窗格，炼丹炉不作为可穿入的寻路格。

每次投影取得全局递增的持久 `epoch`，每个新活动取得人物的 `revision`。旧实体的到站、位置或释放回调无法控制新执行者，解除登记后重新登记同一人物也不能重用旧租约。提现类结算带完成版本，同一时刻重放不产生第二次收益。

化身撤离及服务器停止前记录位置并释放租约。整格检查点必须是身体实际经过、中心位置无方块碰撞且有安全落脚面的位置；悬空或台阶边缘撤回时保留最近安全点。移动阶段按此位置重算行程估时，已经进入工作阶段的进度原样保留。工作进度跨撤离和重启保存，短暂交谈状态不跨重启保存；设施失效或路线失败会取消当前未完成工作。加载后重新观察附近玩家并投影身体。

命簿 payload 升至 **v4**：新增 `social` 和 `life`，继续接受 v1–v3。旧宗门会员中有效的玩家 UUID 会补为社会身份；旧的非 UUID 历史键保持原状。旧存档默认没有生活分配，不会自动改写旧人物的职业或制造城镇居民。坏数据和更新版本的存档拒绝加载，沿用原运行时保留旧磁盘存档的行为。

## 4. 与原宏观模拟的边界

登记生活的修士由生活系统持续管理，不以是否出现在玩家身边决定豁免。原后台旅行、凶兽、机会陷阱、争夺、复仇、决斗、宗门战代表、自动立派和迁移候选会排除这些人；其他修士也不能通过后台目标选择向住镇人物发起不可见战斗。

寿元与原有伤势恢复继续生效，实际修炼累积的时间折算为原 `Cultivation.daily` 的日份额，达到条件后仍可产生突破结果。身份层面的继位、宗门解散和吞并可以继续，但不把店主瞬移回山门。守山执事的派驻候选排除住镇人物。

本期化身仍沿用原命簿投影的无敌语义。真实死亡、玩家伤害、战斗损耗与命簿伤势之间的权威桥接属于后续阶段，不能用这版演示对战。

## 5. 云山场所与管理命令

场所源适配位于 `blueprints/npc_life/`，由 `tools/gen_npc_life_places.py` 读取现有 authored 建筑源生成 `data/myvillage/npc_life/places.json`。Gradle `generateNpcLifePlaces` 在 `processResources` 前运行；生成器只输出生活元数据，不修改既有冻结 worldplan 模板和哈希。

两套布局为 `yunshan_planned_v1` 和 `yunshan_showcase_v2`。规划大陆中的云山可自动登记场所，也可用 `/myvillage life yunshan` 登记；只登记空间，人物需明确分配。展示街区使用 `/myvillage life bind <site> yunshan_showcase_v2 <origin>`，原点必须与真实建筑一致，命令不会生成建筑。

管理员命令均在 `/myvillage life` 下，权限等级 2：

| 命令 | 用途 |
|---|---|
| `yunshan` | 登记当前规划世界的云山城 |
| `bind <site> <layout> <x> <y> <z>` | 将已有布局登记到指定原点 |
| `place <site> <place> <kind> <x> <y> <z>` | 增加一个已加载、可用的场所；包含显式 `gather` 采集点 |
| `demo <site>` | 分配客栈当值者、药师、散修和访客四个示例岗位 |
| `assign <person> <site> <role> <home> <work>` | 手工分配同地区、非旅行和非闭关的存活人物 |
| `unassign <person>` | 解除生活登记，保留原命簿人物；随后可以重新分配 |
| `status` / `status <person>` / `status site <site>` | 检查场所、岗位、进度、租约、观察状态与物资 |

`demo` 从当地原有、未分配的散修中选人；缺人、住处被占或设施失效会明确说明，不能保证任意种子在任何地区都有四位符合条件的人。重复执行同一示例不增加重复居民。采集点需要先显式登记，测试者自行确认从住处到点位确实可走。

同 ID 场所重复登记幂等；不同几何的重绑拒绝。一个人的生活岗位只在同地区登记，成员归属与住处独立。命令不跨地区搬人、不生成新人物或替玩家填补被拆建筑。

## 6. 配置与扩展顺序

调度间隔、观察半径、场所与人口上限、寻路预算、活动时长、休息时段、疲劳、盘缠、工资、采集额度及交谈记忆均以 `world_sim/life_rules.json` 为唯一调参来源。加载时校验字段名、类型、范围和相关余额约束。生活时间来自共享修炼日历的有效服务器 tick，`/time set` 和睡觉改变天色不会直接推进这份日历。

药材、药品与盘缠是本期的有界命簿账户，未接玩家 `ItemStack`，不收割真实灵植方块，不宣称覆盖炼丹产量、店铺交易或完整供需。后续建议按以下依赖扩展：先让真机场景稳定，再接真实交易与补货，随后增加 NPC 间关系和地方委托，再做跨城迁移与任务承诺，最后接战斗和重大死亡结果。
