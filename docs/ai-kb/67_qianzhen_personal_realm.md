# 第一章个人秘境

## 玩家入口与隔离

`/qianzhen enter` 首次创建、之后继续；`/qianzhen leave` 返回进入前的安全位置。命令不要求管理员权限。登录提示提供同一入口。序章叙事不在本次实现范围。

每个 UUID 使用独立 `myvillage:qianzhen/<uuid>` ServerLevel，区块保存在该维度目录。主世界 `data/myvillage_qianzhen_realms.dat` 保存归属、命簿地区、返回点和续玩位置。进入前持久化返回点；不占用玩家原有床/重生锚记录。秘境配置必须同时保持 `bed_works=true` 和 `natural=false`：前者防止原版床爆炸，后者在睡眠事件前阻止原版改写重生点；点击床给出返回提示，不进入睡眠。秘境死亡优先在本秘境入口重生，入口阻挡时回到外部安全点。

全服模板维度不能进入；私人维度必须归当前玩家所有且已创建完成。服务器传送入口、观战镜头、维度旅行和登录恢复在发送目标世界前核对归属，剧情交互另外核对当前归属。非玩家实体不能通过维度旅行携带 NPC、宠物或载具跨越边界。

## 场景与人物所有权

沿用 `tools/qianzhen/story_assets.py` 生成的六处原模板、道路和交互锚点。首次创建分批进行：先持久化 PLACING，逐栋放置，再分批道路；保存区块和 COMPLETE 后初始化人物并开放进入。中断或失败不会自动重放/覆盖；已进入过的秘境若场景记录缺失，同样拒绝重新生成。保留现场，恢复匹配备份。

`SceneDeploymentData` 在私人维度使用该维度的数据目录，原显式场景保留旧全局文件。古阵状态因此按秘境隔离。四名人物仍经 WorldSim facade 创建和迁移，剧情和场所键为 `qianzhen_ch1_<uuid>`；不建立第二份持久 NPC 实体。不同秘境角色名字相同，命簿 ID 不同。普通天下页的搜索、人物详情、附近人物和关联事件按查询玩家过滤他人的秘境角色，直接猜人物 ID 也不返回详情；管理员命令仍可排查完整命簿。地区图只解释主世界坐标，秘境坐标不会被当成主世界地区或计入宗门巡察。

个人章节与领奖回执仍由 `StoryRuntime`/Attachment 持久化，接受时绑定私人维度。退出与重进不重置，正常重启不补领奖。旧显式场景已接取进度不自动迁移，避免覆盖原有记录或重复奖励。

配置只在 `data/myvillage/story/qianzhen_realm.json`、维度模板和维度类型 JSON 中维护。动态维度在服务器启动时从归属目录恢复，再加载玩家；空闲秘境不保留强制加载票据。

## 主世界与检查

V7 新修仙大陆不含第一章主世界聚落；V1–V6 保留，V6 字节基线来自已交付 0.89.0 jar。既有建筑不回删。普通世界与修仙大陆均可进入个人秘境。

必要检查包括：归属与存档损坏拒绝、两套命簿人物及救援独立、古阵记录独立、旧生成规则保持；远程实际双客户端检查入口、互访拒绝、剧情操作、退出续玩、死亡和保存重启。实际运行结果另记，代码存在不等于通过。玩家手感、FPS 和长期负载保持未验收。
