# NPC 持剑战斗与命簿伤亡（0.63.0）

首批接入中立修仙者的基础剑连招、自卫、负伤撤退，以及宗门、野外散修、城镇居民三类命簿化身的损耗与死亡。实际检查、失败修复和玩家尚未验收的项目见 [验证记录](../testing/2026-10-18-npc-sword-combat.md)。

## 战斗执行

玩家输入包和 `NpcCombatGoal` 都进入 `CombatSessionManager.acceptBasic`，共享 `CombatSession` 和 `advanceAction`。招式、活动帧、缓存窗口、连段、最大目标数、命中几何、伤害倍率、反应与脚步来自原有战斗定义，不复制 NPC 专用剑招数值。

`CombatActors` 提供真实玩家或 Mob 伤害来源，以及共同伤害许可。原版队伍、玩家 PvP 和命簿同宗保护在服务端生效；AI 的选敌不能越过这些许可。`CombatDamageService` 共用主体，玩家事件、饥饿、统计和进攻天命保留玩家分支；NPC 的实际装备也会消耗耐久。基础剑招本身不扣灵力，NPC 档案的灵力字段为后续技能接入保留。

NPC 的步进逐段检查支撑，用原版碰撞处理执行有界移动，遇到缺口即停止，动作期间清除残留寻路输入。命中原点跟随实际身体；不使用玩家客户端位移的计划终点作为 NPC 命中位置。AI 的起手距离也调用同一套样本几何，避免站在台阶下对够不到的目标持续挥空。

`CombatReactionService` 分开暴露击停和硬直：纯击停通过 `CombatSession.pauseOneTick` 暂停动作相位；硬直清除动作与缓存并保留必要恢复时间。卸载区块、被冻结的实体不推进 NPC 动作。玩家现有受击控制方式保持原有规则，NPC 没有新增技能闪避。

## AI 与配置

`data/myvillage/npc_combat/rules.json` 是 NPC 基础属性、初始武器、感知节奏、反应时间、追击边界、撤退条件、脱战恢复和归因时限的唯一配置。首批只因实际受袭进入自卫，失去合法目标、超出追击边界或成功逃离后脱战；没有全图扫描、主动围攻或无延迟闪避。

普通召唤与刷怪蛋 NPC 沿用原版实体存档。`NpcCombatInitialized` 只初始化装备一次，涵盖带 NBT 的 `/summon` 和旧 NPC 载入；武器损坏后的空手不会因重载而重新得到一把剑。命簿化身从人物战斗档案恢复装备，仍不保存为区块实体。

## 命簿与近场交接

纯数据位于 `sim/combat/`，实际修改只通过 `WorldSim` facade 与 `NpcCombatLedger`。`NpcCombatRuntime` 保存有界的已加载身体索引，`WorldSimAvatars` 仍是三类化身的共同创建入口。

- 每次投射取得递增执行权 epoch；只有当前人物和当前 epoch 可以提交状态与死亡。身份复制出的实体在加入世界时被拒绝。
- 战斗档案持久保存当前生命／上限、灵力、完整主手物品数据、恢复截止时间、更新版本、施害来源与时间，以及维度、地区、位置、速度、落地状态、下落距离和燃烧时间。
- 受伤、治疗和攻击后的装备损耗会及时回写，正常 tick 与撤回补齐身体状态。保存时不依赖仍留在临时实体里的血量。
- 化身撤回、区块卸载和服务器关闭只提交损耗并释放执行权。真实 `die` 才提交死亡；删除化身不等于击杀人物。
- 安全的生活移动仍由居民位置管理；尚未落地或仍在燃烧的身体保留物理状态，重新投射不能把它移回安全脚底格来免除后果。此类冷状态不会继续生活收益。

`People.lifeResident` 的既有外部执行边界同时涵盖当前近场执行权和未解决的物理危险，供旅行、相遇、复仇、战争候选与继位争斗使用。寿元仍由命簿推进，交战中的修炼进度停止；近场伤势由实际身体回写。

存档 payload 升级为版本 5。版本 1–4 没有战斗档案的既有人物在首次投射时初始化；版本 5 缺少战斗组件属于损坏数据，拒绝静默重建。执行权不从存档恢复，epoch 计数保留。零生命档案不被解释为“尚未初始化”。

## 生活与社会后果

战斗开始和结束时先按共享修炼日历结算生活时钟，再切换挂起状态，避免短于生活结算间隔的交战获得额外工资。交战期间工作、采集和修炼进度停止；脱战后丢弃尚未结算的当前活动进度并重新寻路，已有钱、药材和已完成收益保留。伤者优先回住处休息，必须实际到达目标才继续活动。交战中保存并重启也不能恢复成原岗位的无条件工作。

NPC 击杀沿用 `Combat.afterKill` 的师徒、好友、宗门关系和击杀计数，再进入 `Deaths.bury`。玩家以 UUID 对应的 `ActorRef` 记录，死亡回执保留显示名；受害者的师徒／亲友和宗门保存对该玩家的仇怨。没有入宗记录的玩家也不会因此绕过宗门入门与敌意检查。主动跨地区追杀玩家的 AI 属于后续战术阶段。

环境原因保留真实死因；在配置归因时限内的间接死亡可追溯最近的玩家或 NPC 施害者。强制 `/kill` 不冒用最近攻击者。人物详情与命令显示真实杀者名称，玩家杀者不被伪装成整数 NPC 链接。死亡只记一次，清理活人、生活记录与战斗档案，后续地区访问不会再次投射死者。

## 动作和同步

`tools/npcgen/combat.py` 读取已有玩家剑招姿态输入，为三套 NPC 骨架去除各自绑定姿势、解算肘部与脚底位置，并生成战斗片段。握点来自各自手部方块中心；模型、动画输出仍由 `npcgen` 生成。NPC 的衣服、面部、贴图与原步态保持原有作者归属。

`NpcWeaponLayer` 使用生成握点与武器 geometry，撤销物品 baked display 变换后正确持握。非战斗时背负，交战时持剑。攻击独占骨骼；持剑移动保留步态，普通待机不覆盖攻击。

`DATA_COMBAT` 原子快照包含动作、开始时间、同步时间、相位、朝向、revision 和击停。初始实体配对自然携带该快照，新观察者无需碰巧收到最初的 START 包。`NpcCombatPresentation` 使用统一 `ClientCombatClock`，客户端状态按实体对象隔离，旧身体不能污染新身体。网络兼容版本为 32。

## 检查入口与边界

轻量检查：三套 `python3 -m tools.npcgen build <look> --check`、`tools/validate_custom_entities.py`、NPC 生成和战斗适配的 focused tests。

重型检查：Modal `--preset npc-combat-build` 或 `--preset npc-combat-runtime --cases ...`。完整 NPC runtime 集合先运行相关 Java 检查与 jar；局部场景只构建对应固定提交并运行所选场景。场景结果分别记录，不用局部通过代替完整验收。

枪、拳、剑气、主动武技、技能身法、NPC 进攻天命、群体支援和主动阵营战争不在本批。NPC 掉落与真实物品经济没有扩展。玩家外观、手感、音效、平衡和 FPS 验收仍为 `not_verified`，云端软件渲染与命令准备不替代这些结论。
