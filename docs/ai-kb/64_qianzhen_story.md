## 数据与写入所有权

- `blueprints/qianzhen/` 原六份蓝图与 `manifest.json` 拥有建筑和相对位置；
  `story_scene.json` 拥有道路、剧情站位和可点击调查目标。
- `tools/qianzhen/story_assets.py --opening` 生成新版私人场景的 `build/generated/qianzhen/resources`；不带 `--opening` 的调用保留原 authored 来源供冻结 V6 使用；
  由 `generateQianzhenStoryAssets` 纳入 jar。不要手改结构 NBT 或派生位置表。
- `data/myvillage/story/qianzhen_actors.json` 定义人物身份与角色。
- `data/myvillage/story/qianzhen_chapter_1.json` 编排章节、对话、线索和奖励。
  第一版在服务器启动时加载并校验，不承诺在线热重载。
- 个人任务使用独立 Attachment，死亡复制由 `copyOnDeath` 负责。任务服务
  是写入口；客户端只接收快照、提交当前对话的有界选项。
- 人物由 WorldSim 保存，WorldSimAvatars 管理唯一、非持久身体。角色不是
  另存一份的实体，也不因重进或靠近而再次生成身份。

人物采用明确的剧情保护规则，避免后台突破、寿元或普通伤害使章节永久
中断；这只适用于已绑定的剧情角色。周禾是炼气初入的年轻采药人，没有
为本章新增命簿凡人境界或专属实体类型。

## 修改剧情内容

章节 JSON 中 `stages` 定义当前目标、对白与后续阶段，`actions` 定义
角色交谈、精确地点调查和交付动作。`requires` 引用已取得的证据 ID，
`next` 指向稳定阶段 ID；对白和追踪变体按顺序匹配已有证据、共享返回与
古阵处置事实。条件是有界事实表，不执行任意命令或脚本。

改文字时保留稳定 ID。改变流程并增加 `version` 后，新玩家会在正式接受
时绑定新版本；已接取的旧版本进度不会自动清空或重绑，须另做明确迁移。
重复 ID、悬空引用、非法条件、不可达结局和自动循环会拒绝加载整份定义。

## 共享事实与个人任务

救援后周禾使用同一命簿身份回到药庐；这是剧情安排送回，不是实机步行
护送机制。古阵限额恢复同样是场景共享事实。后来接任务的玩家可在当前
位置访问人物、核实已发生的结果，再推进自己的任务和领取自己的报酬。
另一玩家完成操作不会直接写入本人的完成或奖励记录。

调查必须真正右键定义中的方块，服务器核对场景、维度、距离、视线、
方块状态与当前步骤。对话会话绑定当前身体、人物租约和个人进度版本；
过期或重放选择不能推进。奖励先检查背包容量，正常保存后的重复交付不
再次发放；满包时保持待领奖。

## 进入与界面

管理员在新建平坦世界显式部署阡镇：

```mcfunction
/myvillage qianzhen deploy <x> <y> <z>
```

部署会检查场景范围，重复部署不能覆盖既有场景。它不注册自然生成、不
改变出生规则、不改写冻结 worldplan。普通玩家用 `/qianzhen where` 查询
位置，然后主动找程砚交谈；仅看见 NPC 不会自动接下委托。

任务追踪右上文字沿用已确认样式；0.91.0 另增加一个当前目标的透遮挡标记、屏外方向和距离。默认 `O` 打开
行迹，`Y` 切换追踪显示；可以在原版按键设置中重新绑定。`P` 保留原版社交菜单。
详细内容仅展示已经获得的线索，不提前列出未揭示的剧情。

## 检查入口

```bash
.venv-modal/bin/python -m tools.modal_runner run --preset qianzhen-story-build --ref <固定提交> --timeout 2400
.venv-modal/bin/python -m tools.modal_runner run --preset qianzhen-story-runtime --ref <固定提交> --timeout 7200
```

`qianzhen-story-resume` 仅用于本次固定验收前缀：验证 HTTPS 包哈希、生产输入、
完整已执行动作前缀与保存状态后，从同一位置接续。其旧运行仍标记失败，
已经通过的场景有独立来源；默认键 P→Y 是显式兼容项，剧情和场景漂移会拒绝复用。
一般新内容仍从 `qianzhen-story-runtime` 的新世界开始。

build 包含场景生成及一致性、相关 Python 检查、剧情与命簿生命周期的
聚焦 Java 检查和 jar。runtime 追加真实客户端采集；玩家推进使用映射
键鼠输入，RCON 只用于准备场景与读取权威结果。

调查点除距离与连通性外，还检查从站位眼高到点击中心的中间格是否为空气。
这是保守遮挡检查，不模拟目标自身的原版碰撞形状；水釜、讲台等仍须实际
右键验证。剧情接近点可以覆盖建筑原有观景站位，不因此改动原建筑几何。

采集器、preset 或代码存在不等于验收完成。实际结果须核对当次固定源、
`selected/completed/unrun`、失败日志和云端终止记录。开发者证据不能代替
玩家的外观、手感、音效、FPS、长期平衡和广泛多人验收。

本次固定源、原生场景结果与失败修复记录见
[阡镇第一章验收](../testing/2026-10-23-qianzhen-story.md)。
