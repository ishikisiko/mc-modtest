# 0.99.4 药铺器谱

药铺原丹药商人新增四本玄铁甲器谱，沿用有界买入和共享库存，不参与丹药生产。`WorldSim.fromBytes` 在校验存档后通过 `CommerceEngine.reconcileOffers` 补入配置中尚无库存键的商品；每个有新增商品的商店只增加一次 revision。保留所有已存数量（包括零）、交易次数、资金和人员，重复加载不补货；超出存档容量或 revision 上限时拒绝加载。售价、初始库存和容量仅由 `commerce_rules.json` 持有。

# 云山活城与完整主城 V4（0.64.0）

0.93.0 起，药铺伙计 `herbalist` 不再配药或补货；新增药童、灵植师、炼丹师与分类原料生产，见 [KB68](68_npc_herbal_professions.md)。本页以下配药和工作补货描述保留为历史记录。

0.65.0 在客栈增加既有命簿人物担任的城镇向导，白天接待、夜间回客房，按每位玩家实际修炼与原版进度给下一步及 tips。命簿保存格式现为 7；下文的 v6 是商业系统初版记录。操作和兼容见 [KB60](60_vanilla_exploration.md)。

本版把已确认 D1 整城接入新修仙大陆，并让现有命簿居民向玩家交易和提供收费恢复。它不是新的独立人物表，也不是后台自动经营整个世界。

## 进入与操作

在新建世界时选择现有“修仙大陆（种子蓝图）”世界类型。0.64.0 默认生成器为 `myvillage:planned_v4`（0.88.0 起新世界使用 V5 聚落规划，保留同一完整云山城，见 [KB65](65_bay_terraces.md)），新世界包含完整 D1 云山城；普通原版世界不自动转换。专用服务器首次建世界的 `level-type=myvillage\:cultivation` 配置保持不变。

```mcfunction
/myvillage worldplan info
/myvillage worldplan city
/myvillage life yunshan
/myvillage life status site yunshan
/myvillage life commerce yunshan
```

城市位置由种子决定，按 `worldplan city` 的输出前往，不沿用旧 V3 的传送坐标，也没有新增虚构的 `/locate` 结构 ID。城市的任意已加载区块首次被观察后，会幂等登记 V4 场所；实际可用的住处和岗位被观察后，从本地现有、空闲散修中安排客栈当值者、药师和铁匠。没有合适人物或设施尚未加载时，职位可以空缺，不凭空造人；最后一条命令可查看并重试尚未成功安排的岗位，不刷新已初始化仓库。

店主必须真实到达岗位并处于工作阶段，玩家近距右键才打开店铺。0.64.2 起所有命簿商人共用买入／卖出标签，数量框两侧提供减／加按钮，每页三行，显示实际物品总数、总价、可交易份数和余额。数量是报价份数，切换标签重置为 1；输入限正整数，上限沿用配置 stock_limit，空白或 0 不会提交。客栈疗养在买入页按单次服务办理，数量控件禁用；没有商品的标签显示空态。药铺收六味现有药材，出售现有三种普通下品丹药；铁匠铺买卖有限的铁锭和铜锭；客栈当值者提供收费恢复。价格、容量、恢复比例、冷却与交互距离只在 `data/myvillage/world_sim/commerce_rules.json` 维护。潜行右键保留原生活交谈或宗门入口。下班、战斗、店主离开岗位、设施失效或视线/距离不符时拒绝服务。

0.64.1 的已启用商店采用持续日班：按世界实际日光时刻及 `life_rules.json` 的休息时段判定营业，白天以当值优先，不因单次工作结束、疲劳或原短社交计划离岗；夜间回自己的住处。正在战斗的身体仍由战斗执行器接管。切换时段必须重新走到目标，单次工资/配药周期完成后则留在同一已验证岗位继续工作。`/time set` 或睡觉只改变营业意图，不推进生活工资、配药进度或付费恢复冷却。未启用商业的生活居民沿用原活动选择。

日班与寻路修复的证据及限制见 [0.64.1 定向验证](../testing/2026-10-18-yunshan-day-duty-navigation.md)。 批量交易检查见 [0.64.2 定向验证](../testing/2026-10-18-commerce-bulk.md)。

收购只接受与普通默认物品组件完全相同的物品，不会将命名、附魔、品质或其他特殊组件的货品降格回收。库存有限，卖出/买入会同时影响共享城镇公库；钱不够、背包放不下、店铺无钱收购或库存满时，整次交易拒绝。

客栈服务是**一次有上限的生命/灵力恢复**，不是租赁房间、设置出生点或跳过黑夜。需要本店可用且未被居民占用的真实床位，玩家近期未受攻击、未燃烧，而且确实有可恢复资源。每位玩家的冷却使用持久的共同生活时钟，跨菜单、商店和正常重启不能反复付一次钱领多次恢复；休息不替玩家执行原版睡眠。

旧世界不自动开启经济。管理员对已绑定、实际存在的建筑可执行 `/myvillage life commerce <site>` 明确启用；旧生活布局若没有铁匠住处/岗位，不会自行补建筑。完整 D1 预览若按本版局部坐标放置，可用 `life bind <site> yunshan_planned_v4 <x> <y> <z>` 登记实际最小角后启用服务。绑定只登记位置，不放建筑；不同整体旋转/平移必须有对应场所适配，不能把自然预览的坐标未经换算照搬。

## 世界生成与兼容

`blueprints/worldplan/rules_v4.json` 和 `tools/worldplan/district.py` 复用原 D1 实现器、70 所民居和四栋功能建筑输入。原 210×82×265 内容不拉伸、不重排，外侧仅补齐区块对齐边界，形成 224×82×272、238 个 16×82×16 的区块列模板。门、屋顶、空气、道路和七处题字来自同一完整蓝图；每个新区块只放自己的模板，不跨界写邻居或强制加载整城。

城市二维地面由 D1 原始逐列地形生成，保留原来的台地、湖床与院落高差；外围通过 V4 的有界过渡接入规划地形，不把整城压成一块平板。它不是把独立普通世界的实测选址结果复制到所有种子中，外观仍需实机验收。

V4 的冻结规则包含城市模板哈希、逐列地表与布局身份。保存时使用有界 GZIP/Base64 的 ASCII 字符串，防止完整城市使 NBT 单字符串超限；解压大小也受限制。旧 `planned_v1/v2/v3` 和对应 biome codecs、冻结 JSON、35 个旧城市模板均保留，旧存档继续按旧规则生成新区块。V3 基线另外钉住源资源哈希。不要用 `/reload`、删除区块或手改 `level.dat` 将旧世界转换成 V4。

城市既有世界生成保护和已生成 FULL 区块不重建规则继续生效，玩家改建不被运行时还原。场所元数据从相同 D1 坐标和旋转推导，17 个目标格与最终 V4 模板共享布局哈希；四栋独立建筑原来的展示坐标不是城市摆放坐标。

## 商业权威与补货

纯逻辑位于 `sim/commerce/`，修改仅经 `WorldSim` facade。商品数量存在命簿商业组件，钱仍使用已有 `life.supplies` 的城镇公库；人仍是原命簿人物，现场身体仍由 `WorldSimAvatars` 管理。初始化只给一次有限起始货物，不再另建现金账户。店主死亡或解除岗位不会自动补人和刷新货物；`staffed_roles` 保留已经完成的安排。

药材收购进入原生活药材库存。原 `gather/deliver` 也可以给该库存供料，但本版不把装饰药圃直接当作可采集点、不新增真实灵植自动收割。药师完成实际 `work` 后，沿用有料才配药的规则，再把有限命簿药品转换成店铺丹药库存。没有药材时仍可站岗接客，但不会扣出负药材或凭空补货。玩家炼丹炉的配方、品质与输入不被改写，NPC 的抽象配药不冒称实体炉自动炼丹。铁匠首版是有限金属货栈，未新增后台采矿或自动炼器生产线。

商业菜单不持有临时货物槽。服务端先完整复制并规划玩家主背包/快捷栏的扣款与产出，再以人物执行租约、共享库存 revision 和玩家身份提交账本，最后同线程替换已准备的背包。请求仅携带本菜单 ID、随机会话 token、单次序号、商品索引和有界请求份数，客户端不能提交价格或生成物品。买卖按完整份数同时校验库存／收购容量、公库和背包后，只递增一次交易计数；任一条件失败都不退化为部分成交。旧窗口请求、重复序号、另一位玩家以及争购最后一件货的旧 revision 不能重复结算。

命簿 payload 升至 **6**，网络版本为 **34**。v1–v5 正常迁移到空商业组件；v6 缺少组件、损坏字段或未来版本拒绝静默重置。库存、公库、交易计数与恢复冷却经正常保存/重启保留，菜单与 token 不持久化。这里不承诺玩家文件与命簿文件之间的异常断电跨文件事务原子性。

本次针对用户允许减少测试的要求，优先实现并运行相关纯核/资源检查。实际运行记录见 [本次检查记录](../testing/2026-10-18-yunshan-living-v4.md)。已有云山独立世界或 NPC 生活的历史实机证据，不能代替本次 V4 与商业菜单的实机验证。

python3 tools/worldplan/generate_assets.py
