## Working Conventions

- Start from `docs/ai-kb/INDEX.md`; it maps narrative docs in `docs/ai-kb/` and normative specs in `openspec/specs/`.
- Keep `docs/ai-kb/` concise and factual. New docs must be listed in `docs/ai-kb/INDEX.md` and cross-link same-topic specs.
- Keep examples small; prefer deterministic converters and validators in `tools/`.
- `src/main/resources/data/myvillage/` is the current implemented namespace. Treat `minecraft_town_mod` as a historical placeholder unless a dedicated rename updates code, resources, specs, and docs together.
- Implementation is not complete until generated resources, a practical jar build, and user-facing `README.md` command/usage docs are current.
- `reports/` is ignored deterministic output except `reports/town_distinctness_calibration.json` and `reports/cultivation_style_baseline_hashes.txt`; do not delete those two, and do not `git add` generated reports.
- Add settlement families through `tools/buildgen/groups.py`; do not infer families from `style_id` prefixes.
- Resolve modset legality through `tools/buildgen/modset.py` and `exmod/mod_block_catalog.json`; do not hardcode mod ids/namespaces in validators.
- Add roof/motif forms through registries in `tools/buildgen/ops.py` plus style allow-lists; do not dispatch by string-prefix matching.
- Add/recalibrate regions through JSON under `src/main/resources/data/myvillage/worldgen/` plus `tools/buildgen/region_topology.py`; runtime region binding is passive, and `next_rung_regions` stays a set at tier ties.
- For visual/aesthetic structure changes, inspect current preview/reference evidence and give a critical design judgment before editing generators.
- Version/changelog mechanics are single-sourced in `openspec/config.yaml` (`rules.tasks`); reference that rule rather than restating it. `python3 tools/bump_version.py <version> [--dry-run]` applies it, and `python3 tools/release_gate.py` runs the release checks with a freshly written jar (README "Versioning And Changelog").
- GenOps orchestration lives in `genops/` and `tools/genops/`; user-facing use is natural-language Commander conversation, while CLI commands are backend tools the agent runs itself.
- For CRAFT-required work, keep the owner interface decision-only: confirm need, scope/depth, direction, and verdicts; the Commander owns change names, run ids, pipelines, task ids, worker routing, checks, and archive unless audit detail or a backend failure is requested.
- Before manual visual review, run the acceptance checklist, build the artifact when practical, update command docs, generate the visual acceptance report, inspect representative PNGs, and serve `out/preview/` with `python3 -m http.server 8765 --bind 0.0.0.0 --directory out/preview` until review ends. While this host keeps its current public IP, report the aggregate route as `http://43.156.135.198:8765/index.html`; for a focused preview, report its direct path below that same public base URL rather than a localhost or tunnel URL.
- Chunky automation is a staged handoff, not visual acceptance. Headless Chunky renderer PNGs cannot prove custom `myvillage:` block appearance until a dedicated compatibility path exists.
- When commands or acceptance prep steps change, update `README.md`, this `AGENTS.md`, and relevant `openspec/specs/` documents together.
- Flying-sword changes must keep the custom payload input-only and run `tools/validate_rideable_flying_sword.py`, tests, build, and the acceptance server; riding and appearance still require in-game review.
- Qingfeng sword-combat changes must use the exact untracked root `PlayerAnimationLibNeoforge-1.1.4+mc.1.21.1.jar`, keep both combat C2S payloads empty and all timing/hit/damage/step authority on the server, keep PAL imports client-only, and run `tools/validate_sword_combat_foundation.py`, its tests, mod-item and existing gameplay validators, Gradle tests/build, jar inspection, the acceptance server, and a final physical-client smoke. Use `-Pcombat_smoke_server`, `-Pcombat_smoke_game_dir`, and `-Pcombat_smoke_username` for isolated final/two-client runs; `/myvillage_pal_smoke move <n>`, `first_person <n> <tick>`, and `third_person <n> <tick>` are only client visual-pose probes and never substitute for mapped-click or server evidence. Move sets and weapons are data under `src/main/resources/data/myvillage/combat/` (`style/`, `weapon/`, `index.json`); add or retune moves there, never in Java constants, and never name a specific item in `combat/**` or `client/combat/**` (resolve through `CombatStyles`). Register every item that has a weapon entry as `CombatWeaponItem` (vanilla re-equip rule minus the durability replay; a plain `SwordItem` replays the equip animation after every durability-costing hit); `tools/validate_mod_items.py` enforces it. Explicit hit samples (and a move's optional presentation-only `trail.samples`, which the world trail follows instead of the hit samples and the server never reads) go in non-decreasing tick order with the same count on every active tick once any tick has several, and the far ends of whichever samples a cut's trail draws must reach each weapon's world-trail tip radius. The accepted Qingfeng values are pinned in `tools/tests/test_combat_style_baseline.py` and `BasicSwordStyleTest`; a deliberate retune updates both. Collect presentation evidence with `python3 -m tools.combat_capture` (see `tools/combat_capture/README.md`); it holds the shared heavy-work lock, and on this 4-core/7 GB host only one Gradle or Minecraft job may run at a time. Offline previews are `python3 -m tools.combat_preview fp|pose|model` (numpy/Pillow via `.venv-preview/`, see its README); a change to the first-person solver, a rig, or a geometry contract must rewrite `src/test/resources/first_person_preview_parity.json` (`-PupdatePreviewParity`) and keep `tools/combat_preview/fp_rig.py` passing `tools/tests/test_combat_preview_parity.py`. First-person swings are data in `assets/myvillage/combat/qingfeng_first_person.json`; keep each `strike` window covering the server active ticks. Chain/cancel windows (`buffer_start_tick`/`chain_tick` in the style file) are allowed but server-decided. A step is a server-decided impulse (`setDeltaMovement` + `hurtMarked`) that client physics executes, and hits use the server-planned origin. Keep trails, sounds, hit-stop, camera shake/FOV (scaled by the accessibility options), impact freeze/jitter, and the `FirstPersonArmRenderer` arm (never cancels `RenderHandEvent`) presentation-only. Regenerate `sword_combat.json` and `spear_combat.json` with `tools/gen_sword_pal_anims.py` and never hand-edit them; it holds one pose table per style (`POSE_TABLES`), each with its own weapon contract, 3D model, rules, cut paths, and output file, and a two-handed table puts the left hand on the shaft with `ON_SHAFT`. The 3D Qingfeng model, its texture, the `separate_transforms` wrapper, and `combat/qingfeng_sword_geometry.json` come only from `tools/gen_qingfeng_sword_model.py`; never hand-edit them. Likewise the Lingxiao spear's model files, icon, and `combat/lingxiao_spear_geometry.json` come only from `tools/gen_lingxiao_spear_model.py`. The first-person grip aligns from the contract and the undone baked display transform; never hard-code weapon geometry or grip offsets in Java. Geometry contracts are format 2 with weapon-neutral names (`butt`, `handle`, `collar`, `head`, `head_base`, `head_tip`, `axes.length`; loaded by `WeaponGeometry`) and the rig scale is `rig.weapon_scale`; the format 1 sword names are rejected, never read as fallbacks. A second hand needs the contract's `off_hand_grip_center` and the rig's `rig.off_hand` block (optional own `thickness`, `upper_arm`, `forearm`, and released `rest_direction`/`rest_reach`, all built by `Rig.offArm()`/`OffHand`) with per-key `off_hand_slide`/`off_hand_roll`/`off_hand_elbow`/`off_hand_hold` (drawn only with an empty off-hand slot); the trails span the contract's optional `trail`. Capture defaults to `fp,tp_back,tp_front` for weapons under 1.8 blocks and `fp,tp_back_right,tp_front_left` (cropped quarter views) for longer ones; quarter-view motion comes from client-only `motion`, never from a combo; `combo --layout sweep|line` and `--tick-rate` give multi-target and slowed server evidence with per-move hit attribution. Gate A/B/C and every real-client/two-player item stay separate; never infer the owner's texture, animation, or gameplay verdict.
